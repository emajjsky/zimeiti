# 富内容理解与成稿标题建议设计

## 1. 目标

本次改造统一项目中的“解读型任务”调用方式，让阿里云百炼 CLI 的多模态能力真正参与正文、图片、视频和音频的联合理解；同时把当前位置和语义不正确的“选题建议”改造成文案助手中的“标题建议”，并完整移除没有实际产品价值的内容预检链路。

改造后的用户链路为：

1. 用户通过链接、粘贴文字、上传文档、图片、视频或音频提供内容。
2. 系统将正文和媒体组织为一个富内容包，通过同一次多模态模型调用完成联合理解。
3. 用户基于理解结果生成或继续编辑正文。
4. 正文形成后，用户可以在文案助手内生成 3—5 个标题候选。
5. 用户选择一个候选替换当前标题，或关闭候选并保留当前标题。

内容预检报告不再参与草稿完成、版本保存或结果展示。

## 2. 核心原则

### 2.1 一次调用联合理解

文字、图片、视频和音频属于同一份内容，不拆成独立识别任务，也不先生成若干媒体摘要再交给文本模型拼接。统一执行器直接构造一次 `bl omni` 调用：

```text
RichContentPackage
  ├─ title / body / summary / metadata
  ├─ images[]
  ├─ videos[]
  └─ audios[]
        ↓
     bl omni
        ↓
  任务专属结构化 JSON
```

这样可以让模型同时利用正文语义、图片中的文字与视觉关系、视频画面与语音、音频内容完成判断，避免跨调用的信息损失。

### 2.2 统一输入，任务专属输出

所有解读型任务共享同一套富内容输入协议、媒体路径解析、CLI 参数构造、输出提取和错误记录能力。每个任务仅定义自己的提示词和输出 Schema，避免重复实现 CLI 调用和媒体处理。

### 2.3 能力匹配以真实模型能力为准

模型目录返回的旧能力标签只能作为信息来源，不能覆盖本地已确认的模型能力规则。Qwen 3.6、3.7、3.8 系列的文本、图片、视频联合理解能力应合并进最终能力集合。

凡输入可能包含图片、视频或音频的任务，只允许选择满足多模态理解要求的模型。系统不得静默降级到纯文本模型，也不得在媒体被忽略后继续返回看似成功的结果。

### 2.4 标题建议属于成稿优化

标题建议的依据是已经生成并可编辑的当前正文，而不是导入内容阶段的原始材料。它属于文案助手中的成稿优化动作，与“发现选题”或“内容解读”分离。

### 2.5 删除无价值链路

内容预检不是必经步骤，也不再作为草稿完成的附属调用。删除时同时清理任务策略、服务、接口注入、数据库字段、领域类型、界面、样式和测试，不保留失效入口或兼容分支。

## 3. 统一富内容协议

服务端使用统一的内部数据结构：

```ts
interface RichContentPackage {
  text: {
    title: string;
    body: string;
    summary?: string;
    metadata?: Record<string, string | number | boolean | null>;
  };
  media: Array<{
    kind: 'IMAGE' | 'VIDEO' | 'AUDIO';
    source: string;
    label?: string;
    origin?: 'WEB' | 'UPLOAD' | 'ASSET' | 'DRAFT';
  }>;
}
```

`source` 可以是模型可访问的公网 URL，也可以是经过安全解析的本地绝对路径。统一执行器负责：

- 清理空正文和重复媒体；
- 保持媒体顺序与标签；
- 将本地上传路径限制在允许的素材目录内；
- 根据媒体类型生成 `--image`、`--video`、`--audio` 参数；
- 生成单次 `bl omni --text-only --output json` 调用；
- 从 CLI 包装结果中提取文本 JSON；
- 使用任务 Schema 校验结果；
- 在调用日志中记录任务、模型、耗时、输入规模和明确错误。

媒体数量遵循实际任务需要。用户主动选择的创作素材仍保持最多 9 个；网页正文内部媒体由提取与大小限制控制，不混用“最多 9 个创作素材”的交互约束。

## 4. 模型能力分类

### 4.1 根因

当前模型目录条目优先使用远端返回的 `capabilities`，导致本地对 `qwen3.8-max` 等模型的多模态识别结果被旧目录标签覆盖，设置页因而把可理解图片和视频的模型展示成普通文本模型。

### 4.2 规则

最终能力集合按“远端目录能力 + 本地可信识别规则”合并，不做互相覆盖。

对 Qwen 3.6—3.8 系列多模态理解模型，最终至少包含：

```text
TEXT + IMAGE + VIDEO + VISION + MULTIMODAL
```

若具体型号支持音频理解，再增加 `AUDIO`。不能仅因名称属于 Qwen 系列就推断生成类能力；图片生成、视频生成和语音生成仍按独立模型目录与 operation 判断。

前端模型筛选和服务端策略校验必须调用等价的能力规则，避免设置页可选但服务端拒绝，或设置页隐藏但服务端实际支持。

## 5. 解读型任务改造

### 5.1 内容解读

适用于参考链接、粘贴内容、上传文件和“继续已有内容”。输入包括正文及其关联图片、视频、音频，输出：

- 内容摘要；
- 核心观点；
- 结构线索；
- 可复用事实、案例和表达；
- 可复用画面与图像线索。

该链路已经采用单次 Omni 调用，本次将其底层调用抽入统一执行器，并保留现有用户结果结构。

### 5.2 热点分析

热点分析不能只读取 RSS 标题和摘要。任务准备阶段冻结一份来源快照，内容包括完整网页正文、正文图片、网页视频和来源元数据，再通过富内容执行器生成热点判断。

快照在任务创建时确定，执行过程中不重新读取来源，避免同一个任务因网页变化得到不同输入。

### 5.3 声音提炼

声音提炼读取用户授权或提供的参考文章正文及其媒体。模型联合判断：

- 叙述视角与语气；
- 句式、节奏和段落组织；
- 图片、图表、视频在表达中的作用；
- 开头、转折、论证和结尾习惯。

输出仍是可复用的写作规则与声音资产，不把具体原文或媒体内容复制成模板。

### 5.4 配图策划

配图策划输入当前正文、正文已有图片、项目已选素材和参考图。模型基于文字与现有视觉内容共同规划封面和段落插图，避免重复画面、位置错配和提示词脱离正文。

输出继续使用严格 JSON Schema，包含图片角色、插入锚点、画面描述、正向提示词、推荐来源和参考素材关系。提示词以清晰的肯定式画面描述为主。

### 5.5 模板分析

模板分析同时输入 DOM/排版结构信号和页面视觉截图。结构信号用于识别字号、间距、块级关系和样式规则，截图用于理解整体视觉节奏、色彩、装饰和图文关系。

模板分析结果仍需经过现有安全规则和布局 Schema 校验，模型输出不直接成为可执行 HTML。

### 5.6 视频拉片分析

视频拉片是富内容理解的一个专用入口。首版只支持上传本地视频文件，不读取抖音、Bilibili、视频号或其他视频页面链接。链接获取涉及平台访问控制、页面结构变化和内容授权风险，留待后续独立评估，不进入本次实现。

入口位于“新建创作”弹窗的创作方式选择区，放在“继续已有内容”右侧。四个入口依次为：

1. 从零创作；
2. 参考内容创作；
3. 继续已有内容；
4. 视频拉片。

“视频拉片”卡片副标题为“上传视频，拆解内容并提取关键帧”。桌面端四卡等宽并列；窄屏按现有响应式规则换行，不压缩文字和点击区域。

选择“视频拉片”后，弹窗下半部分切换为：

- 项目标题，可选；
- 视频上传区，支持点击上传和拖放；
- 已选视频的封面预览、文件名、时长、分辨率和文件大小；
- 目标平台，沿用现有平台选择；
- 主按钮文案“创建并开始拉片”。

拉片模式不显示题材输入、链接输入、正文输入或多素材选择，避免把不同输入逻辑混在同一表单中。

处理链路分为四层：

```text
上传的视频文件
        ↓
视频校验与素材入库：格式、大小、时长、媒体信息
        ↓
bl omni：联合理解画面、字幕、语音、节奏与事件
        ↓
时间轴分析 + 关键帧截取 + 素材入库
```

#### 5.6.1 拉片输出

模型输出严格 JSON，至少包含：

```ts
interface VideoShotAnalysis {
  summary: string;
  timeline: Array<{
    startSecond: number;
    endSecond: number;
    description: string;
    spokenContent?: string;
    visualElements: string[];
    reusableFor: Array<'COVER' | 'OPENING' | 'BODY' | 'ENDING' | 'REFERENCE'>;
    keyFrameSecond?: number;
  }>;
  narrativeStructure: string[];
  hooks: string[];
  reusableCopyElements: string[];
  visualStyle: string[];
}
```

时间点由模型给出，服务端使用 `ffmpeg` 从已获取的原视频按时间点截取关键帧。关键帧不是模型返回的图片，也不依赖截图接口；截取失败必须标记具体片段失败，不能把空图片写入素材库。

#### 5.6.2 文件边界

首版支持项目现有上传体系可安全保存的常见视频格式，实际格式、大小和时长上限在实现阶段依据服务器上传限制与百炼 Omni 输入限制取两者较小值，并在选择文件后立即校验。

视频上传完成后写入素材库，再创建拉片任务。上传失败、格式不支持、文件损坏或无法读取媒体信息时，不创建分析任务，并向用户展示具体原因。

系统只处理用户主动上传且有权使用的视频。首版没有链接解析器、网页下载器、登录态抓取或平台专用适配器。

#### 5.6.3 关键帧素材

拉片完成后，关键帧以普通素材记录，保留以下元数据：

```ts
interface VideoKeyFrameAssetMetadata {
  sourceVideoId: string;
  timestampSecond: number;
  frameRole: 'COVER' | 'OPENING' | 'BODY' | 'ENDING' | 'REFERENCE';
  description: string;
}
```

用户可以在素材库瀑布墙中预览、批量选择最多 9 张关键帧，直接带入公众号创作、配图策划或正文排版。关键帧与原视频建立关联，删除关键帧不删除原视频。

## 6. 标题建议

### 6.1 任务定义

将原 `TOPIC_RECOMMENDATION` 语义替换为 `TITLE_RECOMMENDATION`。该任务只在已有正文时可用，输入为：

- 当前草稿标题；
- 当前完整正文；
- 当前正文图片和封面图；
- 平台类型；
- 可选的写作声音信息。

输出 3—5 个候选：

```ts
interface TitleRecommendation {
  title: string;
  angle: string;
}
```

`title` 是可直接替换的标题，`angle` 用一句简短说明概括标题抓住的内容重点。不给候选附加评分、风险等级或复杂审核结论。

### 6.2 交互位置

入口位于文案助手的正文编辑区域，与润色、扩写、压缩等成稿动作同层，但作为独立操作：

- 正文为空时按钮禁用，并显示“完成正文后可生成标题建议”；
- 点击后显示明确生成状态；
- 结果以内嵌候选面板展示，不跳转页面；
- 每个候选提供“替换当前标题”；
- 面板提供“放弃”关闭操作；
- 替换只修改当前工作副本标题，沿用现有草稿 revision 与自动保存机制；
- 用户继续修改正文后，已有候选标记为已过期，不自动再次调用模型。

导入内容页不再自动调用标题或选题建议，内容解读完成只负责把可用内容带入创作链路。

## 7. 删除内容预检

完整删除以下内容：

- `CONTENT_PREFLIGHT_REVIEW` 模型任务和设置页策略项；
- 预检提示词、解析 Schema 和执行服务；
- 草稿完成接口中的 `runContentPreflight` 注入与调用；
- `completeDraftWithPreflight` 包装函数；
- `ContentPreflightReport` 类型；
- `ContentDraftVersion.preflight` 字段；
- 结果页预检报告区块及专用样式；
- 预检专项测试和策略测试；
- 数据库 `preflight_json` 字段。

数据库通过新增迁移删除字段并清理历史策略，不改写已经执行过的历史迁移。草稿完成恢复为单一职责：校验 revision、冻结当前草稿版本、生成或保存排版结果并返回版本。

## 8. 数据流与接口

### 8.1 富内容执行器

建议新增聚焦的服务模块：

```text
server/services/rich-content-understanding.cjs
```

公开接口保持小而明确：

```js
normalizeRichContentPackage(input)
buildOmniArgs({ model, prompt, content, maxTokens })
runRichContentTask({ task, workspaceId, modelPolicy, prompt, schema, content })
```

业务服务负责组装自己的内容包和任务提示词，统一执行器不理解“热点”“声音”“标题”等业务概念。

### 8.2 标题建议接口

新增草稿级接口：

```http
POST /api/v1/content-drafts/:draftId/title-recommendations
```

请求：

```json
{ "revision": 12 }
```

服务端读取当前工作副本和关联素材，校验 revision 后执行 `TITLE_RECOMMENDATION`，返回候选及所依据的 revision：

```json
{
  "draftId": "...",
  "revision": 12,
  "recommendations": [
    { "title": "...", "angle": "..." }
  ],
  "policy": {
    "scope": "TITLE_RECOMMENDATION",
    "provider": "BAILIAN_CLI",
    "model": "qwen3.8-max"
  }
}
```

替换标题不新增专用接口，继续调用现有草稿 `PATCH`，从而复用 revision 冲突保护和保存逻辑。

### 8.3 视频拉片接口

新增视频分析资源接口：

```http
POST /api/v1/video-analyses
```

视频先通过现有素材上传接口入库，再传入素材 ID：

```json
{ "assetId": "..." }
```

创建后返回异步分析任务：

```json
{
  "id": "...",
  "status": "ANALYZING",
  "source": { "type": "ASSET", "assetId": "..." }
}
```

状态依次可能为 `ANALYZING`、`EXTRACTING_FRAMES`、`SUCCEEDED` 或 `FAILED`。查询接口返回拉片结果、关键帧素材和来源状态：

```http
GET /api/v1/video-analyses/:analysisId
```

前端展示“视频拉片”页面：顶部显示上传视频和状态，中部按时间轴展示片段，右侧或下方以图片瀑布墙展示已截取关键帧，并提供“加入创作素材”“加入配图策划”和“下载原视频”等动作。

## 9. 错误处理

- 没有正文：前端不发请求，服务端仍返回明确的 400 业务错误。
- revision 已变化：返回 409，前端刷新草稿并清除过期候选。
- 模型不具备多模态能力：策略保存和任务启动均拒绝，并指出需要多模态理解模型。
- 本地媒体路径越界或文件不存在：在调用前失败，不把无效路径传给 CLI。
- CLI 调用失败或输出不是有效 JSON：任务返回真实失败原因并写入调用日志，不生成空候选或虚假成功状态。
- 部分网页媒体无法下载：保留成功获取的正文与媒体，并在来源快照中记录缺失项；只有当任务核心输入完全不可用时才失败。
- 标题建议失败不影响当前草稿内容，也不改变草稿 revision。

## 10. 测试策略

所有行为改动遵循测试先行。

### 10.1 单元与服务测试

- Qwen 3.6、3.7、3.8 模型能力与目录旧标签合并正确；
- 纯文本生成模型不会被误标成多模态理解模型；
- 富内容包正确去重并保留图片、视频、音频；
- `bl omni` 参数包含正确的媒体参数；
- 各解读任务传入正文和媒体，不只传摘要；
- 上传的视频文件进入 Omni 分析并输出时间轴片段；
- 关键帧截取使用真实时间点，截取文件可预览并带有来源元数据；
- 未上传成功或无法读取的视频不会创建分析任务；
- 标题建议解析 3—5 个合法候选，并拒绝空标题和无效 JSON；
- 草稿 revision 冲突时不调用模型；
- 预检任务、服务、字段和策略不再存在。

### 10.2 前端测试

- 正文为空时标题建议不可用；
- 生成过程中显示状态；
- 候选可以替换当前标题；
- 放弃不修改标题；
- 正文变化后候选过期；
- 设置页将 Qwen 3.6—3.8 正确展示为多模态理解模型；
- 设置页没有预检策略项。

### 10.3 集成验证

- 使用本地 CLI dry-run 验证同一次请求包含正文、图片、视频和音频；
- 本地真实联调内容导入、热点分析、声音提炼、配图策划、模板分析和标题建议；
- 验证草稿完成不再触发预检调用；
- 运行全量测试、类型检查、生产构建、服务端语法检查和 `git diff --check`。

真实计费模型调用只在用户明确同意后执行。本地验证通过前不部署服务器。

## 11. 非目标

本次不新增预检报告替代品，不增加标题评分系统，不自动替换用户标题，不新增独立选题工作台，不重做正文生成链路，也不改变图片生成、视频生成和语音生成模型的分类规则。

## 12. 完成标准

满足以下条件才视为完成：

1. 所有指定解读型任务都能把正文和关联媒体放进同一次多模态调用。
