# 内容引擎项目计划

> 状态：Draft v0.1  
> 日期：2026-07-22  
> 计划原则：先完成可 dogfood 的内容闭环，再扩展平台、团队和复杂自动化。

## 1. 计划目标

在 12 周内交付一个 Windows 优先的桌面 MVP，使产品主理人能够用自己的账号完成以下闭环：

`热点收集 → 选题 → 三端内容包 → 本地视频任务 → 发布审核 → 复盘记录`

MVP 的成功标准不是功能数量，而是连续 14 天用它完成真实内容生产并发现可量化的效率提升。

## 2. 实施原则

1. **先 dogfood，后多租户扩展**：自身内容账号是第一批测试用户。
2. **先半自动，后自动**：先让用户最后确认发布，再评估每个平台的官方 API。
3. **先工作流，后模型炫技**：LLM、图片、数字人均通过适配器接入，产品价值在流程和资产沉淀。
4. **先预设自动化，后自由编排**：V0.1 不做 n8n 式流程画布。
5. **先稳定的数据模型，后完善 UI**：热点、选题、项目、版本、发布、指标的关系必须先固定。

## 4. M0：产品冻结（第 1 周）

### 4.1 交付物

- `01_PRD_内容引擎.md`
- `02_PLAN_内容引擎.md`
- `03_IMPLEMENT_内容引擎.md`
- 统一交互原型：`stitch_/stitch_/editorial_workshop/prototype.html`
- 飞书 Base 原型与字段映射说明。

### 4.2 必须决策

| 决策 | 当前结论 |
| --- | --- |
| 首发系统 | Windows 优先，后续支持 macOS |
| 主客户端 | Electron + React + TypeScript |
| 视频策略 | 本地 GPU/外部服务适配器，不训练模型 |
| 首发平台 | 公众号、小红书、视频号 |
| 发稿策略 | 人工确认的辅助发布 |
| 飞书定位 | 可选镜像/协作层，不是数据库 |
| 试用内容题材 | 以 AI 工具科普为 dogfood，底层支持全题材 |

### 4.2.1 M0 必须冻结的实施决策

| 决策 | V0.1 结论 |
| --- | --- |
| 用户模型 | 单 Owner、单工作空间；不做产品内多人协作 |
| 身份 | 邮箱 Magic Link；P1 再评估手机号和飞书登录 |
| ORM | Drizzle ORM，统一 PostgreSQL 与 SQLite Schema 类型 |
| Python 依赖 | `uv` |
| 部署 | Docker Compose（API、Worker、PostgreSQL、Redis、对象存储） |
| 文案模型 | 用户配置 OpenAI 兼容 API；系统只保存适配器配置和使用记录 |
| 视频交付 | P0 以 FFmpeg + Hyperframer 导出为准，不承诺特定数字人供应商 |
| 信息源 | RSS、手工剪藏、经书面确认的公开热点源；禁止未审查的账号/网页抓取 |

### 4.3 退出条件

- 设计稿至少覆盖：今天、发现、规划、创作、发布、复盘。
- 团队可以从 PRD 讲清一条热点如何变成已发布内容。
- 不再新增一级导航或不在闭环内的新模块。

## 5. M1：基础骨架（第 2 周）

### 5.1 功能范围

- Electron 桌面壳与统一应用导航。
- 本地 SQLite 数据库与文件目录配置。
- 云端 API、用户/工作空间身份、PostgreSQL 主库。
- 内容项目、选题、热点的最小 CRUD。
- 云端与桌面端同步客户端；仅同步元数据。
- 首次启动向导：工作空间、题材、平台、飞书、素材目录、本机能力检测。

### 5.2 验收

- 新用户可完成首次启动向导。
- 可新建题材、选题、内容项目。
- 断网时可编辑本地草稿，联网后可同步。

## 6. M2：情报与选题（第 3-4 周）

### 6.1 功能范围

- 题材、关键词、排除词、信息源、刷新频率配置。
- 云端定时采集框架，先接 RSS、经审查的公开热点源和手工剪藏。
- 情报去重、摘要、题材归类、可信度/时效字段。
- 发现页、热点详情、收藏/忽略/转选题。
- 选题池、选题详情、确认立项。
- 飞书 Base 镜像模式：热点摘要与选题单向同步；飞书意见通过显式导入回写。
- 先交付桌面端 RSS 配置、手动刷新和应用运行期间的本地定时采集；云端 Worker 在 OAuth 与跨设备同步阶段接管持续任务。
- 飞书默认采用“模板编辑 → 预览 → OAuth 授权 → 确认创建”的路径；已有 Base 字段映射属于高级导入，不阻塞首版闭环。

### 6.2 验收

- 每日定时任务可稳定写入 20 条以上可读热点。
- 用户能在 3 次点击内由热点创建内容项目。
- 飞书不可用时，桌面端流程不阻断。

## 7. M3：内容生产（第 5-6 周）

### 7.1 功能范围

- 内容项目五步状态：Brief、写作、视觉、视频、审核。
- 平台内容版本模型：公众号、小红书、视频号。
- 文案生成适配器、账号风格模板、事实待确认项。
- 公众号 Markdown/富文本输出与排版预览。
- 小红书封面/分页图文项目，图片提示词和素材替换。
- 素材索引、版权来源、项目关联和本地/云端缩略图。

### 7.2 验收

- 从确认选题到公众号初稿、小红书卡片草稿、视频号口播稿/分镜不超过 30 分钟；最终视频成片不计入该指标。
- 每个平台版本可独立编辑、审核和保存版本。
- 用户能定位任一图片和引用的来源。

## 8. M4：本地视频（第 7-8 周）

### 8.1 功能范围

- 本地 Python Sidecar 进程管理与健康检查。
- 视频项目：场景、口播稿、字幕、配音、素材和时间轴。
- FFmpeg 基础拼接、字幕合成和导出。
- 数字人/配音/视频供应商适配器接口；首批接入由产品主理人选定。
- GPU 检测、任务队列、失败重试、等待本机状态。
- Hyperframer 素材包导出。

### 8.2 验收

- 本地可完成一个 45-90 秒知识视频从脚本到导出的任务。
- 用户离线/关机时任务进入“等待本机”，重启后可继续。
- 无 GPU 或服务异常时提供导出/云端/人工处理降级提示。

## 9. M5：发布与闭环（第 9-10 周）

### 9.1 功能范围

- 发布日历、排期状态、待发布队列。
- 发布审核与规格预检。
- 浏览器插件基础能力：剪藏、打开平台后台、预填标题/正文/标签。
- 本地账号状态检测，不上传 Cookie。
- 发布记录与手工发布确认。
- P0 数据录入和基础复盘记录。

### 9.2 验收

- 用户能从审核页进入对应平台后台并完成最终发布。
- 发布失败有明确记录、原因与重试入口。
- 已发布内容可链接回内容项目及其所有素材。

## 10. M6：Dogfood 与 Beta（第 11-12 周）

### 10.1 Dogfood 要求

- 连续 14 天使用产品完成真实内容生产。
- 至少完成 10 个内容项目、30 个平台版本、5 个视频项目。
- 记录每个步骤耗时、失败率和手工绕行原因。

### 10.2 Beta 要求

- 邀请 5-10 位不同题材的创作者。
- 每位用户完成一次“首次设置 → 热点 → 选题 → 内容包”的流程。
- 收集激活、留存、内容采用率、发布完成率和主观满意度。

### 10.3 V0.2 评审依据

- 哪些平台最常被要求优先接入。
- 哪类视频工作流最常卡住。
- 飞书镜像/协作模式的实际使用比例。
- 自动化、素材库、数据分析中哪些是真实高频需求。

## 11. 工作分解与负责人建议

| 领域 | 主要职责 | 建议角色 |
| --- | --- | --- |
| 产品/内容 | PRD、模板、提示词、dogfood、反馈 | 产品主理人 |
| 桌面端 | Electron、React、SQLite、文件和任务 UI | 桌面前端工程师 |
| 服务端 | API、PostgreSQL、同步、队列、授权 | 后端工程师 |
| 本地计算 | Python Sidecar、FFmpeg、GPU、模型适配 | AI/媒体工程师 |
| 设计 | 设计系统、原型、状态与异常路径 | 产品设计师 |
| 测试 | 多机型、断网、发布预检、回归 | QA 或开发轮值 |

单人起步时可按顺序完成：产品/设计 → 桌面壳 → 情报/选题 → 内容生产 → 视频 → 发布。

## 12. 风险、依赖与缓解

| 风险 | 影响 | 缓解策略 |
| --- | --- | --- |
| 平台 API 不稳定或不开放 | 发稿/数据功能延后 | 采用人工确认的浏览器辅助发布，能力按平台分级 |
| 本地 GPU 差异大 | 视频体验不稳定 | 能力检测、模型按需下载、云端/导出降级 |
| 信息源质量参差 | 热点价值低 | 题材词、来源白名单、去重、可信度和用户反馈 |
| 飞书字段被改动 | 同步失败 | 字段映射、系统 ID、校验与修复向导 |
| 开源协议不兼容 | 法务与商业风险 | 建立第三方组件清单，AGPL 项目只参考或隔离部署 |
| 范围持续膨胀 | MVP 延期 | 任何新功能必须映射到主链路和指标后才进入排期 |

## 15. 当前资讯来源关口（2026-07-23）

1. 已完成 RSS、手动刷新、定时采集和合规链接剪藏。
2. 已完成本机文本模型连接配置，下一步接入模型驱动的摘要、筛选和选题推荐，但任何 AI 结果都必须保留来源并标注待核验事实。
3. 然后实现连接器目录和 Tavily 候选搜索。Tavily 只用于发现公开候选链接，不自动抓取全文。
4. 资讯来源链路验收后，进入飞书模板 OAuth 创建与单向镜像；飞书仍不是产品主数据库。

### 15.1 情报页面重构顺序

1. 将“发现”页的顶层筛选改为来源或来源分组；增加时间、可信度、处理状态筛选。题材仅作为次级的情报库视图。
2. 将现有“归属题材”自由输入升级为来源与题材的多对多关联；在来源编辑页配置题材及包含词、排除词，保留可复用的情报库定义。
3. 接入“模型目录”和“任务策略”后，热点 AI 分析从任务策略解析模型，不写死模型 ID。

### 15.2 模型路由验收顺序

1. 在“模型与 API”验证百炼 CLI 或外部 API，进入“任务策略”同步模型目录。
2. 为“热点分析”选择并保存一个模型；未保存前，发现页 AI 分析必须被阻止并给出配置路径。
3. 用户主动分析一条热点，确认结果显示所选模型，并在“调用记录”看到成功状态、耗时及可用 Token 数据。
4. 再分别为选题、文案、改写、排版、生图、配音和视频配置模型；各功能接入时必须复用同一任务路由器。
5. 外部 API 验收只填写连接信息并完成验证；在任务策略中同步该渠道模型后，确认连接页没有模型选择字段。

## 16. 百炼本地执行器（2026-07-23）

1. 桌面端随包安装 `bailian-cli`，不依赖用户自行全局安装 Node 或 `bl`。
2. 百炼作为默认综合能力执行器：一把 Key + 自动/文字/视觉/音频/视频范围；通用 Agent 在实际执行任务时再选择具体 CLI 命令和模型。
3. 外部 API 作为独立补充连接，先覆盖结构化文本能力；不可被误标为已具备百炼的图片、语音和视频能力。
4. 下一个实现任务是定义 Agent Skill 到百炼 CLI 子命令的受控映射，并为每次生成建立确认、成本提示、任务状态和资产归档。

## 17. 模型目录与能力边界（2026-07-24）

1. 模型目录采用双来源：DashScope `/models` 用于可查询目录；客户端内置已核验的百炼多媒体模型目录。用户配置并验证一个百炼 API Key 即可使用产品能力，模型市场控制台会话不作为用户必经步骤。
2. 市场模型、Token Plan 专属模型和账号未开通模型不写死为默认可用项；新模型由产品维护官方目录后进入客户端，三方模型通过各自 API 连接同步。
3. 目录能力拆分为文本、图像生成、视频生成、语音合成、视觉理解、全模态、语音识别、音乐生成、推理、嵌入和代码；任务策略只能选择与任务输入输出一致的能力。
4. 每次目录同步保存模型 ID、来源、能力、权限状态和同步时间；视频、图像、音频任务在真正执行前由适配器再校验该模型的输入参数，不能只根据模型名称路由。
5. CLI 的 `model list` 命令可能要求控制台会话令牌，但该命令仅用于模型市场元数据查询，不能用于判断用户 API Key 是否可用，也不能阻塞模型调用、任务策略或目录同步。
