# 内容引擎执行计划

> 版本：Web-only v1.0
> 更新：2026-07-27
> 原则：每个阶段必须跑通用户闭环并验收，再扩展能力；不以页面数量作为进度。

## 1. 执行总览

```text
阶段 0：Web 基线
阶段 1：核心 Agent 与情报到选题
阶段 2：选题到图文内容包
阶段 3：发布与复盘
阶段 4：飞书、账号与媒体生产增强
```

阶段 0 的功能基线和阶段 1 的情报、分析到选题主链路已经建立；真实 Tavily、真实内容模型与多用户交叉访问仍有独立验收项。阶段 2 已完成“项目资料与参考 Scope”和“受控研究计划”两个切片，下一步先统一项目 Agent 并跑通公众号、小红书、知乎、微博文案候选；来源证据随后作为研究动作接回，配图、排版和审核执行器不在本切片并行开发。P0 仅支持单 Owner 工作空间，不包含成员邀请、分配、审核或评论。

## 2. 阶段 0：Web 基线

### 目标

建立可安全承载用户数据与外部能力的 Web 运行环境。

### 已完成

- React/Vite Web 前端与 Fastify API。
- 用户注册、登录、JWT 会话和工作空间隔离。
- PostgreSQL 迁移、Redis/BullMQ、Docker 本地编排。
- 服务端加密凭据库，浏览器不保存 Tavily/百炼 Key。
- 服务端 RSS 刷新、公开链接剪藏、Tavily 搜索 API。
- 17 个合规自动 RSS 目录、7 个辅助渠道、批量接入与独立失败状态。
- 13 类确定性分类、真实命中关键词持久化、规范化 URL 去重，以及题材筛选与关键词搜索。
- 百炼 CLI Worker 和异步任务队列骨架。
- Web 注册、首次设置、状态保存与真实 RSS 刷新验收。

### 尚未完成

- 工作空间快照尚未完全拆分为正式领域表。
- Tavily 和公开链接剪藏需要用户真实 Key/链接验收。
- 百炼 Worker 已承载热点分析、大纲、初稿和项目研究计划；项目 Agent 当前只开放研究计划动作，尚未执行来源读取与事实核验。
- 多用户工作空间交叉访问自动化测试尚未完成。

### 验收门槛

- 新用户可注册、进入工作空间、保存刷新后的来源和热点。
- RSS 刷新成功、失败和空结果均可识别。
- 用户 Key 在刷新页面后不回显。

## 3. 阶段 1：核心 Agent 与情报到选题

### 用户闭环

```text
配置题材与来源 → 刷新/检索/剪藏 → 情报收件箱 → 核心 Agent 计划 → AI 分析 → 创建选题 → 选题确认
```

### 工作项

1. 建立 Agent 动作注册表、结构化计划、确认卡和生成运行记录数据模型；创作 Skill 组合在阶段 2 落地。
2. 建立核心 Agent：模型规划、动作白名单校验、结构化计划、取消与确认接口；不允许自由工具调用。
3. 将题材、资讯来源、关键词和刷新策略从工作空间快照拆为领域 API 与表。来源与情报已迁移；独立题材配置仍待完成。
4. 增加定时刷新 Worker、去重、失败重试和来源健康状态。规范化 URL 去重和单次刷新失败隔离已完成；定时调度和重试仍待完成。
5. 完成 Tavily Key 的真实保存、搜索和“加入热点池”验收。
6. 完成公开链接剪藏：可读公开页预读；验证码、登录、付费墙给出明确可行动提示。
7. 接入百炼 CLI 的情报分析、来源核验和选题评分动作，输出摘要、热度、建议角度和待核验事实。
8. 实现选题池、选题评分和从情报创建选题。

### 不做

- 不做飞书自动同步。
- 不做视频、数字人、生图或复杂账号授权。
- 不允许 AI 自动把搜索结果直接变成正式选题。

### 验收门槛

用户使用自己的来源和 Tavily Key，完成一次：RSS/搜索/剪藏中的任一情报 → AI 分析 → 创建并确认一个选题。

## 4. 阶段 2：选题到图文内容包

### 用户闭环

```text
确认选题 → 资料与研究 → 内容母版 → 多平台版本 → 配图 → 排版 → 审核 → 导出内容包
```

### 工作项

1. 建立正式的内容项目、项目资料、参考作用范围、研究运行、证据、内容母版、平台策略、平台版本、会话、Agent 动作、生成运行记录和资产引用数据模型。项目输入与参考资料已完成，后续对象待实施。
2. 实现项目内通用 Agent 与动态 Workflow，不再新增孤立的“改写/解读”页面；完整草稿允许跳过大纲，所有路径仍需经过事实、版权和发布审核。
3. 接入百炼 CLI 文本动作和受限浏览器动作：研究计划、公开网页检索、事实核验、解读、润色、保留观点重构、长文写作、局部改写和平台适配。
4. 建立模型 Scope、模型选择、调用确认、用量日志和失败重试。
5. 建立题材、内容类型、语言风格、排版和渠道五类 Skill 预设，并增加账号规则、栏目模板、平台策略和本次指令的优先级与冲突提示。
6. 支持用户多选目标平台；共享内容母版，公众号、小红书、知乎和微博分别保存目标篇幅、传播目标、钩子、CTA、渠道规则和素材要求。排版与内容包首批只验收公众号和小红书。
7. 支持项目级素材上传、已有素材使用、参考图作用范围、配图计划、图像 API 产物、版权状态和插入位置。基础上传和参考用途已完成，采用关系、生成产物、版权状态与插入位置待实施。
8. 支持正文编辑、自由对话、局部选择修改、候选稿接受、版本差异、人工修改和导出；Agent 结果不得直接覆盖正式资产。
9. 支持公众号和小红书实际图文内容包、渠道审核、事实核验和版权清单；知乎、微博先完成独立文案版本和渠道规则，再按真实交付格式开放后续入口。

### 不做

- 不做自动发布。
- 不把视频作为图文项目必经步骤；视频工坊作为后续独立扩展能力。
- 不让 Agent 在缺少来源或用户确认时编造事实、直接覆盖人工版本。

### 验收门槛

用户从一个真实选题、自己的草稿和至少一条参考资料创建项目，通过同一个项目 Agent 形成可追溯候选并采用至少一个正式文案版本；四个平台文案互相隔离且刷新可恢复。完整纵向验收仍要求公众号或小红书中的至少一个平台完成实际配图、排版、事实/版权审核和内容包导出。

## 5. 阶段 3：发布与复盘

### 用户闭环

```text
内容包 → 发布预检 → 排期 → 用户确认发布 → 填写数据 → 复盘建议
```

### 工作项

1. 账号目标、发布日历、发布任务、状态机和预检规则；P0 账号只记录发布目标，不做 OAuth 授权。
2. 导出公众号 HTML/素材包、小红书图文包、视频号口播/字幕/视频素材包。
3. 手工确认发布和平台内容链接/ID 回填。
4. 手工录入基础指标，形成内容与题材复盘结论。
5. 只支持人工填写平台内容链接/ID 和基础指标；官方 OAuth/API 统一移至阶段 4。

### 验收门槛

用户完成一次真实人工发布，并在同一内容项目中记录发布链接、基础数据和一条复盘结论。

## 6. 阶段 4：增强能力

### 4.1 飞书与协作

- 飞书 OAuth、可编辑模板、创建 Base、字段映射和单向/双向同步策略。
- 飞书只镜像热点、选题、排期和审批信息；主库仍是 PostgreSQL。
- 团队成员、角色、审核与评论。

### 4.2 账号与半自动发布

- 按平台规则接入官方 OAuth/API。
- 浏览器扩展在用户已登录的后台页预填内容。
- 扩展不上传 Cookie，风险提示、验证码和最终发布由用户完成。

### 4.3 媒体生产

- 图像、ASR、语音、视频理解和数字人 API 适配器。
- Remotion/Hyperframer 云端渲染 Worker 与对象存储。
- 长耗时任务队列、取消、重试、成本预算和产物归档。
- 视频工坊读取已完成的文稿与素材，按用户主动选择生成口播、分镜、字幕或成片任务；不改变原图文项目的完成状态。

## 7. 每次迭代的固定流程

1. 明确本次只服务哪一段用户闭环。
2. 先更新 PRD 和实施方案中的对象、边界、接口和验收条件。
3. 实现 API、数据迁移和 Worker，再实现页面。
4. 用真实来源、真实用户账户和人工确认跑通一次。
5. 更新验收记录，区分“已实现”“已真实验收”“待用户验收”。
6. 推送 GitHub 后再进入下一项。

## 8. 部署策略

### 本地开发阶段

在本地完成每个闭环和自动化测试。当前 2 核 2G 阿里云服务器不承担本地开发和视频渲染。

### 个人测试环境

阶段 1 或阶段 2 跑通后部署。2 核 2G 只运行 Web 静态文件、API 和低并发文本任务；PostgreSQL/Redis 最好迁移到托管服务，媒体文件使用 OSS。

### 不允许的部署方式

- 在 2 核 2G 主机上并发跑数据库、Redis、视频渲染和多个 Worker。
- 在生产服务器上使用 Vite 开发服务器。
- 将用户密钥、Cookie 或未加密数据库备份提交到 Git。

## 9. 阶段 2 推荐实施切片：真实公众号纵向闭环

阶段 2 不再直接从“对话式改写”开始，而按以下依赖推进：

1. 项目资料：支持粘贴想法/草稿、关联热点、导入公开链接和上传图片，并为参考内容选择事实、观点、结构、语言、钩子或视觉作用范围。
2. 研究验证：Agent 生成检索问题，用户确认后调用 Tavily/公开网页/受限 Playwright，保存来源快照和证据状态。
3. 内容母版：生成并确认核心观点、事实证据、待核验项、必须保留表达和可用素材清单。
4. 平台策略：先完成公众号；将目标篇幅从 WritingBrief 迁移为平台级参数，增加传播目标、钩子、CTA 和账号/渠道规则快照。
5. 文案协作：支持已有完整草稿跳过大纲、对话式局部修改、候选版本、差异查看和采用。
6. 配图：根据已确认文稿生成配图计划，跑通“已有图片 + 一张参考图生成封面”两种来源。
7. 排版与审核：生成公众号 HTML 和素材包，完成事实、原创、渠道、素材版权五类检查。
8. 公众号真实内容包验收通过后，再复用内容母版派生小红书版本；视频继续作为独立扩展任务。

本切片的首个验收样例固定为：用户提供一份自己的草稿、两条参考链接、一张已有图片和一张视觉参考图，最终导出一套可人工发布的公众号内容包。该样例用于约束后续数据模型和页面，避免继续围绕空白生成场景堆功能。

## 2026-07-27 设计更新：通用 Agent 与文案优先

1. 一个项目只保留一个 Agent 身份和完整时间线；页面默认显示当前阶段消息与前序摘要，可切换完整历史。
2. Agent 统一接管研究、大纲、初稿及后续配图、排版、审核动作。自由对话只负责表达意图，执行必须映射到注册动作并经过确认卡。
3. 内容母版作为底层共享资产，不增加强制页面。单平台可直接生成候选，多平台先整理共享母版，再派生独立平台版本。
4. 首批文案覆盖公众号、小红书、知乎和微博；四个平台分别保存策略和版本，不用公众号直接替代知乎，也不用小红书直接替代微博。
5. 第一实施切片只完成 Agent 基座、四平台文案候选、差异、采用和刷新恢复，不并行开发配图、排版与审核执行器。
