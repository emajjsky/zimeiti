# 内容引擎 PRD

> 版本：Web-first v1.0
> 更新：2026-07-24
> 面向：P0 为个人创作者；P2 扩展至 2-5 人内容团队

## 1. 产品定义

内容引擎是一个以“内容项目”为中心的 Web 编辑部。它帮助创作者把合规收集到的信息，转化为可发布的公众号、小红书和视频号内容包，并通过发布记录和数据复盘改善下一轮选题。

产品不限定题材。AI、财经、历史、人文、国学等题材使用同一套工作流；AI 是生产能力，不是内容垂类。

唯一主线：

```text
情报收件箱 → 选题池 → 内容项目 Agent → 平台内容包 → 人工确认发布 → 数据复盘 → 下一轮选题
```

## 2. 目标与边界

### 2.1 P0 目标

1. 创作者每天在 10 分钟内处理情报并确定优先选题。
2. 一个已确认选题在一个内容项目中产出公众号稿、小红书图文稿和视频号口播稿。
3. 每次 AI 生成均可追溯使用的来源、模型、提示词版本、任务状态和成本。
4. 用户能导出发布内容包并人工发布，明确记录“待发布、已提交、已确认发布”。
5. 用户能回填基础数据，并填写或基于规则生成一条下一轮选题/内容建议；P0 不承诺自动化复盘 Agent。

### 2.2 不做什么

- 不绕过登录、付费墙、验证码、风控或网站访问限制。
- 不保存平台密码或 Cookie，不承诺所有平台全自动发布。
- 不把飞书多维表格当作主数据库。
- 不在 P0 自建图像、语音、数字人或视频基础模型。
- 不在 P0 做复杂多租户计费、广告投放、CRM 或企业审批。

## 3. 用户与场景

| 用户 | 目标 | 高频场景 |
| --- | --- | --- |
| 个人创作者 | 稳定更新、减少选题与制作时间 | 每日看热点、完成一条内容、手工发布、看结果 |
| 内容主理人 | 管理栏目、内容节奏和质量 | P2：审核选题、分配项目、查看发布和复盘 |
| 编辑/运营协作者 | 补充资料、编辑版本、安排发布 | P2：在项目中补证据、改稿、填写发布结果 |

## 4. 核心对象

| 对象 | 定义 | 关键关系 |
| --- | --- | --- |
| 工作空间 | 一个创作者或团队的数据与授权边界 | 包含所有业务对象和凭据 |
| 题材 | 关键词、栏目、来源规则和内容策略的组合 | 关联多个来源与选题 |
| 情报 | RSS、授权数据、搜索或手工剪藏得到的一条记录 | 可进入多个选题 |
| 选题 | 值得投入制作的内容机会 | 被确认后创建一个内容项目 |
| 内容项目 | 一次完整内容生产的工作单元 | 包含对话、证据、版本、素材、任务与发布记录 |
| 平台版本 | 面向单一平台的可发布内容 | 属于内容项目，可有多次发布任务 |
| 素材 | 图片、音频、视频、引用和品牌资产 | 可被多个项目复用 |
| 发布任务 | 某个版本面向某账号的一次发布动作 | 记录预检、用户确认和结果 |
| 复盘记录 | 内容表现、人工观察与可复用结论 | 回流到题材、栏目和选题策略 |

## 5. 用户工作流

### 5.1 情报收件箱

用户先在“情报源”配置题材、关键词、RSS/官方/授权来源和刷新频率；所有模型、百炼和检索凭据统一在“模型与 API”管理。系统按计划收集公开信息；用户也可以剪藏公开网页链接或用 Tavily 查找候选网页。

“情报源”分为两个互斥工作页签：

- 自动来源：默认提供可公开访问的 RSS 目录，按国内综合、科技商业、国际科技分组，用户多选后批量接入；自定义 RSS 作为折叠式补充入口。
- 辅助渠道：微博、今日头条、央视网、X、公众号、财经媒体和官方公告只提供用户主动发起的公开链接剪藏和限定域名搜索，不做未授权定时抓取，不绕过登录、验证码、付费墙或站点风控。

RSS、公开链接剪藏和 Tavily 候选使用同一分类协议。当前统一题材为 AI、科技、财经、体育、娱乐、社会、国际、时政、文化、教育、健康、汽车、其它；系统根据标题和摘要生成题材及真实命中关键词，来源预设题材只在正文无规则命中时兜底。情报按工作空间和规范化原文 URL 去重，删除追踪参数不应产生重复记录。

情报页只解决三件事：按来源和时间查看近 30 天资讯、判断是否值得跟进、转为选题。来源是一级筛选，时间提供 24 小时、7 天和 30 天三个范围，题材是次级筛选。服务端在读取和刷新时清理超过 30 天的情报；不提供无限历史堆积。情报卡片使用三列瀑布布局：顶部来源横条按来源稳定配色，卡尾显示彩色题材和实际命中的来源关键词，不显示“可信/待核验”标签，时间统一显示为“今天/昨天/日期 + 时分”。当关联选题已立项且对应项目仍存在时，右上角显示“已立项”，项目删除后该标签消失。

### 5.2 选题判断

每条选题应显示：来源证据、时效、目标受众、建议角度、事实待核验项、适合的平台和预估制作量。AI 可以提出建议，不能替代事实判断。

### 5.3 内容项目 Agent

确认选题后创建内容项目。项目是用户的主工作区，Agent 是项目内唯一的通用 AI 入口。用户用自然语言提出任务，例如：

> 基于这些来源写一篇公众号解读，同时生成 6 页小红书图文结构和 60 秒口播稿；任何不确定事实列入待核验。

Agent 按当前任务 Scope 调用工具：检索、归纳、改写、排版、生图、音视频理解、生成、渲染或飞书同步。每个会改变资产或消耗费用的任务，都必须在执行前展示确认卡。确认卡固定包含任务目的、引用来源数、模型、提示词版本、预估费用、预期产物、是否写入资产；用户可确认或取消，取消不得进入任务队列。

项目创建前的热点分析属于独立 AI 任务入口，但使用相同的 Scope、确认卡和运行记录协议；它只生成建议，不会自动创建选题或项目。

### 5.4 平台内容包

P0 固定支持：

| 平台 | P0 输出 |
| --- | --- |
| 公众号 | 标题、正文 Markdown、引用/事实清单、HTML 导出、封面建议 |
| 小红书 | 标题、正文、标签、封面文案、6-10 页分页图文脚本和素材清单 |
| 视频号 | 标题、简介、60 秒口播稿、分镜、SRT 字幕稿和视频素材清单，不含成片 |

P0 发布证据统一为：导出包版本号、目标平台、计划时间、用户填写的平台内容链接或内容 ID、确认时间。仅打开平台后台或复制内容不视为发布成功。

### 5.5 发布与复盘

发布中心只记录真实状态：待排期、预检阻断、等待确认、已打开后台、已提交、已确认发布、失败或取消。P0 只支持人工发布和人工指标回填，不接入平台 OAuth/API。

有官方 API 的平台使用授权 API；无官方发布 API 时，产品导出内容包或由浏览器扩展预填，用户必须在平台页面确认发布。复盘 P0 支持人工录入阅读、收藏、点赞、评论、转发、播放和完播等指标。

## 6. 信息架构

```text
今天            今日待办、待确认选题、待发布和异常
发现            情报收件箱与候选搜索结果
规划            选题池、栏目和选题评分
创作            内容项目 Agent、平台版本、素材和任务
发布            日历、预检、账号目标、发布记录
复盘            内容表现、指标和可复用结论
────────────────────────────────
素材库          素材资产与模板
情报源          RSS/官方/授权来源、关键词和刷新规则
网页搜索        Tavily 检索与候选结果
模型与 API      百炼 Key、核心 Agent 规划模型、Tavily 等检索 API、外部 API、任务策略与调用记录
设置            飞书模板、账号、工作空间与安全
```

设置页是低频配置页。用户不应该在日常创作时反复配置 Key、来源或模型。

## 7. AI 与模型策略

- 百炼 CLI 是首选的服务端 AI 执行器；每个工作空间在“模型与 API → 百炼”只配置一次加密保存的百炼 Key，核心 Agent 复用该凭据，只配置规划模型。
- 用户可增加外部 API，但外部 API 只能覆盖其标注的能力范围。
- 每个任务都有 Scope：热点分析、选题推荐、改写/解读、长文写作、平台改写、排版、文生图、图生图/图片编辑、ASR、语音、文生视频、首帧图生视频、首尾帧生视频、参考图/视频生成、视频编辑和渲染。
- Agent 只能在该 Scope 允许的模型中选择；没有有效模型策略时不得发起生成。
- 每次生成创建不可变运行记录：来源快照、模型、提示词版本、输入/输出摘要、估算与实际用量、任务状态和产物引用。
- 视频、数字人、图像、ASR 和语音均通过合规 API 或独立 Worker 实现；Remotion/Hyperframer 是渲染适配器，不是用户主界面。

## 8. 核心 Agent 与 Skill 体系

### 8.1 定位

核心 Agent 是云端内容运营编排器，不是任意模型的聊天壳，也不是自由行动的通用电脑代理。它接收用户在内容项目或情报页的请求，读取工作空间和项目上下文，生成受限计划，选择 Skill，并把结果写入正式资产。

百炼 CLI、模型 API、Tavily、飞书、Remotion 和平台 API 都是 Agent 可调用的工具提供方，不是 Agent 本身。OpenClaw、Hermes、Codex 等通用 Agent 的规划和工具调用思想可以借鉴，但不作为产品的核心依赖。

### 8.2 执行链路

```text
用户请求
→ 核心 Agent 读取项目/题材/来源/平台上下文
→ 生成结构化计划
→ 校验允许的 Skill、Scope 与权限
→ 展示确认卡
→ Worker 执行 Skill 任务
→ 写入情报、选题、内容版本、素材或发布任务
→ 记录运行、模型、来源与用量
```

### 8.3 Skill 契约

每个 Skill 必须版本化，并声明：名称、适用场景、输入/输出结构、执行目标、允许工具、模型 Scope、来源要求、提示词版本、确认策略、质量检查和失败降级策略。

执行目标只允许三种：

- `cloud`：RSS、Tavily、飞书、云端模型和外部媒体 API。
- `worker`：百炼 CLI、长耗时媒体任务和云端渲染。
- `human`：发布确认、付费、删除、风险处置等只能由用户完成的动作。

### 8.4 P0 Skill

| Skill | 输入 | 输出 | 执行目标 |
| --- | --- | --- | --- |
| 情报分析 | 一条情报与来源 | 摘要、热度、待核验事实 | worker |
| 来源核验 | 来源集合与主张 | 证据表、风险项 | worker |
| 选题评分 | 情报、栏目和平台 | 选题角度、评分、受众 | worker |
| 内容写作 | 已确认选题与来源 | 结构化正文草稿 | worker |
| 平台内容包 | 内容项目与目标平台 | 公众号/小红书/视频号版本 | worker |
| 发布预检 | 平台版本与素材 | 阻断项、警告项、导出清单 | cloud |

### 8.5 题材 Skill 包

题材包不是另一套产品，而是对基础 Skill 的规则覆盖。P0 先提供通用包；后续按同一接口增加财经政策、历史人文、国学等包。题材包可覆盖来源优先级、事实规则、禁用表达、写作结构和预检规则，但不能绕过平台合规、确认卡或审计。

## 9. 外部集成与合规

| 集成 | 角色 | 原则 |
| --- | --- | --- |
| RSS/公开网页 | 情报来源 | 只读取公开内容，遵守站点规则 |
| Tavily | 候选搜索 | 用户主动检索才调用，不自动入库 |
| 飞书 Base | 项目协作镜像 | OAuth 授权后按模板创建/同步，不作为主库 |
| 百炼 CLI/API | AI 能力 | 服务端受控执行，浏览器不接触 Key |
| 平台官方 API | 授权、发布、数据 | 仅在平台允许的范围内使用 |
| 浏览器扩展 | 半自动发布辅助 | 不上传 Cookie，验证码与最终发布由用户操作 |

## 10. 阶段范围

### P0：第一条真实内容闭环

单 Owner 工作空间下的资讯来源与刷新、候选搜索/剪藏、选题、内容项目 Agent、三平台内容包、人工发布确认、人工数据回填和规则化复盘结论。

### P1：协作与生产增强（执行计划阶段 4）

飞书 OAuth/模板同步、账号授权、浏览器扩展预填、素材库、图像/ASR/语音、任务用量和成本预算。

### P2：媒体生产与自动化

Remotion/Hyperframer 云端渲染、数字人和视频 API、自动数据同步、团队角色、审核流和更深的复盘模型。

## 11. 成功标准

- 用户可连续 7 天通过同一工作空间完成至少 5 条内容的“情报到发布记录”闭环。
- 情报到创建选题的中位耗时低于 10 分钟。
- 已确认选题到三平台内容包初稿的中位耗时低于 30 分钟。
- 每条生成内容都能看到来源、模型和待核验事项。
- 不出现未授权发布、Cookie 上云或绕过平台验证的实现。
# 2026-07-25 补充：模型与凭据闭环

- “模型与 API”是所有模型、检索和外部连接的唯一凭据入口；浏览器永不读取或回显 Key。
- 百炼和 Tavily均支持保存并检测、重新检测、替换与移除，状态统一为未配置、待验证、可用或异常，并显示最后检测时间和可操作的失败原因。
- 外部 API 连接必须配置、检测、同步目录后才可参与任务策略；删除连接后，同时清除其模型目录与依赖策略。
- 任务策略按功能 Scope 选择已同步的真实模型目录。没有可用模型时不能保存策略，不能以硬编码模型名称兜底。
- 百炼模型目录分为“账户目录”“CLI 媒体能力”和“百炼模型市场”：账户目录来自用户 Key 的 `/models`，CLI 媒体能力来自当前内置 CLI 已实现的命令，模型市场用于补充异步媒体和语音模型。市场目录只表示官方存在，不表示用户账号已开通；真正执行时仍需按账号权限与接口结果校验。
- 任务策略保留左侧功能任务列表，右侧使用“模型来源、执行模型”下拉配置；每个模型必须声明支持的输入输出操作，不能用笼统的图片或视频能力替代具体接口契约。
- 音频任务拆分为“配音与口播”和“语音识别”。TTS 模型只能进入前者，ASR 模型只能进入后者；视频任务继续按文生视频、首帧图生视频、首尾帧生视频、参考生成和视频编辑分别路由。
- “百炼、核心 Agent、检索 API、外部 API、任务策略、调用记录”是六个独立工作页。页头必须显示当前页名称，每页只展示本页配置、状态与操作，不允许重复展示全局连接概览。
- 今日调用、累计调用、成功/失败和 Token 统计只属于“调用记录”；其它页不得显示。页面反馈必须绑定产生反馈的页签，模型同步结果只在“任务策略”中出现。

# 2026-07-25 补充：资讯来源闭环

- 自动来源目录包含 17 个公开 RSS，覆盖国内综合、科技商业、国际科技和国际财经；来源失败必须独立展示，不得阻断其它来源刷新。国际财经自动源为美联储、美国 SEC 和欧洲央行官方 RSS。
- 微博、今日头条、央视网、X、公众号、财经媒体和官方公告属于辅助渠道。财经媒体覆盖腾讯财经、新浪财经、同花顺、东方财富和财联社；官方公告覆盖国内监管机构、交易所、阿里巴巴与腾讯投资者关系页。渠道卡只负责把用户带到剪藏或限定域名搜索，不在情报源页重复放置检索 API 设置。
- 热点页支持来源、时间、题材、语言、搜索和刷新。题材是唯一结构化内容分类筛选；关键词继续显示在卡片上，并由搜索框匹配，不单独提供关键词下拉。
- 新浪财经旧 RSS 虽能返回 HTTP 200，但内容停留在 2018 年，不得作为默认自动源。腾讯财经、同花顺、东方财富和财联社没有经过验证的稳定开放 RSS/API 合同，不得伪装为自动源。
- 默认保留近 30 天情报。读取与刷新时清理过期数据，避免无限堆积。
