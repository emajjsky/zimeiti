# 内容引擎 PRD

## 2026-07-30 研究结果必须建立在原始来源之上

- 从热点或导入资讯创建的项目，研究任务必须优先复用项目已保存的原始资讯快照，再执行补充搜索；原始来源不得依赖第二次联网读取成功，也不得只把标题交给模型。
- 研究结果必须区分“可直接使用”“可参考（单一来源）”“需要补充核验”。没有直接证据或只有不相关来源时，不能为了填满可用信息而提升状态；页面应保留补充研究入口。
- 补充检索最多与原始来源组成有限的自动来源集合；搜索结果必须命中项目主体，不能把同一行业、同一交易所但主体无关的页面送入事实核验。

## 2026-07-30 创作策略初始化与错误反馈

- 写作策略只在用户离开规划、进入实际创作链路后初始化，不能在项目平台版本尚未生成时提前提交空平台。
- 已有写作策略的平台为空时，系统按“已有图文版本 → 规划目标平台 → 当前图文平台 → 公众号”的顺序自动恢复，并同时补齐各平台写作规则；视频号不进入图文写作策略。
- 用户手动保存或自动保存前执行同一套平台规范化，不允许因为空数组静默跳过保存，也不要求用户理解或修复内部数据。
- 参数校验错误不得向页面暴露 Zod 字段名、错误码或 JSON。页面只显示可执行的中文反馈；可自动恢复的问题优先自动修复，不额外增加说明区。

## 2026-07-30 视觉导演：结构、风格、模板与参考图

- 配图阶段先生成结构化视觉方案，再执行搜图或 AI 生图。系统根据正文识别场景图、主体主视觉、概念示意图、思维导图、流程图、时间线、对比图、数据图、信息卡片、清单卡片、引语卡片和新闻资料图。
- 项目默认风格统一当前渠道的图片视觉，单张图可选择跟随项目或独立覆盖。首批预设为清新杂志、波普怀旧、极简知识图、科技媒体和纪实报道；修改项目默认不会覆盖单图独立设置。
- 每个图片位保存原文依据、结构内容、视觉类型、版式模板、风格继承、参考图及参考维度。思维导图保存中心主题与分支，流程图保存步骤，时间线保存年份事件，对比图保存两侧对照项。
- 参考图最多三张，每张可指定只参考色彩与排版、构图、质感、人物/主体或全部视觉特征。参考图不会自动成为最终配图，也不会要求模型照搬其中的文字和标识。
- 没有参考图时执行百炼 CLI 文生图；选择参考图后执行真实图生图。所有搜索和生成仍由用户主动触发，失败保留视觉方案和参考关系，不重置当前图片位。
- 提示词由结构化视觉方案自动编译，仅在“高级设置”中允许调整。用户主要操作是确认视觉结构、模板、风格、参考图和比例，不需要从空白提示词开始。

## 2026-07-30 配图执行修订：主动检索与图文信息图

- 打开配图页、切换配图项或切回搜图页签时只预填推荐关键词，不自动请求图片检索。只有用户点击推荐词或“搜索”后才调用检索 API，避免擅自消耗配额和打乱当前选择。
- AI 生图分为“视觉插图”和“图文信息图”两种模式。普通场景图、新闻资料图和概念画面默认使用视觉插图；数据图、引语卡片、信息卡片及小红书内容页默认使用图文信息图，用户可逐项切换。
- 图文信息图必须由正文自动提取主标题、核心结论和 3 至 5 条信息点，并按渠道生成版式约束。公众号优先横版正文信息图，小红书优先 3:4 竖版高密度知识卡片，知乎和微博使用各自阅读比例。
- 视觉插图继续禁止图内文字；图文信息图允许模型生成简体中文，其负面约束改为错别字、乱码、拼写错误、文字变形、信息拥挤和层级混乱，不得再用“禁止文字”抵消模型能力。
- AI 生图区以当前已绑定图片的大图预览为主。生成成功后立即绑定并显示，刷新后从项目私有素材恢复；提示词和负面提示词放入可展开的高级设置，默认不占据主工作区。
- 模型费用仍只由用户点击“生成这一张”后产生。切换模式只重建当前项的提示词和负面约束并自动保存，不调用模型。

## 2026-07-30 配图工作台修订：从正文自动形成可执行方案

- 配图页不从空白搜索框或空白提示词开始。系统读取当前渠道标题、正文、题材和核心表达，先生成该渠道的配图方案，再让用户逐项完成。
- 封面和正文图片使用不同规划规则。封面表达全文主题；正文图必须表达对应段落的视觉主体、关系或场景。正文图的第一搜索词不得重复封面，也不得让多张正文图默认搜索同一个新闻动作。
- 每个配图项必须包含用途、插入位置、2 至 3 组搜图关键词、完整生图提示词、负面提示词、推荐比例和已绑定素材。用户可以微调，但不需要从零填写。
- 系统按平台、正文长度和段落自动推荐数量；用户可在配图页直接增减并自动保存。公众号为 1 张封面 + 2 至 5 张正文图，知乎为 1 张封面 + 2 至 4 张正文图，小红书为 1 张封面 + 5 至 8 张内容页，微博为 0 至 1 张信息流主图。封面不计入正文数量。
- 增加数量时，系统为尚未覆盖的段落补充配图项；减少数量时，超出项解除位置绑定，但图片继续保留在项目素材库。重新规划和刷新都保持用户当前数量，不静默恢复推荐值。
- 配图项是带版本号的可持久化项目数据。搜图选用、AI 生图和项目素材都绑定到当前配图项，刷新后保留绑定状态。旧版方案升级或用户重新规划时保留封面，正文图片解除绑定但继续留在项目素材库，避免错误图片继续冒充匹配结果。
- “已绑定”只表示某个位置已有图片，不代表系统判断图片与段落匹配。同一张图片不能同时绑定多个配图位置；再次选用时移动绑定关系。
- 搜图优先复用用户已配置的 Tavily 图片检索能力，网页候选图明确提示用户确认版权与授权；未配置或无结果时回退 Wikimedia Commons 开放图库并保留许可、署名和来源页。
- AI 生图继续由用户主动触发，避免自动产生模型费用。系统负责预填提示词和比例；生成结果保存为私有项目素材并绑定当前配图位置。
- 排版按配图方案顺序读取素材。封面进入首图位置，正文图片按文章段落插入，小红书和微博发布稿保留对应页码或位置标记。

## 2026-07-30 创作工作台修订：可回退步骤与双配图路径

- 同一渠道内的“正文、配图、排版、审核”是固定工作页签，不因交付状态推进而消失或禁用。状态只决定默认打开的位置和允许执行的确认操作，不能剥夺用户回到正文、配图或排版修改的入口。
- 配图可在正文完成前提前准备并保存；只有当前渠道已有正文后，才允许确认素材并进入排版。正文修改后允许重新生成排版，不要求用户重新走完整项目流程。
- 配图来源拆分为三条互不混淆的路径：项目素材、公开许可图片搜索、AI 生图。项目素材用于已有文件与已选图片；搜索结果必须展示来源页和许可信息；AI 生图必须保存为项目私有素材，不能伪造图片或把模型设置入口当作生成结果。
- 第一阶段图片搜索使用 Wikimedia Commons 公开接口，结果保留来源、许可和署名元数据。后续可接入用户自行配置的商业图库 API，但不得抓取或展示不明授权的搜索结果。
- AI 生图使用“模型与 API > 文生图”任务策略。当前真实执行器为百炼 CLI 的 `image generate`，支持提示词、负面提示词和比例；生成成功后自动添加至当前项目并选中，调用记录写入 API 使用日志。

> 更新：2026-07-28
> 面向：P0 为个人创作者；P2 扩展至 2-5 人内容团队

## 1. 产品定义

内容引擎是一个以“内容项目”为中心的 Web 编辑部。它帮助创作者把合规收集到的信息，转化为公众号、小红书、知乎、微博文案及后续图文/视频内容包，并通过发布记录和数据复盘改善下一轮选题。

产品不限定题材。AI、财经、历史、人文、国学等题材使用同一套工作流；AI 是生产能力，不是内容垂类。

唯一主线：

```text
情报 / 想法 / 草稿 / 导入内容 → 内容项目（规划 → 研究 → 正文 → 平台版本 → 配图 → 排版 → 审核）→ 人工确认发布 → 数据复盘
```

## 2. 目标与边界

### 2.1 P0 目标

1. 创作者每天在 10 分钟内处理情报，并把值得跟进的热点直接加入创作项目；也可从手工想法、已有草稿或导入内容开始。
2. 一个内容项目以“规划”为第一步，依次完成研究、正文、平台版本、配图、排版和审核，并按用户多选的目标渠道产出独立内容包；视频由用户按需另行创建。
3. 每次 AI 生成均可追溯使用的来源、模型、提示词版本、任务状态和成本。
4. 用户能导出发布内容包并人工发布，明确记录“待发布、已提交、已确认发布”。
5. 用户能回填基础数据，并填写或基于规则生成一条下一轮选题/内容建议；P0 不承诺自动化复盘 Agent。

### 2.2 不做什么

- 不绕过登录、付费墙、验证码、风控或网站访问限制。
- 不保存平台密码或 Cookie，不承诺所有平台全自动发布。
- 不把飞书多维表格当作主数据库。
- 不在 P0 自建图像、语音、数字人或视频基础模型。
- 不在 P0 做复杂多租户计费、广告投放、CRM 或企业审批。

## 3. 用户与场景

| 用户 | 目标 | 高频场景 |
| --- | --- | --- |
| 个人创作者 | 稳定更新、减少选题与制作时间 | 每日看热点、完成一条内容、手工发布、看结果 |
| 内容主理人 | 管理栏目、内容节奏和质量 | P2：审核选题、分配项目、查看发布和复盘 |
| 编辑/运营协作者 | 补充资料、编辑版本、安排发布 | P2：在项目中补证据、改稿、填写发布结果 |

## 4. 核心对象

| 对象 | 定义 | 关键关系 |
| --- | --- | --- |
| 工作空间 | 一个创作者或团队的数据与授权边界 | 包含所有业务对象和凭据 |
| 题材 | 关键词、栏目、来源规则和内容策略的组合 | 关联来源、情报和内容项目 |
| 情报 | RSS、授权数据、搜索或手工剪藏得到的一条记录 | 可直接加入一个内容项目，并保留来源快照 |
| 内容项目 | 一次完整内容生产的唯一工作单元 | 可来源于热点、手工想法、草稿、导入内容或历史迁移；包含规划、对话、证据、版本、素材、任务与发布记录 |
| 项目规划 | 项目进入研究前由用户确认的决策稿 | 包含标题、题材、角度、目标、受众、核心表达、平台、时效、来源要求与限制；目标篇幅不属于规划 |
| 平台版本 | 面向单一平台的可发布内容 | 属于内容项目，可有多次发布任务 |
| 素材 | 图片、音频、视频、引用和品牌资产 | P0 归属于单个项目；P1 才允许跨项目检索和复用 |
| 发布任务 | 某个版本面向某账号的一次发布动作 | 记录预检、用户确认和结果 |
| 复盘记录 | 内容表现、人工观察与可复用结论 | 回流到题材、栏目和选题策略 |

## 5. 用户工作流

### 5.1 情报收件箱

用户先在“情报源”配置题材、关键词、RSS/官方/授权来源和刷新频率；所有模型、百炼和检索凭据统一在“模型与 API”管理。系统按计划收集公开信息；用户也可以剪藏公开网页链接或用 Tavily 查找候选网页。

“情报源”分为两个互斥工作页签：

- 自动来源：默认提供可公开访问的 RSS 目录，按国内综合、科技商业、国际科技分组，用户多选后批量接入；自定义 RSS 作为折叠式补充入口。
- 辅助渠道：微博、今日头条、央视网、X、公众号、财经媒体和官方公告只提供用户主动发起的公开链接剪藏和限定域名搜索，不做未授权定时抓取，不绕过登录、验证码、付费墙或站点风控。

RSS、公开链接剪藏和 Tavily 候选使用同一分类协议。当前统一题材为 AI、科技、财经、体育、娱乐、社会、国际、时政、文化、教育、健康、汽车、其它；系统根据标题和摘要生成题材及真实命中关键词，来源预设题材只在正文无规则命中时兜底。情报按工作空间和规范化原文 URL 去重，删除追踪参数不应产生重复记录。

情报页只解决三件事：按来源和时间查看近 30 天资讯、判断是否值得跟进、加入创作。来源是一级筛选，时间提供 24 小时、7 天和 30 天三个范围，题材是次级筛选。服务端在读取和刷新时清理超过 30 天的情报；不提供无限历史堆积。情报卡片使用三列瀑布布局：顶部来源横条按来源稳定配色，卡尾显示彩色题材和实际命中的来源关键词，不显示“可信/待核验”标签，时间统一显示为“今天/昨天/日期 + 时分”。当对应热点项目仍存在时，右上角显示“已加入”，项目删除后该标签消失；再次打开时进入原项目，不重复创建。

### 5.2 规划与立项

产品不再维护独立选题池。用户从热点、手工想法、已有草稿或导入内容创建项目后，首先进入规划。热点分析可以提供时效、目标受众、建议角度、事实待核验项和平台建议，但只作为规划预填；用户保存并确认规划后，项目才进入研究阶段。规划确认前不得伪造正文或把推荐角度当作正式内容。

### 5.3 内容项目 Agent

内容项目是用户的主工作区，Agent 是项目内唯一的通用 AI 入口。用户确认规划后进入研究，并可用自然语言提出任务，例如：

> 基于这些来源写一篇面向普通读者的公众号解读，使用我保存的清新科普风格；任何不确定事实列入待核验。

Agent 按当前任务 Scope 调用工具：检索、归纳、改写、排版、生图、音视频理解、生成、渲染或飞书同步。每个会改变资产或消耗费用的任务，都必须在执行前展示确认卡。确认卡固定包含任务目的、引用来源数、模型、提示词版本、预估费用、预期产物、是否写入资产；用户可确认或取消，取消不得进入任务队列。

项目创建前的热点分析属于独立 AI 任务入口，但使用相同的 Scope、确认卡和运行记录协议；它只生成建议，不会自动创建内容项目。

### 5.4 平台内容包

P0 固定支持：

| 平台 | P0 输出 |
| --- | --- |
| 公众号 | 标题、摘要、正文 Markdown、引用/事实清单、实际封面与正文配图、HTML 和素材包 |
| 小红书 | 标题、正文、标签、实际封面、6-10 页分页图文、素材清单和发布字段 |
| 视频号（可选扩展） | 用户主动创建视频任务后，产出标题、简介、口播稿、分镜、字幕稿和视频素材清单；不影响图文项目完成状态 |

P0 发布证据统一为：导出包版本号、目标平台、计划时间、用户填写的平台内容链接或内容 ID、确认时间。仅打开平台后台或复制内容不视为发布成功。

### 5.5 发布与复盘

发布中心只记录真实状态：待排期、预检阻断、等待确认、已打开后台、已提交、已确认发布、失败或取消。P0 只支持人工发布和人工指标回填，不接入平台 OAuth/API。

有官方 API 的平台使用授权 API；无官方发布 API 时，产品导出内容包或由浏览器扩展预填，用户必须在平台页面确认发布。复盘 P0 支持人工录入阅读、收藏、点赞、评论、转发、播放和完播等指标。

## 6. 信息架构

```text
今天            按项目阶段生成的真实待办、待发布和异常
发现            热点情报、网络搜索与链接导入
创作            项目中心与规划、研究、正文、平台版本、配图、排版、审核
发布            日历、预检、账号目标、发布记录
复盘            内容表现、指标和可复用结论
────────────────────────────────
素材库          P0 查看项目级素材与品牌模板；P1 扩展跨项目检索和复用
设置            工作空间、资讯来源、模型与 API（含检索 API）、飞书模板、账号与安全
```

设置页是低频配置页。用户不应该在日常创作时反复配置 Key、来源或模型。

## 7. AI 与模型策略

- 百炼 CLI 是首选的服务端 AI 执行器；每个工作空间在“模型与 API → 百炼”只配置一次加密保存的百炼 Key，核心 Agent 复用该凭据，只配置规划模型。
- 用户可增加外部 API，但外部 API 只能覆盖其标注的能力范围。
- 每个任务都有 Scope：热点分析、选题推荐、改写/解读、长文写作、平台改写、排版、文生图、图生图/图片编辑、ASR、语音、文生视频、首帧图生视频、首尾帧生视频、参考图/视频生成、视频编辑和渲染。
- Agent 只能在该 Scope 允许的模型中选择；没有有效模型策略时不得发起生成。
- 每次生成创建不可变运行记录：来源快照、模型、提示词版本、输入/输出摘要、估算与实际用量、任务状态和产物引用。
- 视频、数字人、图像、ASR 和语音均通过合规 API 或独立 Worker 实现；Remotion/Hyperframer 是渲染适配器，不是用户主界面。

## 8. 核心 Agent 与 Skill 体系

### 8.1 定位

核心 Agent 是云端内容运营编排器，不是任意模型的聊天壳，也不是自由行动的通用电脑代理。它接收用户在内容项目或情报页的请求，读取工作空间、项目上下文和 Skill 组合，生成受限计划，选择允许的执行动作，并把用户接受的结果写入正式资产。

百炼 CLI、模型 API、Tavily、飞书、Remotion 和平台 API 都是 Agent 可调用的工具提供方，不是 Agent 本身。OpenClaw、Hermes、Codex 等通用 Agent 的规划和工具调用思想可以借鉴，但不作为产品的核心依赖。

### 8.2 执行链路

```text
用户请求
→ 核心 Agent 读取项目/题材/来源/平台上下文
→ 生成结构化计划
→ 校验允许的动作、Skill 组合、Scope 与权限
→ 展示确认卡
→ Worker 按 Skill 组合执行动作
→ 写入情报、选题、内容版本、素材或发布任务
→ 记录运行、模型、来源与用量
```

### 8.3 Skill 契约

Skill 是可复用的创作规范，不等同于“生成大纲、改写一段、生成图片”等执行动作。Agent 先判断用户动作，再读取当前项目绑定的 Skill 组合约束执行结果。

每个 Skill 必须版本化并且只属于一个维度：题材、内容类型、语言风格、排版或渠道。Skill 声明适用场景、规则正文、必要输入、来源要求、质量检查、禁用表达和版本号；模型 Scope、工具权限、确认策略与失败降级由执行动作管理，不能混入风格 Skill。

Agent 动作的执行目标只允许三种：

- `cloud`：RSS、Tavily、飞书、云端模型和外部媒体 API。
- `worker`：百炼 CLI、长耗时媒体任务和云端渲染。
- `human`：发布确认、付费、删除、风险处置等只能由用户完成的动作。

### 8.4 P0 Skill 维度

| 维度 | 示例 | 主要约束 |
| --- | --- | --- |
| 题材 | AI、财经、历史、人文、国学 | 来源优先级、术语、事实规则和风险边界 |
| 内容类型 | 科普、解读、评论、教程、盘点、故事 | 叙事目标、结构和信息深度 |
| 语言风格 | 通俗、专业、犀利、清新、故事化 | 语气、句长、节奏、称谓和禁用表达 |
| 排版 | 公众号深度长文、小红书分页图文 | 标题层级、段落、强调、图片位置和导出结构 |
| 渠道 | 公众号、小红书 | 字数、标题、标签、封面、合规和内容包字段 |

五类 Skill 按生产阶段组合，不在同一个表单一次绑定。文案阶段使用题材、内容类型、语言风格和当前平台渠道规则；排版阶段在文案与图片素材确认后再选择排版规则。P0 提供平台内置预设，允许用户复制后编辑规则；不允许上传任意脚本。系统安全、事实核验、确认卡和审计规则不属于 Skill，任何组合都不能覆盖。

### 8.5 Agent 执行动作

生成大纲、生成初稿、素材重构、局部修改、生成标题、生成配图、套用排版和发布预检是 Agent 动作。每个动作声明输入/输出契约、工具白名单、模型 Scope、确认策略和写入范围；同一个动作可以在不同 Skill 组合下复用。

- “模型与 API”是所有模型、检索和外部连接的唯一凭据入口；浏览器永不读取或回显 Key。

## 2026-07-27 补充：多渠道内容生产 Workflow

本节替代前文把所有项目简化为“创作设定 → 大纲 → 初稿”的单一路径。产品目标不是替用户一次性生成文本，而是把用户自己的观点、草稿、参考资料和素材整理成可验证的内容母版，再派生为多个可独立编辑和发布的平台版本。

### 创作起点与动态路径

创建项目时允许从选题、完整草稿、零散想法、参考资料、已有文章或音视频内容开始。系统根据已有输入推荐路径：完整草稿可以跳过大纲，直接选择润色、保留观点重构、补充证据、扩写、压缩或平台改编；只有选题或零散想法时，先完成研究和大纲。跳过步骤只改变推荐顺序，不绕过事实、版权和发布审核。

### 项目输入与参考资料

每个项目提供“资料与研究”工作页，统一接收用户想法、原稿、笔记、语音转写、公开链接、上传文档、图片、音频和视频。每条参考必须标记作用范围：事实来源、观点参考、结构参考、语言参考、标题/钩子参考、视觉参考或反例；还可限定为全项目、指定平台或指定创作阶段。Agent 可以推荐分类，但用户可修改。

第一切片已开放三个互斥页签：我的内容、参考链接、素材文件。用户可新增、编辑和删除文本输入及参考资料，上传文件，并在刷新后恢复；单个文件上限为 50MB。第二切片已允许用户勾选资料并向项目 Agent 提出自然语言研究要求，先生成确认卡，确认后通过百炼 CLI 生成结构化研究计划。当前仍不会自动读取参考链接、转写音视频或宣称事实已核验；来源读取和证据状态保留为后续受控研究动作。

事实来源与风格参考必须分离。系统不得因为某篇参考文章表达优秀，就把其中所有陈述视为已验证事实；不得把参考图片默认解释为允许复制的人物、商标、构图或受保护风格。

### 浏览器研究与事实验证

Agent 先把写作目标拆为待回答问题，再调用 Tavily、公开网页读取或受限 Playwright 浏览器动作。Playwright 只读取允许公开访问且需要浏览器渲染的页面，不绕过登录、验证码、付费墙和站点风控。研究结果必须保存来源、发布时间、访问时间、摘要、可支持论点和冲突信息，并形成“已验证、单一来源、来源冲突、待核验”四种证据状态。

所有浏览器研究复用公开网页导入的 URL、DNS、跳转、响应体积和超时限制，并增加工作空间级并发、站点级速率限制和失败冷却。遇到 robots/站点条款禁止自动访问、明确挑战页或权限不明时停止并要求用户改为手工提供摘要；只持久化完成项目所需的摘要、引用片段和来源元数据，不建立网页全文镜像库。

### 内容母版与平台版本

内容母版保存跨平台共享的核心观点、事实证据、引用、案例、待核验项、用户必须保留的表达和可用素材，不直接作为发布稿。用户可多选公众号、小红书、知乎、微博、视频号、抖音或快手；P0 文案先开放公众号、小红书、知乎和微博，配图、排版与实际内容包先验收公众号和小红书。知乎与微博在对应交付格式完成前只开放真实文案版本，不显示未实现的排版或发布入口。

每个平台创建独立版本和策略快照，至少包含内容类型、语言风格、目标篇幅、传播目标、钩子策略、CTA、渠道规则、排版规则和素材要求。修改内容母版后，系统标记受影响的平台版本并提供差异同步，不得静默覆盖已人工修改的版本。

项目素材是文件和授权信息的权威对象。内容母版只引用“可用于哪些论点或视觉目的”的候选素材；平台版本保存采用关系、裁剪/编辑派生物、插入位置和发布适配。原始素材删除、授权撤销或适用范围变化时，所有采用它的平台版本标记为素材失效并阻断导出，历史运行仍保留不可变引用记录。

### 渠道规则与规则优先级

渠道规则覆盖标题、篇幅建议、正文结构、标签、链接、封面、图片/视频规格、CTA、发布字段和合规检查；排版规则只在文案和素材确认后生效。渠道规则和账号规则必须版本化，平台规则变化不得追溯修改历史运行。

冲突时按“平台硬性规则 > 当前账号规则 > 栏目/系列模板 > 项目平台策略 > 本次用户指令 > Agent 推荐值”处理。硬性规则阻断；建议性冲突展示原因，并允许用户选择采用建议或保留当前设置。

### 钩子与传播策略

单篇内容可分别选择标题钩子、开场钩子、阅读推进钩子、情绪/身份钩子、转发钩子、行动钩子和视觉钩子。Agent 根据目标读者、内容类型和传播目标推荐 2-3 个方案，用户选择或自由修改。权威、反常识、利益、冲突、数据等公式只作为可编辑模板，不作为所有题材的强制规则；账号内容比例和发布节奏属于栏目与日历，不混入单篇提示词。

### 固定流程与自由对话

固定流程负责状态、依赖和质量门：项目概览 → 资料与研究 → 内容母版 → 平台版本 → 配图 → 排版 → 审核 → 内容包。内容母版是共享数据层，不强迫单平台用户额外经过一个页面；多平台任务由 Agent 建立或更新母版后再派生。项目内 Agent 对话在所有阶段共用同一条项目时间线，用户可直接提出检索、核验、润色、局部改写、跨平台改编或素材处理请求。Agent 必须把自由对话转换为受限动作计划，展示使用的资料、工具、模型、费用和写入范围；结果先进入候选版本，用户采用后才修改正式资产。

### 配图、排版与最终交付

文案确认后先生成配图计划，每项记录插入位置、内容目的、比例、文字要求和来源方式。用户可多选使用已有素材、编辑已有图片、参考图生成、文生图、合规网络素材、数据图表或跳过。所有素材必须记录来源、授权状态和适用平台，参考图需说明只参考色彩、构图、角色、产品或质感中的哪些维度。

最终审核同时检查内容完整性、事实证据、原创性、渠道适配和素材版权。公众号内容包必须包含标题、摘要、正文、封面、正文图片、HTML、引用/待核验清单和素材目录；小红书内容包必须包含标题、正文、标签、封面、分页图文、素材目录和发布字段。可选视频任务从已确认内容母版或平台文稿创建，不阻塞图文内容包完成。

### 新旧 Workflow 迁移

数据模型增加 `workflow_version`。当前已实现项目继续标记为 `LEGACY_V1`，在 V2 的资料、母版、平台策略、配图和审核能力全部可用前，新项目也不得伪装为 V2。`CONTENT_MASTER_V2` 开放后，新项目默认使用 V2；旧项目由用户主动选择迁移，系统只复制现有 Brief、来源、正文、核验项和素材引用，不调用模型、不删除旧候选、不改变正式正文。

迁移前展示字段映射和缺失项；迁移后旧运行记录只读保留。V2 项目未完成内容母版、平台策略和最终审核时不得导出 V2 内容包。旧项目可继续使用现有大纲/初稿能力，但页面必须明确标注为旧流程，不能宣称已经完成新的研究、母版或多渠道审核。

## 2026-07-29 补充：正文质量与事实门槛

- 正文候选不是“模型返回了 JSON”就算完成。任何平台正文必须同时通过结构校验、事实边界校验和平台成稿质量审稿，才可以创建候选版本；正式正文仍只允许用户手动采用候选后更新。
- `verifiedFacts` 是正文唯一的客观事实来源。`NEEDS_REVIEW`、冲突信息和用户待核验清单属于禁止写入区：不得作为事实、类比、技术解释、能力推演或“通常如此”的背景继续展开；只能保留在待核验清单。
- 事实不足而无法支撑目标篇幅和核心表达时，系统必须停止生成，并给出“研究事实不足，暂不生成正文”的明确状态；不得用新闻通稿、百科常识、模型记忆或模糊免责声明凑成一篇文章。
- 公众号质量审稿至少检查：开篇是否有读者场景/问题与阅读价值、正文是否按事实到读者意义推进、是否出现通稿/百科/Markdown 草稿痕迹、结尾是否回应开篇问题；审稿不通过时最多自动重写一次，仍不通过则不产生候选。

- 账号声音蒸馏必须容忍模型的轻微结构偏差，例如诊断维度附带说明、扩展规则由同维度诊断可推导、中文诊断较短但语义完整；归一化后仍不满足最小诊断要求时，页面只能显示可行动错误，不得暴露 JSON Schema 或内部校验细节。

## 2026-07-30 补充：账号声音确认页的审核体验

- “确认表达规则”是对蒸馏结果的审核页，不是设置长表单。桌面端必须使用可利用的内容宽度，不能将主内容锁在窄列并留下无意义的大块空白。
- 页面先呈现规则名称、声音指纹和来源；样本诊断是主体。每项诊断应同时呈现维度、观察结论和简短依据，方便用户判断是否符合自己的表达，而非只看到抽象标签。
- 默认展示可直接继承的执行摘要；开篇、展开、文字节奏、收束四项文本编辑仅在用户主动点击“编辑规则”后展开。保存、设默认和自动避开项保持可见。
- 审核页沿用产品的马卡龙实色和深蓝边线，不引入玻璃拟态、紫色渐变或与任务无关的说明文字；窄屏时先保证可读和可点击，再退化为单列。

## 2026-07-30 补充：正文到配图的阶段门

- 采用第一篇正式文案候选后，项目进入“平台版本”阶段。该阶段的目标是确认每一个已选图文渠道的独立标题、正文与渠道规则，而不是让用户重复填写项目规划。
- 平台版本页只能在每个目标图文平台都存在非空正式正文时进入配图。缺少正文时系统指出具体平台，不允许用空白版本绕过配图和发布前审核。
- 平台版本确认会将项目推进为“配图中”；配图、排版、审核仍各自拥有独立阶段和质量门，不能由文案确认静默跳过。

## 2026-07-30 补充：文案候选的完整审核

- 正文候选的审核默认展示完整成稿，从标题到结尾均可在弹窗内连续阅读；不能仅因采用前有“段落差异”就隐藏或缩略候选全文。
- 差异视图作为并列的辅助页签，保留新增、删除和保留段落的对照能力。用户可以在完整文稿和差异之间切换，采用与废弃操作保持在固定底部。

## 2026-07-30 补充：本篇账号声音可选

- 文案工作台可以选择已保存的账号声音，也可以选择“暂不使用”。
- 未选择账号声音时仍可生成正文，系统只使用题材、内容类型、渠道、已确认资料和通用反套话质量规则；不臆造账号人格。
- 用户明确选择账号声音后才读取其规则快照。已选声音被删除或不可读取时，必须阻断生成并提示重新选择。

## 2026-07-30 补充：通用反套话与账号声音的边界

- 通用反套话检查用于提示模型自动清理模板化表达，可执行一次自动改写；没有选择账号声音时，它不能让整篇候选稿失败或消失。
- 账号声音的专属规则只在用户明确选择该声音后作为硬性质量门。二次改写后仍违反已选声音规则时，才阻断候选创建并显示原因。

## 2026-07-30 补充：重构已有正文的事实边界

- 重构、润色、扩写、压缩或平台适配已有正文时，用户原稿已包含的待核验事实可以保留，但候选必须将完整主张保留在待核验清单中。
- 系统不允许借重构新增、扩写、推演或包装待核验事实；从零生成正文仍只能使用已核验事实或用户给出的观点方法。

## 2026-07-30 补充：待核验事实的统一执行链

- 每次任务冻结当前正文与研究待核验项；系统从中计算“原稿已有且可保留”的受限清单。
- 文案生成、候选解析和质量审稿共享这一清单。系统自动把被保留的主张写入候选核验清单，用户无需重复填写。
- 质量审稿只允许受限清单中的原稿事实原样存在，发现新增、扩写、推演或伪装为确认结论时必须拒绝候选。

## 2026-07-30 补充：候选生成与发布审核分层

- 文案生成、润色、重构等所有正文动作，只要模型已返回符合结构契约的候选稿，就必须保存为候选，不能因审稿提出风险而让用户得到空结果。
- 系统仍会进行一次自动改写；若二次审稿仍发现事实或成稿质量问题，候选状态标记为“需要人工确认”，并附带具体问题与待核验清单。
- “需要人工确认”候选允许预览、继续修改和采用；最终审核、发布前才以事实核验与平台规则作为硬性拦截条件。

## 2026-07-30 补充：候选稿审阅 SOP

- 候选审阅页的首要任务是完整阅读候选正文，正文必须占据主阅读区并支持独立滚动；段落差异是同一阅读区的可选视图。
- 待核验事实和审稿问题属于发布前核验信息，默认只能显示为“待处理数量”的紧凑状态。用户主动展开后才查看具体条目，不能挤占正文阅读空间。
- “采用到正文”只表示把候选放入可继续编辑的项目正文，不代表完成审核或可直接发布。

## 2026-07-30 补充：核验项的归属

- 项目级核验池记录选题与研究阶段尚未闭环的问题，跨版本保留，供研究与最终审核处理。
- 候选稿核验项只记录本次候选正文直接关联的事实，不得把项目历史核验池、其它平台版本或内容母版的遗留项回填进候选。
- 候选采用时只向项目核验池追加本稿新增的关联项，不能用候选版本覆盖或重复注入历史核验项。

## 2026-07-30 产品收口：研究按需，创作统一

- 用户可见的创作主路径固定为“规划 → 创作 → 配图 → 排版 → 审核”。“研究”不再是必经导航步骤。
- “补充研究”保留在创作页。仅在需要检索、补证、核验或解读外部材料时进入；个人观点、已有素材改写和经验型内容可以直接创作。
- 正文与平台版本不再拆成两个工作页。主稿是内部内容资产，各平台版本是该资产的渠道呈现，用户在同一个“创作”页切换公众号、小红书、知乎或微博。
- 多平台创作完成后，创作页显示紧凑的“确认创作，进入配图”操作；不新增页面，不重复显示写作策略、正文和 Agent。

## 2026-07-30 完整图文交付闭环

- 配图阶段从项目素材库选择视觉素材。用户可以设置首图为封面，也可以在不需要图片的内容中直接确认进入排版；素材属于项目，不与临时页面绑定。
- 排版阶段按渠道生成发布稿：公众号与知乎输出 HTML，小红书与微博输出 Markdown。发布稿包含正文和已选素材位，用户可预览、切换渠道、下载，不依赖平台账号授权。
- 审核阶段只汇总真实状态：渠道正文、发布排版、已选素材和需要人工确认的事实。待核验事实不伪装成系统结论，用户完成确认后才生成发布包。
- 完成审核的项目进入“发布包已就绪”状态。下载发布稿与真正发布到外部平台分开，后者仍由发布中心的账号授权与半自动发布能力承接。
## 2026-07-30：渠道独立制作链路

- 内容项目只承载同一主题、规划和共享资料；公众号、小红书、知乎、微博是各自独立的制作单元，不存在“所有正文完成后才能配图”的项目级门槛。
- 顶层创作入口收敛为“规划、创作”。进入创作后，用户选择当前渠道，只看该渠道的文案、配图、排版、审核与发布包状态。
- 公众号、知乎采用“正文→配图→排版→审核”；小红书采用“短文案→图文卡片素材→排版→审核”；微博采用“短文案→排版→审核”，配图为可选素材。
- 每个渠道独立设置目标篇幅：公众号 1500-2500 字、知乎 1500-3000 字、小红书 300-800 字并适配 6-8 页图文卡片、微博 140-500 字或串文。此设定必须进入该渠道的模型写作上下文。
- 任一渠道审核完成即可下载该渠道发布稿和进入发布中心；仅当项目全部目标渠道都已就绪，项目整体才标记为待排期。

## 2026-07-30 补充：研究简报与可靠核验

- 一键研究必须先自动形成可见的研究简报，至少包含研究主体、2-5 个研究方向、核心关键词、按证据等级排序的优先渠道和可直接执行的查询词。用户不需要先填写这些字段。
- 研究方向必须对应正文缺少的证据，查询词必须同时包含实体名称、待核验事实和来源线索。财经、IPO、上市和募资选题优先交易所正式公告、招股书、监管或发行人披露，再使用原始媒体和可信财经媒体交叉报道。
- 核验按来源隔离执行。某个来源摘要不完整、引用无法定位或模型返回结构错误时，不得把其他有效来源的结论一起清空；系统应保留有效来源结论并把不足来源降级处理。
- 研究结果页面直接展示研究简报、可直接使用事实、单一来源事实、待补充核验项和实际来源，不能只给用户一组没有检索上下文的“待验证”列表。
- 项目再次进入研究页时必须恢复时间最新的有效研究结果；已采用结果是当前研究基线，更早候选不得重新出现。补充研究完成后，新候选在用户采用前不得覆盖已采用基线。
- 研究任务必须支持运行中取消和 Worker 重启接管。瞬时网络错误恢复后应自动清除；任务中断、取消或服务重启不得留下永久 `RUNNING` 状态，也不得写入迟到产物。

## 2026-07-30 补充：正文到配图的渠道门禁

- 当前渠道未确认正文时，“配图、排版、审核”均不可进入；完成正文并确认后才按渠道状态逐步解锁。
- 页面刷新、切换渠道或恢复旧地址时，如果请求的步骤尚未解锁，界面自动回到当前合法步骤，不挂载后续工作区，也不触发自动保存。
- 即使绕过前端直接调用接口，没有至少 80 字正式正文的渠道也不能保存配图方案。结构校验错误统一转换为中文业务提示，不向页面显示 Zod JSON。

## 2026-07-31 补充：研究事实进入正文后的状态对账

- 正文生成必须携带已采用研究结果的完整快照，包括已核验事实、单一来源事实、待补充核验项和来源引用；候选产物保留该快照对应的运行记录，便于确认研究是否真正进入模型上下文。
- 已核验事实即使被正文模型改写措辞，也不得重新进入“发布前核验”。系统应结合文本归一化、数字一致性和语义片段重合完成对账，只保留研究基线之外的新增事实风险。
- 正文质量审稿与事实核验是两个独立状态：无证据推演、因果扩写和主观结论归入“正文需重写”；真正缺少证据的事实才归入“发布前核验”。二者不得混成同一列表。
- 当质量审稿状态为 `NEEDS_REVIEW` 时，候选仍可完整查看和废弃，但前后端都必须阻止采用到正式正文；正式正文不得被未通过审稿的候选污染。
- 候选被错误采用后的数据修复必须保留候选全文与审稿记录，将正式正文恢复为采用前版本，并把项目阶段退回对应写作阶段，不自动再次调用模型。
