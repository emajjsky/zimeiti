# 内容引擎 PRD

> 版本：Web-only v1.0
> 更新：2026-07-28
> 面向：P0 为个人创作者；P2 扩展至 2-5 人内容团队

## 1. 产品定义

内容引擎是一个以“内容项目”为中心的 Web 编辑部。它帮助创作者把合规收集到的信息，转化为公众号、小红书、知乎、微博文案及后续图文/视频内容包，并通过发布记录和数据复盘改善下一轮选题。

产品不限定题材。AI、财经、历史、人文、国学等题材使用同一套工作流；AI 是生产能力，不是内容垂类。

唯一主线：

```text
情报 / 想法 / 草稿 / 导入内容 → 内容项目（规划 → 研究 → 正文 → 平台版本 → 配图 → 排版 → 审核）→ 人工确认发布 → 数据复盘
```

## 2. 目标与边界

### 2.1 P0 目标

1. 创作者每天在 10 分钟内处理情报，并把值得跟进的热点直接加入创作项目；也可从手工想法、已有草稿或导入内容开始。
2. 一个内容项目以“规划”为第一步，依次完成研究、正文、平台版本、配图、排版和审核，并按用户多选的目标渠道产出独立内容包；视频由用户按需另行创建。
3. 每次 AI 生成均可追溯使用的来源、模型、提示词版本、任务状态和成本。
4. 用户能导出发布内容包并人工发布，明确记录“待发布、已提交、已确认发布”。
5. 用户能回填基础数据，并填写或基于规则生成一条下一轮选题/内容建议；P0 不承诺自动化复盘 Agent。

### 2.2 不做什么

- 不绕过登录、付费墙、验证码、风控或网站访问限制。
- 不保存平台密码或 Cookie，不承诺所有平台全自动发布。
- 不把飞书多维表格当作主数据库。
- 不在 P0 自建图像、语音、数字人或视频基础模型。
- 不在 P0 做复杂多租户计费、广告投放、CRM 或企业审批。

## 3. 用户与场景

| 用户 | 目标 | 高频场景 |
| --- | --- | --- |
| 个人创作者 | 稳定更新、减少选题与制作时间 | 每日看热点、完成一条内容、手工发布、看结果 |
| 内容主理人 | 管理栏目、内容节奏和质量 | P2：审核选题、分配项目、查看发布和复盘 |
| 编辑/运营协作者 | 补充资料、编辑版本、安排发布 | P2：在项目中补证据、改稿、填写发布结果 |

## 4. 核心对象

| 对象 | 定义 | 关键关系 |
| --- | --- | --- |
| 工作空间 | 一个创作者或团队的数据与授权边界 | 包含所有业务对象和凭据 |
| 题材 | 关键词、栏目、来源规则和内容策略的组合 | 关联来源、情报和内容项目 |
| 情报 | RSS、授权数据、搜索或手工剪藏得到的一条记录 | 可直接加入一个内容项目，并保留来源快照 |
| 内容项目 | 一次完整内容生产的唯一工作单元 | 可来源于热点、手工想法、草稿、导入内容或历史迁移；包含规划、对话、证据、版本、素材、任务与发布记录 |
| 项目规划 | 项目进入研究前由用户确认的决策稿 | 包含标题、题材、角度、目标、受众、核心表达、平台、时效、来源要求与限制；目标篇幅不属于规划 |
| 平台版本 | 面向单一平台的可发布内容 | 属于内容项目，可有多次发布任务 |
| 素材 | 图片、音频、视频、引用和品牌资产 | P0 归属于单个项目；P1 才允许跨项目检索和复用 |
| 发布任务 | 某个版本面向某账号的一次发布动作 | 记录预检、用户确认和结果 |
| 复盘记录 | 内容表现、人工观察与可复用结论 | 回流到题材、栏目和选题策略 |

## 5. 用户工作流

### 5.1 情报收件箱

用户先在“情报源”配置题材、关键词、RSS/官方/授权来源和刷新频率；所有模型、百炼和检索凭据统一在“模型与 API”管理。系统按计划收集公开信息；用户也可以剪藏公开网页链接或用 Tavily 查找候选网页。

“情报源”分为两个互斥工作页签：

- 自动来源：默认提供可公开访问的 RSS 目录，按国内综合、科技商业、国际科技分组，用户多选后批量接入；自定义 RSS 作为折叠式补充入口。
- 辅助渠道：微博、今日头条、央视网、X、公众号、财经媒体和官方公告只提供用户主动发起的公开链接剪藏和限定域名搜索，不做未授权定时抓取，不绕过登录、验证码、付费墙或站点风控。

RSS、公开链接剪藏和 Tavily 候选使用同一分类协议。当前统一题材为 AI、科技、财经、体育、娱乐、社会、国际、时政、文化、教育、健康、汽车、其它；系统根据标题和摘要生成题材及真实命中关键词，来源预设题材只在正文无规则命中时兜底。情报按工作空间和规范化原文 URL 去重，删除追踪参数不应产生重复记录。

情报页只解决三件事：按来源和时间查看近 30 天资讯、判断是否值得跟进、加入创作。来源是一级筛选，时间提供 24 小时、7 天和 30 天三个范围，题材是次级筛选。服务端在读取和刷新时清理超过 30 天的情报；不提供无限历史堆积。情报卡片使用三列瀑布布局：顶部来源横条按来源稳定配色，卡尾显示彩色题材和实际命中的来源关键词，不显示“可信/待核验”标签，时间统一显示为“今天/昨天/日期 + 时分”。当对应热点项目仍存在时，右上角显示“已加入”，项目删除后该标签消失；再次打开时进入原项目，不重复创建。

### 5.2 规划与立项

产品不再维护独立选题池。用户从热点、手工想法、已有草稿或导入内容创建项目后，首先进入规划。热点分析可以提供时效、目标受众、建议角度、事实待核验项和平台建议，但只作为规划预填；用户保存并确认规划后，项目才进入研究阶段。规划确认前不得伪造正文或把推荐角度当作正式内容。

### 5.3 内容项目 Agent

内容项目是用户的主工作区，Agent 是项目内唯一的通用 AI 入口。用户确认规划后进入研究，并可用自然语言提出任务，例如：

> 基于这些来源写一篇面向普通读者的公众号解读，使用我保存的清新科普风格；任何不确定事实列入待核验。

Agent 按当前任务 Scope 调用工具：检索、归纳、改写、排版、生图、音视频理解、生成、渲染或飞书同步。每个会改变资产或消耗费用的任务，都必须在执行前展示确认卡。确认卡固定包含任务目的、引用来源数、模型、提示词版本、预估费用、预期产物、是否写入资产；用户可确认或取消，取消不得进入任务队列。

项目创建前的热点分析属于独立 AI 任务入口，但使用相同的 Scope、确认卡和运行记录协议；它只生成建议，不会自动创建内容项目。

### 5.4 平台内容包

P0 固定支持：

| 平台 | P0 输出 |
| --- | --- |
| 公众号 | 标题、摘要、正文 Markdown、引用/事实清单、实际封面与正文配图、HTML 和素材包 |
| 小红书 | 标题、正文、标签、实际封面、6-10 页分页图文、素材清单和发布字段 |
| 视频号（可选扩展） | 用户主动创建视频任务后，产出标题、简介、口播稿、分镜、字幕稿和视频素材清单；不影响图文项目完成状态 |

P0 发布证据统一为：导出包版本号、目标平台、计划时间、用户填写的平台内容链接或内容 ID、确认时间。仅打开平台后台或复制内容不视为发布成功。

### 5.5 发布与复盘

发布中心只记录真实状态：待排期、预检阻断、等待确认、已打开后台、已提交、已确认发布、失败或取消。P0 只支持人工发布和人工指标回填，不接入平台 OAuth/API。

有官方 API 的平台使用授权 API；无官方发布 API 时，产品导出内容包或由浏览器扩展预填，用户必须在平台页面确认发布。复盘 P0 支持人工录入阅读、收藏、点赞、评论、转发、播放和完播等指标。

## 6. 信息架构

```text
今天            按项目阶段生成的真实待办、待发布和异常
发现            热点情报、网络搜索与链接导入
创作            项目中心与规划、研究、正文、平台版本、配图、排版、审核
发布            日历、预检、账号目标、发布记录
复盘            内容表现、指标和可复用结论
────────────────────────────────
素材库          P0 查看项目级素材与品牌模板；P1 扩展跨项目检索和复用
设置            工作空间、资讯来源、模型与 API（含检索 API）、飞书模板、账号与安全
```

设置页是低频配置页。用户不应该在日常创作时反复配置 Key、来源或模型。

## 7. AI 与模型策略

- 百炼 CLI 是首选的服务端 AI 执行器；每个工作空间在“模型与 API → 百炼”只配置一次加密保存的百炼 Key，核心 Agent 复用该凭据，只配置规划模型。
- 用户可增加外部 API，但外部 API 只能覆盖其标注的能力范围。
- 每个任务都有 Scope：热点分析、选题推荐、改写/解读、长文写作、平台改写、排版、文生图、图生图/图片编辑、ASR、语音、文生视频、首帧图生视频、首尾帧生视频、参考图/视频生成、视频编辑和渲染。
- Agent 只能在该 Scope 允许的模型中选择；没有有效模型策略时不得发起生成。
- 每次生成创建不可变运行记录：来源快照、模型、提示词版本、输入/输出摘要、估算与实际用量、任务状态和产物引用。
- 视频、数字人、图像、ASR 和语音均通过合规 API 或独立 Worker 实现；Remotion/Hyperframer 是渲染适配器，不是用户主界面。

## 8. 核心 Agent 与 Skill 体系

### 8.1 定位

核心 Agent 是云端内容运营编排器，不是任意模型的聊天壳，也不是自由行动的通用电脑代理。它接收用户在内容项目或情报页的请求，读取工作空间、项目上下文和 Skill 组合，生成受限计划，选择允许的执行动作，并把用户接受的结果写入正式资产。

百炼 CLI、模型 API、Tavily、飞书、Remotion 和平台 API 都是 Agent 可调用的工具提供方，不是 Agent 本身。OpenClaw、Hermes、Codex 等通用 Agent 的规划和工具调用思想可以借鉴，但不作为产品的核心依赖。

### 8.2 执行链路

```text
用户请求
→ 核心 Agent 读取项目/题材/来源/平台上下文
→ 生成结构化计划
→ 校验允许的动作、Skill 组合、Scope 与权限
→ 展示确认卡
→ Worker 按 Skill 组合执行动作
→ 写入情报、选题、内容版本、素材或发布任务
→ 记录运行、模型、来源与用量
```

### 8.3 Skill 契约

Skill 是可复用的创作规范，不等同于“生成大纲、改写一段、生成图片”等执行动作。Agent 先判断用户动作，再读取当前项目绑定的 Skill 组合约束执行结果。

每个 Skill 必须版本化并且只属于一个维度：题材、内容类型、语言风格、排版或渠道。Skill 声明适用场景、规则正文、必要输入、来源要求、质量检查、禁用表达和版本号；模型 Scope、工具权限、确认策略与失败降级由执行动作管理，不能混入风格 Skill。

Agent 动作的执行目标只允许三种：

- `cloud`：RSS、Tavily、飞书、云端模型和外部媒体 API。
- `worker`：百炼 CLI、长耗时媒体任务和云端渲染。
- `human`：发布确认、付费、删除、风险处置等只能由用户完成的动作。

### 8.4 P0 Skill 维度

| 维度 | 示例 | 主要约束 |
| --- | --- | --- |
| 题材 | AI、财经、历史、人文、国学 | 来源优先级、术语、事实规则和风险边界 |
| 内容类型 | 科普、解读、评论、教程、盘点、故事 | 叙事目标、结构和信息深度 |
| 语言风格 | 通俗、专业、犀利、清新、故事化 | 语气、句长、节奏、称谓和禁用表达 |
| 排版 | 公众号深度长文、小红书分页图文 | 标题层级、段落、强调、图片位置和导出结构 |
| 渠道 | 公众号、小红书 | 字数、标题、标签、封面、合规和内容包字段 |

五类 Skill 按生产阶段组合，不在同一个表单一次绑定。文案阶段使用题材、内容类型、语言风格和当前平台渠道规则；排版阶段在文案与图片素材确认后再选择排版规则。P0 提供平台内置预设，允许用户复制后编辑规则；不允许上传任意脚本。系统安全、事实核验、确认卡和审计规则不属于 Skill，任何组合都不能覆盖。

### 8.5 Agent 执行动作

生成大纲、生成初稿、素材重构、局部修改、生成标题、生成配图、套用排版和发布预检是 Agent 动作。每个动作声明输入/输出契约、工具白名单、模型 Scope、确认策略和写入范围；同一个动作可以在不同 Skill 组合下复用。

## 9. 外部集成与合规

| 集成 | 角色 | 原则 |
| --- | --- | --- |
| RSS/公开网页 | 情报来源 | 只读取公开内容，遵守站点规则 |
| Tavily | 候选搜索 | 用户主动检索才调用，不自动入库 |
| 飞书 Base | 项目协作镜像 | OAuth 授权后按模板创建/同步，不作为主库 |
| 百炼 CLI/API | AI 能力 | 服务端受控执行，浏览器不接触 Key |
| 平台官方 API | 授权、发布、数据 | 仅在平台允许的范围内使用 |
| 浏览器扩展 | 半自动发布辅助 | 不上传 Cookie，验证码与最终发布由用户操作 |

## 10. 阶段范围

### P0：第一条真实内容闭环

单 Owner 工作空间下的资讯来源与刷新、候选搜索/剪藏、选题、内容项目 Agent、公众号/小红书图文内容包、人工发布确认、人工数据回填和规则化复盘结论。视频号内容由独立可选流程提供，不作为 P0 图文闭环的完成条件。

### P1：协作与生产增强（执行计划阶段 4）

飞书 OAuth/模板同步、账号授权、浏览器扩展预填、跨项目素材库、ASR/语音、任务用量和成本预算。P0 已包含完成图文闭环所需的项目级素材上传、参考图、配图计划、图像 API 调用和产物归档；P1 扩展为可跨项目复用的完整素材库。

### P2：媒体生产与自动化

Remotion/Hyperframer 云端渲染、数字人和视频 API、自动数据同步、团队角色、审核流和更深的复盘模型。

## 11. 成功标准

- 用户可连续 7 天通过同一工作空间完成至少 5 条内容的“情报到发布记录”闭环。
- 情报到创建选题的中位耗时低于 10 分钟。
- 已确认选题到首个目标渠道图文内容包初稿的中位耗时低于 30 分钟。
- 每条生成内容都能看到来源、模型和待核验事项。
- 不出现未授权发布、Cookie 上云或绕过平台验证的实现。
# 2026-07-25 补充：模型与凭据闭环

- “模型与 API”是所有模型、检索和外部连接的唯一凭据入口；浏览器永不读取或回显 Key。
- 百炼和 Tavily均支持保存并检测、重新检测、替换与移除，状态统一为未配置、待验证、可用或异常，并显示最后检测时间和可操作的失败原因。
- 外部 API 连接必须配置、检测、同步目录后才可参与任务策略；删除连接后，同时清除其模型目录与依赖策略。
- 任务策略按功能 Scope 选择已同步的真实模型目录。没有可用模型时不能保存策略，不能以硬编码模型名称兜底。
- 百炼模型目录分为“账户目录”“CLI 媒体能力”和“百炼模型市场”：账户目录来自用户 Key 的 `/models`，CLI 媒体能力来自当前内置 CLI 已实现的命令，模型市场用于补充异步媒体和语音模型。市场目录只表示官方存在，不表示用户账号已开通；真正执行时仍需按账号权限与接口结果校验。
- 任务策略保留左侧功能任务列表，右侧使用“模型来源、执行模型”下拉配置；每个模型必须声明支持的输入输出操作，不能用笼统的图片或视频能力替代具体接口契约。
- 音频任务拆分为“配音与口播”和“语音识别”。TTS 模型只能进入前者，ASR 模型只能进入后者；视频任务继续按文生视频、首帧图生视频、首尾帧生视频、参考生成和视频编辑分别路由。
- “百炼、核心 Agent、检索 API、外部 API、任务策略、调用记录”是六个独立工作页。页头必须显示当前页名称，每页只展示本页配置、状态与操作，不允许重复展示全局连接概览。
- 今日调用、累计调用、成功/失败和 Token 统计只属于“调用记录”；其它页不得显示。页面反馈必须绑定产生反馈的页签，模型同步结果只在“任务策略”中出现。

本节替代前文把所有项目简化为“创作设定 → 大纲 → 初稿”的单一路径。产品目标不是替用户一次性生成文本，而是把用户自己的观点、草稿、参考资料和素材整理成可验证的内容母版，再派生为多个可独立编辑和发布的平台版本。

### 创作起点与动态路径

创建项目时允许从选题、完整草稿、零散想法、参考资料、已有文章或音视频内容开始。系统根据已有输入推荐路径：完整草稿可以跳过大纲，直接选择润色、保留观点重构、补充证据、扩写、压缩或平台改编；只有选题或零散想法时，先完成研究和大纲。跳过步骤只改变推荐顺序，不绕过事实、版权和发布审核。

### 项目输入与参考资料

每个项目提供“资料与研究”工作页，统一接收用户想法、原稿、笔记、语音转写、公开链接、上传文档、图片、音频和视频。每条参考必须标记作用范围：事实来源、观点参考、结构参考、语言参考、标题/钩子参考、视觉参考或反例；还可限定为全项目、指定平台或指定创作阶段。Agent 可以推荐分类，但用户可修改。

第一切片已开放三个互斥页签：我的内容、参考链接、素材文件。用户可新增、编辑和删除文本输入及参考资料，上传文件，并在刷新后恢复；单个文件上限为 50MB。第二切片已允许用户勾选资料并向项目 Agent 提出自然语言研究要求，先生成确认卡，确认后通过百炼 CLI 生成结构化研究计划。当前仍不会自动读取参考链接、转写音视频或宣称事实已核验；来源读取和证据状态保留为后续受控研究动作。

事实来源与风格参考必须分离。系统不得因为某篇参考文章表达优秀，就把其中所有陈述视为已验证事实；不得把参考图片默认解释为允许复制的人物、商标、构图或受保护风格。

### 浏览器研究与事实验证

Agent 先把写作目标拆为待回答问题，再调用 Tavily、公开网页读取或受限 Playwright 浏览器动作。Playwright 只读取允许公开访问且需要浏览器渲染的页面，不绕过登录、验证码、付费墙和站点风控。研究结果必须保存来源、发布时间、访问时间、摘要、可支持论点和冲突信息，并形成“已验证、单一来源、来源冲突、待核验”四种证据状态。

所有浏览器研究复用公开网页导入的 URL、DNS、跳转、响应体积和超时限制，并增加工作空间级并发、站点级速率限制和失败冷却。遇到 robots/站点条款禁止自动访问、明确挑战页或权限不明时停止并要求用户改为手工提供摘要；只持久化完成项目所需的摘要、引用片段和来源元数据，不建立网页全文镜像库。

### 内容母版与平台版本

内容母版保存跨平台共享的核心观点、事实证据、引用、案例、待核验项、用户必须保留的表达和可用素材，不直接作为发布稿。用户可多选公众号、小红书、知乎、微博、视频号、抖音或快手；P0 文案先开放公众号、小红书、知乎和微博，配图、排版与实际内容包先验收公众号和小红书。知乎与微博在对应交付格式完成前只开放真实文案版本，不显示未实现的排版或发布入口。

每个平台创建独立版本和策略快照，至少包含内容类型、语言风格、目标篇幅、传播目标、钩子策略、CTA、渠道规则、排版规则和素材要求。修改内容母版后，系统标记受影响的平台版本并提供差异同步，不得静默覆盖已人工修改的版本。

项目素材是文件和授权信息的权威对象。内容母版只引用“可用于哪些论点或视觉目的”的候选素材；平台版本保存采用关系、裁剪/编辑派生物、插入位置和发布适配。原始素材删除、授权撤销或适用范围变化时，所有采用它的平台版本标记为素材失效并阻断导出，历史运行仍保留不可变引用记录。

### 渠道规则与规则优先级

渠道规则覆盖标题、篇幅建议、正文结构、标签、链接、封面、图片/视频规格、CTA、发布字段和合规检查；排版规则只在文案和素材确认后生效。渠道规则和账号规则必须版本化，平台规则变化不得追溯修改历史运行。

冲突时按“平台硬性规则 > 当前账号规则 > 栏目/系列模板 > 项目平台策略 > 本次用户指令 > Agent 推荐值”处理。硬性规则阻断；建议性冲突展示原因，并允许用户选择采用建议或保留当前设置。

### 钩子与传播策略

单篇内容可分别选择标题钩子、开场钩子、阅读推进钩子、情绪/身份钩子、转发钩子、行动钩子和视觉钩子。Agent 根据目标读者、内容类型和传播目标推荐 2-3 个方案，用户选择或自由修改。权威、反常识、利益、冲突、数据等公式只作为可编辑模板，不作为所有题材的强制规则；账号内容比例和发布节奏属于栏目与日历，不混入单篇提示词。

### 固定流程与自由对话

固定流程负责状态、依赖和质量门：项目概览 → 资料与研究 → 内容母版 → 平台版本 → 配图 → 排版 → 审核 → 内容包。内容母版是共享数据层，不强迫单平台用户额外经过一个页面；多平台任务由 Agent 建立或更新母版后再派生。项目内 Agent 对话在所有阶段共用同一条项目时间线，用户可直接提出检索、核验、润色、局部改写、跨平台改编或素材处理请求。Agent 必须把自由对话转换为受限动作计划，展示使用的资料、工具、模型、费用和写入范围；结果先进入候选版本，用户采用后才修改正式资产。

### 配图、排版与最终交付

文案确认后先生成配图计划，每项记录插入位置、内容目的、比例、文字要求和来源方式。用户可多选使用已有素材、编辑已有图片、参考图生成、文生图、合规网络素材、数据图表或跳过。所有素材必须记录来源、授权状态和适用平台，参考图需说明只参考色彩、构图、角色、产品或质感中的哪些维度。

最终审核同时检查内容完整性、事实证据、原创性、渠道适配和素材版权。公众号内容包必须包含标题、摘要、正文、封面、正文图片、HTML、引用/待核验清单和素材目录；小红书内容包必须包含标题、正文、标签、封面、分页图文、素材目录和发布字段。可选视频任务从已确认内容母版或平台文稿创建，不阻塞图文内容包完成。

### 新旧 Workflow 迁移

数据模型增加 `workflow_version`。当前已实现项目继续标记为 `LEGACY_V1`，在 V2 的资料、母版、平台策略、配图和审核能力全部可用前，新项目也不得伪装为 V2。`CONTENT_MASTER_V2` 开放后，新项目默认使用 V2；旧项目由用户主动选择迁移，系统只复制现有 Brief、来源、正文、核验项和素材引用，不调用模型、不删除旧候选、不改变正式正文。

迁移前展示字段映射和缺失项；迁移后旧运行记录只读保留。V2 项目未完成内容母版、平台策略和最终审核时不得导出 V2 内容包。旧项目可继续使用现有大纲/初稿能力，但页面必须明确标注为旧流程，不能宣称已经完成新的研究、母版或多渠道审核。
