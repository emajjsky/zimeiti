# 通用项目 Agent 与四平台文案工作流设计

> 日期：2026-07-27
> 状态：用户已确认设计，尚未实现
> 适用范围：纯 Web 内容项目，首批文案平台为公众号、小红书、知乎、微博

## 1. 目标

把当前研究页专用的 `ProjectResearchAgent` 和文案页孤立的大纲/初稿状态统一为一个项目级 Agent。用户在资料与研究、文案、配图、排版和审核阶段看到的是同一个 Agent、同一套项目记忆和同一条可追溯时间线；页面只切换当前阶段的资产与操作，不创建彼此割裂的智能体。

通用能力不等于允许模型任意执行。Agent 必须把自然语言请求转换为已注册动作，冻结上下文、Skill、模型、工具、费用和写入范围，先展示确认卡，执行结果先保存为候选，用户采用后才更新正式产物。

## 2. 产品原则

1. 项目只有一个 Agent 身份和一条完整会话，消息按阶段标记；默认显示当前阶段消息和前序摘要，可切换完整历史。
2. 聊天不是正式资产。研究计划、内容母版、平台文案、图片、排版和审核报告分别版本化，消息只引用产物。
3. 项目进度只由已保存或已采用的真实资产计算；口头回复、执行中任务和未采用候选不算完成。
4. 不强迫每个项目走同一条路线。完整草稿可跳过大纲；零散想法可先研究和大纲；跳步不取消事实、版权和渠道审核。
5. 内容母版是共享数据层，不强迫用户多经过一个页面。单平台任务可以直接生成平台候选，多平台任务由 Agent 建立或更新共享母版后再派生。
6. 事实未核验时允许继续形成文案候选，但必须保留待核验标记，并在最终审核与导出时阻断。

## 3. 方案选择

采用“项目级 Agent + 阶段工作区”。不采用把全部历史反复发给模型的单一长对话，也不采用研究、文案、配图、排版各自独立的多个 Agent。

每次上下文由以下部分组成：

```text
项目长期记忆
+ 前序阶段摘要
+ 当前已采用产物
+ 当前阶段候选
+ 最近对话
+ 用户本次选中的资料
```

长期项目通过阶段摘要和产物引用控制上下文长度。历史消息仍完整保存，但不默认全部进入模型输入。

## 4. 核心组件

### 4.1 Project Agent Orchestrator

读取当前页面、用户请求和项目状态，输出受控动作计划。它只选择动作，不直接修改正式资产。首批支持研究计划及文案类动作，后续复用到配图、排版和审核。

### 4.2 Context Builder

按工作空间和项目读取 WritingBrief、用户资料、研究计划、已采用文案、候选版本、阶段摘要和最近消息。用户主动选择的资料优先于 Agent 推断；未读取链接和只有元数据的文件必须保持原状态。

### 4.3 Action Registry

首批动作：

- `GENERATE_OUTLINE`
- `GENERATE_DRAFT`
- `POLISH_EXISTING_DRAFT`
- `RESTRUCTURE_DRAFT`
- `EXPAND_DRAFT`
- `SHORTEN_DRAFT`
- `REVISE_SELECTION`
- `ADAPT_PLATFORM`
- 已实现的 `PROJECT_RESEARCH_PLAN`

每个动作声明输入 Schema、输出 Schema、允许的 Skill、模型 Scope、工具白名单、是否确认、候选写入位置和采用后的写入范围。未知动作直接拒绝。

### 4.4 Skill Resolver 与 Model Router

题材、内容类型、语言风格和渠道规则参与文案动作；排版 Skill 只在排版阶段生效。模型按任务 Scope 路由，核心 Agent 负责规划，具体动作使用对应文本、图片或媒体模型。百炼 CLI 是执行适配器之一，不等同于 Agent 本身。

### 4.5 Artifact Store

统一产物索引记录类型、版本、状态、父版本、来源运行和采用时间；正文等业务内容保存在专用表。Agent 消息通过引用关联产物，不复制一份不可追踪的正文。

## 5. 数据设计

扩展 `project_agent_messages`：

- `stage`：`RESEARCH`、`COPY`、`VISUAL`、`LAYOUT`、`REVIEW`
- `action_run_id`：关联 `generation_runs`
- `message_type`：普通消息、确认卡、运行状态、候选结果、系统事件
- `artifact_refs_json`：本消息读取或生成的产物引用
- `metadata_json`：展示所需的模型、工具、Scope 和错误摘要

新增：

- `project_stage_summaries`：每个阶段的版本化摘要和覆盖消息范围
- `project_artifacts`：统一产物索引及候选/已采用/废弃状态
- `content_master_versions`：共享观点、事实、案例、保留表达、待核验项和素材引用
- `platform_strategies`：每个平台独立目标、篇幅、钩子、CTA、渠道规则和用户覆盖项
- `platform_content_versions`：平台文案候选与正式版本，引用母版和父版本

`generation_runs`、`jobs`、`agent_action_definitions`、`agent_action_versions` 和用量日志继续复用。现有研究消息迁移为 `RESEARCH` 阶段；现有大纲与初稿候选保留历史，并通过产物索引接入通用 Agent。

## 6. 四平台规则

四个平台共享内容母版，但不共享最终正文。

| 基础类型 | 平台 | 共享能力 | 平台差异 |
| --- | --- | --- | --- |
| 长内容 | 公众号 | 长文结构、论点、案例、引用 | 标题/摘要、开场、分节、关注与转发 CTA，后续生成公众号 HTML |
| 长内容 | 知乎 | 长文结构、论点、案例、引用 | 问题语境、结论前置、论证链、来源说明、讨论型结尾 |
| 短内容 | 小红书 | 钩子、短段落、标签、视觉提示 | 笔记语气、分页图文、封面与正文配图、话题标签 |
| 短内容 | 微博 | 钩子、短段落、话题 | 时效性、单条/长微博/串文、热搜话题、链接和互动表达 |

知乎不能直接套公众号排版，微博也不能直接复制小红书标签和分页逻辑。P0 文案闭环同时支持四个平台；首批实际配图、排版和内容包仍先验收公众号与小红书，知乎和微博在对应交付格式完成前只开放真实文案版本，不显示未实现的排版或发布入口。

## 7. 文案工作流

### 7.1 自由对话入口

用户输入自然语言，Agent 判断是生成、润色、重构、扩写、压缩、局部修改还是跨平台适配。无法唯一判断时只追问一个关键问题，不直接执行。

### 7.2 准备与确认

准备阶段不调用模型，确认卡至少显示：动作、目标平台、输入资料、来源版本、写作策略、Skill、模型、可能费用和写入范围。用户确认后才进入 Worker。

### 7.3 候选与采用

执行成功生成候选版本，编辑区展示全文或局部差异。用户可以继续对候选提出修改，也可以采用、废弃或保留多个分支。采用动作使用事务更新当前平台正式版本和项目进度；不覆盖其它平台。

### 7.4 多平台派生

用户多选平台时，Agent 先确认共享观点和事实，再为每个平台创建独立策略快照与候选。内容母版更新只把相关平台标记为“可同步”；用户查看差异并确认后才能创建新候选。

## 8. 页面设计

项目步骤保持“项目概览、资料与研究、文案、配图、排版、审核”。Agent 是项目级侧栏或抽屉，在所有阶段复用同一组件：

- 页头显示当前上下文，如“文案 · 知乎”。
- 默认时间线显示当前阶段消息和前序摘要。
- “完整历史”切换读取项目全部阶段消息。
- 确认卡、执行状态和候选结果直接出现在时间线中。
- 主区只展示当前阶段的主资产；文案页提供平台切换、编辑器、版本历史和差异审核，不堆放研究资料管理。
- 移动端主资产与 Agent 单栏切换，不并排压缩正文编辑器。

页面不展示尚未注册或尚未实现的动作，不使用说明性大卡片解释功能。

## 9. 错误与安全边界

- 未配置模型、Skill 缺失、资料越权或动作输入不完整时在准备阶段阻断。
- Worker 失败保存错误、用量和冻结上下文，允许基于同一输入重试，不直接写正式产物。
- 链接、文件和产物均按工作空间与项目隔离；消息引用的产物必须属于同一项目。
- 登录、验证码、付费墙、挑战页和权限不明来源统一返回人工处理，不能更换工具绕过。
- Agent 不得把未核验事实改写成已确认结论，不得静默覆盖用户人工编辑版本。

## 10. 测试与验收

自动测试不调用付费模型。至少覆盖：

1. 项目消息跨阶段恢复、阶段筛选与完整历史。
2. 上下文只引用同项目资产，摘要范围可追溯。
3. 自由请求稳定映射到注册动作，未知动作拒绝。
4. prepare 不调用模型，confirm 才入队。
5. 候选不会覆盖正式文案，采用后才更新进度。
6. 四平台策略和候选彼此隔离，母版变化不静默覆盖。
7. 公众号/知乎、红书/微博共享基础规则但保留平台差异。
8. 刷新后恢复消息、运行、候选、采用状态和当前步骤。
9. 1440px、1024px、390px 无横向溢出，移动端编辑器和 Agent 可完整操作。

## 11. 实施切片

第一切片只完成通用 Agent 基座与文案候选闭环：

```text
迁移项目消息与阶段摘要
→ 统一 ProjectAgent UI
→ 接管现有研究、大纲和初稿状态
→ 注册文案动作
→ 四平台策略与文案版本
→ 候选差异、采用、刷新恢复
```

本切片不开发配图、排版、审核执行器，也不执行来源核验。来源核验保留为后续 Agent 研究动作；未核验项继续进入文案候选和最终审核阻断条件。
