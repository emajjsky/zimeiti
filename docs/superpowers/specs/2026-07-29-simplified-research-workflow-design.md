# 简化研究工作流设计

## 目标

把内容项目的研究阶段从“多个后台任务的手工编排”收敛为用户可理解的一条路径：补充资料（可选）→ 开始研究 → 查看/调整结果 → 采用并进入正文。

研究的质量控制仍然存在，但研究计划、检索执行、来源筛选和事实核验不再逐步要求用户确认。

## 现状问题

当前界面同时暴露了两套进度和过多中间动作：制定研究计划、准备查找资料、确认调用、选择来源、准备事实核验、确认调用、确认研究结论。用户无法判断下一步，也被迫理解 `NEEDS_REVIEW` 一类内部状态。

实际验收还表明，检索返回的多条无关来源被默认全选，导致事实核验无法为目标主张提供有效证据。来源数量和长摘要占据了界面注意力，真正需要采用的研究结论反而不突出。

## 用户主流程

顶层流程维持唯一的一套：规划 → 研究 → 正文 → 平台版本 → 配图 → 排版 → 审核。删除研究页内的第二套“项目进度 2/4”。

研究页由“项目资料”和“项目 Agent”组成。

1. 用户可选地添加自己的草稿、想法、参考链接或文件；也可以不添加资料。
2. 用户点击唯一主动作“开始研究”。若用户已配置模型与检索凭据，直接执行，不再为每个内部动作弹出确认卡。
3. Agent 依次生成研究计划、检索或读取资料、按相关性与来源质量过滤、仅对准备写入正文的客观主张核验，并生成研究结果。
4. 页面展示可读的研究结果，用户可在对话中要求补查、只采用官方来源、删除某项或重做研究。
5. 用户点击“采用研究结果并进入正文”。正文 Agent 从已采用结果获得事实、风险和可用参考。

研究并非所有项目的前置条件。用户可选择“无需研究，直接进入正文”；系统在正文审核时仍会标记未核验的外部事实。

## 界面与交互

### 研究空态与执行状态

空态只显示“开始研究”主按钮和“直接进入正文”次要入口。对话框保留自由输入，用于补充研究要求，而不是承载一组任务确认卡。

执行期间，Agent 显示简短状态：正在检索、正在整理、正在核验、已完成。详细动作、调用记录和原始来源放入可展开的“研究过程”，默认收起。

### 研究结果

结果的默认视图只包含：

- 可采用的关键信息及对应引用；
- 需要谨慎表达或暂未确认的信息；
- 推荐的正文角度与可用案例；
- 两个动作：“补充研究”和“采用并进入正文”。

来源清单不再默认全选，也不要求用户逐条勾选。系统只将与主张匹配、质量达标的来源投入核验；用户可在展开详情中排除来源或主动加入链接。

内部枚举只映射为用户语言：例如 `NEEDS_REVIEW` 显示为“暂未确认”，不显示内部代码。

## 资料处理规则

资料分类是系统的上下文规则，不是用户的新必填工作。

| 资料类型 | 默认处理 | 正文使用规则 |
| --- | --- | --- |
| 用户想法、草稿、经历、笔记、访谈转写 | 直接进入写作上下文 | 作为用户观点或经历；其中的外部事实可被 Agent 单独提出核验 |
| 参考文章的观点、结构、语言、标题钩子 | 进入创作参考上下文 | 影响角度和表达，不可直接照搬或写成确定事实 |
| 图片、品牌素材、视觉参考 | 进入后续配图或排版上下文 | 不参与研究核验；配图阶段检查授权和使用范围 |
| 数字、日期、政策、产品能力、人物言论、事件结果 | 进入事实核验候选 | 未经足够证据不得作为确定事实写入正文 |

系统可根据已有的参考用途和文件类型作默认判断。用户需要纠正时，只在资料编辑中调整用途；不新增独立“研究包”或分类管理页面。

## 服务端边界

前端只创建一个“研究运行”。服务端在同一运行中保存内部子步骤、来源快照、相关性评分、证据和最终研究结果。子步骤可恢复、审计和重试，但不会成为用户必经操作。

最终采用的研究结果需要区分：已核验事实、单一来源且用户允许使用的事实、暂未确认项、创作参考和用户素材。正文生成只把前两类作为确定事实；其余内容按用途传入，不制造事实结论。

## 错误与降级

- 未配置模型或检索凭据时，“开始研究”给出明确配置入口；不生成假结果。
- 部分检索失败时仍生成研究结果，清楚列出“未完成来源”，并提供“补充研究”。
- 无关来源不会被作为证据；结果显示“未找到相关证据”，不把无关网页摘要交给正文 Agent。
- 用户选择跳过研究时允许写作，但审核阶段必须展示未核验事实提醒。

## 验收标准

1. 从确认规划到进入正文，用户最多执行“开始研究”和“采用并进入正文”两个研究相关主动作。
2. 研究页不出现重复进度条、逐条来源勾选或多次模型确认卡。
3. 研究执行过程默认只显示状态；来源、证据和调用明细可展开查看。
4. 用户草稿、创作参考和视觉素材不被强制送入事实核验。
5. 无关搜索结果不会默认进入核验；未确认的主张不会被正文 Agent 当作确定事实。
6. 用户可跳过研究进入正文，且后续审核仍能识别未核验外部事实。
# 2026-07-30 可靠性补充

- 统一研究计划必须生成结构化研究简报：主体、方向、关键词、优先渠道和查询词。
- 多来源核验失败时改为逐来源隔离核验并合并，不能因一条坏摘要清空其他有效证据。
- 研究结果默认展示研究简报和三层事实状态，避免用户只看到缺少上下文的待核验列表。
- 本补充不增加用户必填项，不恢复旧的多步骤研究确认界面。

# 2026-08-03 结果真实性补充

- 原始资讯作为基础来源独立读取，后续仍最多执行两次补充自动检索；原文不消耗补充检索额度。
- 补充来源相关性优先匹配结构化研究简报的主体和关键词，不再以原始新闻标题中的营销句作为主要实体。
- 统一结果持久化每次来源动作的成功、失败和待用户补充状态。执行完成与核验成功是两个状态，页面不得混用。
- 核验为 `FAILED` 时显示“事实核验失败”，`PARTIAL` 显示“研究部分完成”，并直接展示原因。没有 `VERIFIED` 或 `SINGLE_SOURCE` 主张时不能采用结果，前端与服务端执行同一门禁。
- 证据直接引用规则不放松；修复输出中的非法引用按主张隔离为待核验，其它合法主张继续保留。
