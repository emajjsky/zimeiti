# 热点来源矩阵与文章分类设计

## 1. 目标

在不依赖违规抓取的前提下，扩大热点数量和题材覆盖，使用户能稳定看到来自国内外多个渠道的近 30 天资讯，并按来源、题材、关键词、时间和语言筛选。

本轮完成来源扩充、文章级分类、关键词标签和筛选闭环。热点 AI 分析在该闭环通过后再执行。

## 2. 已确认边界

- 官方 RSS、官方开放接口、授权接口和允许读取的公开页面可用于自动采集。
- 微博、今日头条、央视网、X 和公众号首期通过公开链接剪藏与 Tavily 限定域名检索接入。
- 不使用非官方 RSSHub 作为默认源，不自动登录平台，不绕过验证码、登录、付费墙或访问限制。
- Playwright 只作为后续浏览助手：普通 HTTP 无法读取用户指定的公开动态页面时，打开页面、读取当前可见内容并让用户确认。Cookie 留在用户本机，不上传服务器。

## 3. 来源矩阵

### 3.1 自动来源

自动来源使用可验证的 RSS 或官方接口。首批预设分组如下：

| 分组 | 来源 | 默认题材 | 策略 |
| --- | --- | --- | --- |
| 综合 | 中国新闻网国内、国际、社会/生活 | 时政、国际、社会 | 分类频道 RSS，不再依赖单一滚动新闻源 |
| 财经 | 中国新闻网财经、36Kr | 财经 | 文章级分类可改判为科技、汽车等 |
| 体育 | 中国新闻网体育 | 体育 | 不设置包含词，保留频道完整内容 |
| 娱乐 | 中国新闻网娱乐 | 娱乐 | 不设置包含词，保留频道完整内容 |
| 科技 | IT之家、少数派 | 科技 | 移除只保留 AI 的窄关键词限制；36Kr 的科技文章由文章级分类识别 |
| 国际科技 | TechCrunch AI、MIT Technology Review、Hacker News 高热、Google AI、OpenAI News | AI、科技 | 保留英文语言规则 |

默认预设只包含本地真实请求返回成功且内容类型可解析的地址。单个来源失败不能阻断其它来源刷新。

### 3.2 辅助渠道

| 渠道 | 剪藏 | 限定域名检索 | 自动定时抓取 |
| --- | --- | --- | --- |
| 微博 | 支持公开链接 | `weibo.com` | 不支持 |
| 今日头条 | 支持公开链接 | `toutiao.com` | 不支持 |
| 央视网 | 支持公开链接 | `cctv.com`、`news.cctv.com` | 仅在后续确认公开栏目规则允许时增加 |
| X | 支持公开链接 | `x.com` | 不支持 |
| 公众号 | 支持可公开读取文章 | `mp.weixin.qq.com` | 不支持 |

辅助渠道卡片只提供明确的“剪藏链接”和“网页搜索”入口，不显示为已经自动接入的来源。

## 4. 统一题材与关键词

首批受控题材：

`AI`、`科技`、`财经`、`体育`、`娱乐`、`社会`、`国际`、`时政`、`文化`、`教育`、`健康`、`汽车`、`其它`。

分类发生在单篇文章层面：

1. 合并标题和摘要并标准化大小写、空格与常见同义词。
2. 标题命中权重高于摘要命中。
3. 按题材规则累计得分，最高分作为文章题材。
4. 没有规则命中时使用来源的默认题材。
5. 仍无默认值时归入“其它”。

分类器同时输出最多 5 个实际命中的关键词，例如“人工智能、芯片、足球、电影、教育、医疗”。关键词必须来自文章文本，不能仅因为来源配置了关键词就显示。

第一阶段使用确定性规则引擎，不调用模型。规则可以自动测试、解释和调整；热点分析阶段再让已配置模型处理摘要、相关性和选题建议。

## 5. 数据模型

`intelligence_items` 增加 `matched_keywords jsonb NOT NULL DEFAULT '[]'`。

前端 `IntelligenceItem` 增加 `keywords?: string[]`。RSS、搜索和剪藏入库时均返回该字段；没有关键词时返回空数组。

为避免多个分类 RSS 重复写入同一文章，RSS 入库前按工作空间内规范化原文 URL 去重。已经存在的记录更新题材、关键词、摘要和发布时间，不重复创建卡片。

来源的 `category` 改为“默认题材”，仅作分类回退，不再强制覆盖每篇文章。

## 6. 页面与交互

### 6.1 情报源

页面分为两个页签：

- 自动来源：按题材分组展示预设，支持选择多个来源后一次添加；下方显示已接入来源。
- 辅助渠道：展示微博、今日头条、央视网、X 和公众号，每个渠道提供剪藏和限定域名检索入口。

自定义 RSS 保留，但作为“添加自定义 RSS”表单，不和推荐来源混在同一视觉层级。

### 6.2 热点情报

筛选顺序保持：来源、时间、题材、关键词、语言、搜索、刷新。

- 题材下拉使用统一题材顺序，不再受首条数据顺序影响。
- 关键词下拉来自当前近 30 天文章的 `keywords` 去重集合。
- 卡片最多显示 1 个题材和 2 个关键词，避免底部拥挤。
- 来源横条继续使用稳定的马卡龙配色。

## 7. Playwright 浏览助手

Playwright 不参与本轮定时采集。下一阶段采用以下降级链路：

```text
用户提交公开链接
→ 普通 HTTP 解析
→ 动态页面且读取失败
→ 用户主动启动本地浏览助手
→ Playwright 读取当前可见标题、摘要、来源和时间
→ 用户确认预览
→ 写入热点池
```

浏览助手不得自动提交登录信息、处理验证码、绕过平台限制或点击最终发布。

## 8. 错误处理

- 每个来源独立记录成功条数、错误原因和最近刷新时间。
- 批量添加时按 URL 去重，已存在来源不重复创建。
- RSS 返回非 XML、超过 2MB、超时或解析为空时，来源显示可操作错误。
- 分类器异常时回退到来源默认题材，不阻断文章入库。
- 辅助渠道检索没有 Tavily Key 时，跳转到检索 API 配置页，不显示虚假结果。

## 9. 验收条件

1. 国内自动来源覆盖至少 8 个题材，并真实刷新出多个分类。
2. 同一篇文章来自多个频道时只保留一条。
3. 体育、娱乐、社会、国际、财经和科技样例能被规则分类器正确识别。
4. 关键词标签来自文章正文命中，热点页可以按关键词筛选。
5. 微博、今日头条、央视网、X 和公众号显示为辅助渠道，可进入剪藏或限定域名搜索。
6. 任何单一 RSS 失败不影响其它来源刷新。
7. 30 天保留策略继续生效。

## 10. 实施顺序

1. 提取共享题材与分类规则，先写分类器测试。
2. 增加关键词字段与全局 URL 去重迁移。
3. 扩充并验证自动来源预设。
4. 重构情报源页面和辅助渠道入口。
5. 增加关键词筛选与卡片标签。
6. 使用真实来源刷新并记录验收结果。
7. 通过后再执行真实热点分析调用。
