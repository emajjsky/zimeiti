# 公众号母稿与平台草稿工作流重构设计

> 日期：2026-08-02
>
> 状态：已完成产品设计，待用户审阅书面规格
>
> 目标：以公众号为唯一母稿，派生小红书和微博图文草稿，并在发布中心送入平台草稿箱

## 1. 背景

当前创作工作台把公众号、小红书、微博和知乎设计成四条平行生产线，并为每个平台同时展示正文、配图、排版和审核。用户需要在平台和步骤两个维度之间反复选择，小红书、微博也被错误地套入公众号式排版和审核状态。公众号排版页展示 HTML 源码而不是真实渲染结果，创作完成后的草稿、账号和发布边界也不清楚。

本次不是隐藏按钮或修正文案，而是重构内容主从关系、草稿领域和发布边界。现有 `delivery.platforms` 通用状态机不再继续扩展。

## 2. 已确认的产品决策

1. 公众号是每个内容项目唯一且强制的母稿；项目不能直接以小红书或微博起稿。
2. 创作主线固定为“内容准备 → 公众号正文 → 公众号配图 → 公众号排版 → 完成草稿”。
3. 小红书和微博只能从已完成的公众号版本派生。
4. 小红书、微博使用单页图文草稿编辑器，不存在独立配图、排版或审核步骤。
5. 小红书和微博各允许最多 9 张图片；公众号最多 12 张。
6. 草稿在创作阶段不绑定发布账号；发布页先选择账号，再勾选兼容的平台草稿。
7. 本期发布终点是平台草稿箱，不直接公开发布。无官方草稿 API 时提供人工内容包和明确确认。
8. 公众号排版提供系统模板和工作空间自定义模板；公开公众号链接只能用于提炼排版规则，不能复制原文和原图片。
9. 删除独立审核步骤。保存前执行确定性内联检查；AI 内容检查只能由用户主动触发。
10. 每个 AI 功能拥有独立可见的任务 Scope、模型策略、业务 API 和调用记录；不允许隐藏策略或静默回退。
11. 知乎从产品、API、任务策略、平台契约和业务数据中移除。历史内容先备份，模型调用记录只作为不可变用量审计保留。

## 3. 产品信息架构

### 3.1 一级导航

一级导航继续保留“创作”和“发布”，不新增独立草稿一级入口。

- 创作：项目准备、公众号母稿制作和派生草稿编辑。
- 发布：内容草稿、平台草稿任务和发布账号。
- 素材库：继续作为空间素材唯一管理入口。
- 复盘：不在本次重构中伪造发布后数据；真实公开发布记录建立后再接入。

### 3.2 创作页

删除平台标签和“正文/配图/排版/审核”二维导航，也删除“规划/创作”大切换。每个项目只显示一条线性步骤：

```text
内容准备 → 公众号正文 → 公众号配图 → 公众号排版 → 完成草稿
```

- 内容准备：选题、目标、资料和可选研究集中在一个页面，不区分平台。
- 公众号正文：生成或编辑唯一母稿。
- 公众号配图：策划、搜图、AI 生图、素材选择和统一预览。
- 公众号排版：选择模板并查看正文、图片和样式的真实渲染结果。
- 完成草稿：执行确定性检查并创建不可变公众号草稿版本。

已完成的步骤允许返回修改；未来步骤按主状态依次解锁。每个页面只提供一个明确的主操作，不再要求用户同时判断平台与阶段。

### 3.3 内容草稿结果页

公众号草稿完成后显示：

- 公众号草稿状态、当前版本和真实预览；
- “生成小红书草稿”；
- “生成微博草稿”；
- 已生成派生草稿的编辑、预览和重新生成入口；
- “去发布”。

母稿产生新版本时，已有派生稿显示“母稿已有新版本”，但系统不得自动覆盖。用户主动重新生成后创建新的派生版本，旧版本继续保留。

### 3.4 小红书和微博草稿

小红书和微博都使用单页图文编辑器：

- 同页编辑平台文案；
- 同页预览、增删、排序、裁切和替换图片；
- 主动 AI 生图在当前草稿页执行；
- 保存后形成账号无关的平台草稿；
- 不显示配图、排版、审核或发布成功状态。

小红书派生时优先复用适合的公众号素材。比例不合适或缺少的竖版卡片明确标记为待处理，用户在当前页裁切、替换或主动生成。微博从公众号素材中选择最多 9 张附件并保存顺序。

### 3.5 发布页

发布页包含三个页签：

```text
内容草稿 | 平台草稿任务 | 发布账号
```

操作顺序固定为：

```text
选择平台账号 → 勾选兼容的本地草稿 → 发送到平台草稿箱
```

草稿不能在创作阶段绑定账号。同一草稿版本可以分别送入多个账号的草稿箱，每次发送形成独立任务和回执。

## 4. 公众号排版模板

### 4.1 模板来源

- `SYSTEM`：系统预设模板，必须有真实缩略图和完整预览。
- `URL_ANALYSIS`：从用户提供的公开公众号链接提炼。
- `CUSTOM`：用户复制现有模板后编辑形成。

模板属于工作空间，可命名、预览、编辑、复制、归档和删除。已被草稿或历史版本引用的模板不可归档或删除，避免破坏既有草稿的模板管理语义。

### 4.2 链接分析边界

用户提交公开公众号链接时必须确认有权将其用于排版参考。服务端只读取公开页面，执行 SSRF 防护、重定向复查、响应大小限制和 HTML 清洗；不上传 Cookie、不绕过登录、验证码或访问限制。

模型只提炼标题层级、字号、颜色、段距、引用、分隔、重点块、图片样式和留白规则。系统不保存来源文章正文和原图片，也不复制来源页面脚本、追踪代码或不受支持的 CSS。

### 4.3 模板协议与渲染

模板保存受校验的结构化样式规则，不保存任意可执行 HTML。渲染器根据模板版本、公众号正文和有序素材确定性生成安全 HTML。

排版页必须展示真实渲染效果，不允许用 HTML 源码或静态占位图冒充预览。预览和最终草稿使用同一渲染器；最终草稿版本同时冻结模板版本和清洗后的渲染 HTML，确保发送时内容不漂移。

## 5. 领域模型

### 5.1 正式对象

| 对象 | 责任 |
| --- | --- |
| `content_projects` | 选题、内容准备和当前公众号主流程位置 |
| `content_drafts` | 账号无关的平台草稿及当前编辑态 |
| `content_draft_versions` | 生成、完成、派生和发送前的不可变草稿版本 |
| `content_draft_assets` | 草稿版本使用的素材、角色和图片顺序 |
| `wechat_layout_templates` | 工作空间级公众号模板主体 |
| `wechat_layout_template_versions` | 模板规则、来源和预览的不可变版本 |
| `platform_draft_tasks` | 草稿版本发送到目标账号草稿箱的任务与回执 |

`content_projects` 不再拥有 `delivery.platforms`。平台正文、图片、排版、审核和发布状态不得重新写入项目 JSON。

### 5.2 草稿关系

```text
公众号草稿版本
  ├─ 小红书草稿版本
  └─ 微博草稿版本
```

- 公众号草稿没有来源草稿，是项目唯一母稿。
- 小红书和微博草稿必须记录 `source_draft_version_id`。
- 草稿平台只允许 `WECHAT`、`XIAOHONGSHU`、`WEIBO`。
- 草稿不保存账号 ID。
- 图片只通过外键引用 `workspace_assets`，不复制存储键、哈希或外链。
- 平台草稿任务必须固定引用一个不可变草稿版本。

### 5.3 状态

项目主状态固定为：

```text
PREPARING
WECHAT_WRITING
WECHAT_IMAGING
WECHAT_LAYOUT
DRAFT_READY
```

派生稿生成和编辑属于 `content_drafts`，不再改变项目主阶段。草稿状态固定为 `EDITING`、`READY`、`ARCHIVED`；平台草稿任务状态固定为 `PENDING`、`RUNNING`、`SUCCEEDED`、`FAILED`、`MANUAL_PENDING`、`MANUAL_CONFIRMED`、`CANCELLED`。

## 6. API 设计

### 6.1 草稿

```text
GET    /api/v1/creative/projects/:projectId/drafts
POST   /api/v1/creative/projects/:projectId/wechat-draft
PATCH  /api/v1/content-drafts/:draftId
POST   /api/v1/content-drafts/:draftId/complete
POST   /api/v1/content-drafts/:draftId/derive
GET    /api/v1/content-drafts/:draftId/versions
GET    /api/v1/content-drafts/:draftId/preview
```

`PATCH` 使用 revision 乐观锁，旧页面不得覆盖新内容。自动保存只更新编辑态；生成、完成、派生和发送平台前创建不可变版本。`derive` 只允许从公众号版本派生小红书或微博。

### 6.2 公众号模板

```text
GET/POST       /api/v1/wechat-layout-templates
PATCH/DELETE   /api/v1/wechat-layout-templates/:templateId
POST           /api/v1/wechat-layout-templates/:templateId/duplicate
POST           /api/v1/wechat-layout-templates/import
POST           /api/v1/wechat-layout-templates/:templateId/preview
```

模板分析失败不得创建空模板。删除已使用模板时返回引用影响并要求归档，不级联破坏草稿。

### 6.3 平台草稿任务

```text
GET  /api/v1/publishing/drafts
POST /api/v1/platform-draft-tasks
GET  /api/v1/platform-draft-tasks
POST /api/v1/platform-draft-tasks/:taskId/retry
POST /api/v1/platform-draft-tasks/:taskId/cancel
POST /api/v1/platform-draft-tasks/:taskId/manual-confirm
```

创建任务时提交账号 ID、兼容平台的草稿版本 ID 和 `OFFICIAL_API | MANUAL` 方式。官方成功必须保存真实 `externalDraftId` 和受控平台响应摘要。人工方式先生成内容包，只有用户确认后才能进入 `MANUAL_CONFIRMED`。

本期 API 不提供直接公开发布动作。公开发布记录、指标和复盘在平台草稿闭环真实稳定后另行设计，不复用平台草稿成功冒充已发布。

## 7. 显式 AI 任务策略

必须建立以下独立 Scope：

```text
WECHAT_COPY_GENERATION
WECHAT_VISUAL_PLANNING
TEXT_TO_IMAGE
IMAGE_TO_IMAGE
WECHAT_TEMPLATE_ANALYSIS
XIAOHONGSHU_ADAPTATION
WEIBO_ADAPTATION
CONTENT_PREFLIGHT_REVIEW
```

每项策略独立保存提供方、连接、模型、参数、最大输出、提示词模板版本和启用状态。执行时把完整策略快照写入运行记录，并在页面显示本次任务实际使用的 Scope、提供方和模型。

任务配置与审计继续使用正式设置 API，并扩展为上述 Scope：

```text
GET /api/v1/models/task-policies
PUT /api/v1/models/task-policies/:scope
GET /api/v1/settings/prompt-templates/:scope
PUT /api/v1/settings/prompt-templates/:scope
POST /api/v1/settings/prompt-templates/:scope/reset
GET /api/v1/models/usage
```

业务执行接口只能通过任务 Scope 解析已保存策略，不能接受浏览器临时提交模型名称绕过策略。任务运行记录必须能关联业务草稿、策略快照、提示词版本、状态、用量和错误。

未配置策略时返回 `TASK_POLICY_REQUIRED`，不得复用其他 Scope、默认模型或隐藏连接。`CONTENT_PREFLIGHT_REVIEW` 只能由用户主动运行，不是保存草稿的前置条件。

图片数量、素材有效性、模板结构、HTML 安全和平台兼容属于确定性校验，不调用模型。

## 8. 错误与安全边界

至少定义以下稳定错误：

- `TASK_POLICY_REQUIRED`
- `DRAFT_REVISION_CONFLICT`
- `DRAFT_SOURCE_VERSION_STALE`
- `DRAFT_PLATFORM_UNSUPPORTED`
- `DRAFT_ACCOUNT_PLATFORM_MISMATCH`
- `DRAFT_ASSET_INVALID`
- `DRAFT_IMAGE_LIMIT_EXCEEDED`
- `LAYOUT_TEMPLATE_SOURCE_UNREADABLE`
- `LAYOUT_TEMPLATE_IN_USE`
- `ACCOUNT_DRAFT_CAPABILITY_UNAVAILABLE`
- `PLATFORM_DRAFT_DUPLICATE`

页面显示可行动中文说明，服务端日志保存关联 ID 和内部错误。不得向浏览器返回堆栈、密钥、数据库错误、平台令牌或第三方敏感响应。

平台草稿任务使用幂等键。网络超时后必须先查询任务或平台结果，不能盲目重复创建草稿。官方连接器只在已验证具有草稿接口能力时开放；否则只能使用人工内容包。

## 9. 迁移与删除

### 9.1 真实数据预检

2026-08-02 对当前真实库只读统计：

- 56 个项目存在平台版本；
- 56 个项目有公众号版本；
- 56 个项目有小红书版本；
- 7 个项目有微博版本；
- 6 个项目含知乎数据；
- 小红书或微博存在但缺少公众号母稿的项目为 0。

因此无需为孤立派生稿保留运行时兼容分支。

### 9.2 执行顺序

1. 停止业务写入，备份 PostgreSQL 和素材目录并记录 SHA-256。
2. 单独导出知乎正文、图片关系和元数据，生成可读归档与校验清单。
3. 创建草稿、版本、素材关系、模板和平台草稿任务正式表。
4. 把公众号版本迁为母稿，小红书和微博版本迁为对应母稿的派生草稿。
5. 迁移公众号图片顺序、排版结果和素材 ID，不复制物理文件。
6. 从业务表、项目 JSON、WritingBrief、平台策略和活动任务中删除知乎。
7. 删除 `delivery.platforms`、平台统一状态机、旧审核状态和无效排版对象。
8. 同一发布版本切换到新 API 和新页面，不双写、不保留旧运行时兼容入口。
9. 对项目、草稿、素材关系、文件大小、SHA-256、断裂引用和旧字段残留做迁移后对账。

任一数量、关系或文件校验不一致时中止上线并使用迁移前备份整体恢复，不做猜测性单条修复。

模型调用、用量和错误审计继续保留。审计中的 `ZHIHU` 只表示历史实际调用，不得被业务 API、任务策略页面或草稿恢复逻辑读取为可用平台。

## 10. 测试与验收

### 10.1 自动化

- 项目只按内容准备、公众号正文、配图、排版和草稿推进。
- 创作页不再出现平台切换、审核步骤和知乎。
- 系统模板、自定义模板、公开链接分析、模板版本和真实渲染预览。
- 页面不把 HTML 源码或静态占位图当成排版预览。
- 小红书、微博只能从公众号版本派生。
- 母稿更新只标记派生稿过期，不自动覆盖。
- 小红书和微博在单页完成文案及图片编辑，图片上限均为 9。
- 公众号最终草稿图片上限为 12。
- 所有 AI 动作显示真实策略，缺少配置时明确阻断且不发生模型调用。
- 草稿不绑定账号；发布页先选账号，再勾选兼容草稿。
- 官方成功必须返回真实平台草稿 ID；人工任务必须显式确认。
- 不存在直接公开发布入口或伪发布成功状态。
- revision 冲突、失效素材、模板链接失败和平台任务失败均有明确恢复路径。
- 桌面与 390px 页面无重叠、横向溢出或隐藏关键操作。
- 迁移后 56 个项目及素材完整，业务知乎数据、`delivery.platforms` 和旧状态残留为 0。

### 10.2 真实验收

使用一个真实项目完成：

```text
公众号正文
→ 公众号配图
→ 选择系统模板
→ 导入一个有权参考的公众号链接并生成自定义模板
→ 查看真实排版渲染
→ 保存公众号草稿
→ 派生并编辑小红书草稿
→ 派生并编辑微博草稿

```

关闭和刷新浏览器后，当前步骤、草稿内容、图片顺序、模板版本和任务状态必须恢复一致。

## 11. 完成定义

只有同时满足以下条件才可宣布本次重构完成：

- 新领域表、迁移、API、Worker 和页面全部切换完成；
- 旧平台通用状态机、审核页、知乎能力和无效排版代码已经删除；
- 不存在双写、隐藏任务策略、默认模型回退或历史字段运行时兼容；
- 自动化、迁移对账和真实浏览器主线验收全部通过；
- 公众号排版展示真实渲染；
- 小红书、微博图文草稿不再出现独立配图、排版和审核步骤；
- 平台草稿成功来自真实外部草稿 ID 或明确人工确认；
- 执行计划和实施文档准确区分已完成、待实施和未开放能力。
