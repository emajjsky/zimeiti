# 创作流程：自动保存与最小输入设计

## 目标

将“规划 → 研究 → 正文”从多字段手工表单改为“系统先继承已有上下文，用户只在需要时补充意图”的工作流。用户不应因未点击保存而被正文 Agent 阻塞。

## 已确认的问题

1. 正文页的默认写作策略仅存在于前端状态；界面显示“已保存”，但服务端没有 `WritingBrief`，所以 Agent 拒绝请求。
2. 规划页要求填写题材、角度、目标、受众、核心表达、来源要求、限制与发布时间，重复呈现系统可从选题、热点和已有资料继承的信息。
3. 研究结果就绪后，“补充方向”持续显示为大输入框，误导用户认为必须填写才能采用结果或进入正文。

## 交互设计

### 1. 规划：只编辑必要决策

规划主面仅保留：

- 选题标题（可编辑）
- 目标平台（可多选）
- 时效（默认继承）
- 补充要求（可选自然语言输入，覆盖研究要求与限制）

创作角度、创作目标、目标受众、核心表达、来源要求与限制继续保留在数据模型中，但由已有项目规划、热点分析结果或可解释的安全默认值填充。它们收纳为“查看规划详情”，需要时可修改，不作为进入研究的必填表单。

计划发布时间从规划移除，保留数据字段但仅在发布中心安排。未安排不应造成阻塞。

规划字段变更采用 700ms 防抖自动保存。页面仅显示“正在保存 / 已自动保存 / 保存失败”，不提供用户必须点击的保存按钮。确认进入研究时先等待最后一次保存完成。

### 2. 研究：结果优先，补充可选

未产生结果时：主要操作为“开始研究”；“无需研究，直接进入正文”保留为次级操作。

已有结果时：主要操作为“采用并进入正文”；“补充研究”改为次级入口，点击后才展开一个可选的单行补充输入。空输入时仍可基于当前项目上下文启动补充研究。

用户输入、资料、链接和文件仍可在左侧资料区主动添加，但不要求添加、不要求勾选。研究结果继续区分可采用信息、暂未确认项和正文角度。

### 3. 正文：策略自动创建、自动同步

进入正文阶段时，如果服务端没有 `WritingBrief`：

1. 用项目规划、目标平台和已注册 Skill 生成默认策略；
2. 立即写入服务端；
3. 在策略未保存完成期间，Agent 显示“正在准备创作设定”并临时禁用发送；
4. 写入成功后自动允许 Agent 请求。

写作策略字段后续变更也采用 700ms 防抖自动保存。策略区的状态文字改为“已自动保存”，只在失败时显示可重试动作。正文草稿沿用现有自动保存。

### 4. 错误与一致性

- 前端不得把未持久化的默认值标为“已保存”。
- Agent 的阻塞状态只表示真实保存中、保存失败、模型未配置或任务执行中；不再要求用户主动点击保存。
- API 保存失败时保留本地编辑值，明确展示失败原因和“重试保存”，不丢失用户输入。
- 后端确认规划时补齐缺失的可推导字段，避免旧项目或 API 调用绕过前端后仍被必填校验阻断。

## 数据与兼容性

- 不删除 `ProjectPlanning` 和 `WritingBrief` 的现有字段，也不改写已保存项目。
- 已有项目继续读取原值；缺失字段只在保存或确认时以确定性默认值补齐。
- 不新增模型调用，不在自动保存时调用检索、百炼、浏览器或发布接口。

## 验收标准

1. 新项目只编辑标题、平台和可选补充要求，也能自动保存并进入研究。
2. 已有研究结果可不填写任何补充内容，直接采用并进入正文。
3. 首次进入正文时，服务端 `WritingBrief` 自动存在；Agent 不再出现“请先保存创作设定和写作策略”。
4. 修改写作策略后无需点击保存；短暂显示保存中，成功后 Agent 可继续发送。
5. 保存失败时不丢失本地内容，且仅在实际失败时显示重试。
6. 桌面与 390px 移动端无横向溢出；规划与研究不新增冗余说明或强制输入。

## 测试范围

- 单元：规划默认值、后端确认补齐、默认 Brief 的自动持久化、策略防抖保存与 Agent 阻塞条件。
- API：无 Brief 的正文项目首次加载后可成功准备 Agent 请求。
- Playwright：规划最小输入、研究直接采用、正文自动准备策略、保存失败重试，以及桌面/移动布局。
