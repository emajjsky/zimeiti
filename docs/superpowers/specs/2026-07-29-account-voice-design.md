# 账号声音与个人 IP 设计

日期：2026-07-29  
状态：已确认方案，待用户审阅后进入实施计划

## 1. 要解决的问题

现有“语言风格”是“清新、故事化、通俗”等泛化标签。它只会让模型选择常见的科普模板，不能表达一个真实账号的立场、叙事方式、常用语言或禁区，因而容易产生：

- “很多人会问”“今天我们讲清楚”“这意味着”等无作者归属的 AI 套话；
- emoji 小标题、百科式定义、强行比喻、总结式互动等固定生成套路；
- 换一个账号也能成立的内容，无法形成可辨认的个人 IP。

本设计将用户可见的“语言风格”替换为账号级的“账号声音”。声音是可复用、可编辑、可绑定账号的创作资产；不是每篇文章临时提交的案例，也不是对第三方作者的模仿器。

## 2. 目标和非目标

### 目标

1. 用户只在首次创建或调整账号时设定声音；后续项目自动继承。
2. 首次设定不要求提供样稿。表达原型模板和三个极简问题足以生成第一版档案。
3. 用户可选择性地用自己的历史稿、已获授权的稿件或链接校准声音；这些材料仅抽取表达规律，绝不作为事实来源或照抄内容。
4. 单篇文章只允许做明确、有限的“本篇偏移”，不重新填写整套风格。
5. 生成与审稿共同抑制 AI 套话，同时不牺牲项目中的事实、渠道和合规规则。
6. 用户对稿件的有效修改可显式沉淀为账号偏好，持续提升一致性。

### 非目标

- 不承诺“只靠模板就绝无 AI 味”；个性来自用户可编辑的声音档案与后续反馈。
- 不支持“模仿某位作者/公众号”的按钮，也不将第三方文章改写为用户声音。
- 不在创作页堆出完整的提示词、风格表单或复杂的多个下拉框。
- 本轮不实现配图、排版、视频和发布工作流。

## 3. 产品方案比较

| 方案 | 内容 | 问题 |
| --- | --- | --- |
| A. 扩充“清新/犀利/故事化”下拉项 | 增加更多风格名称和提示词 | 仍是泛标签，没有账号归属；不采用。 |
| B. 强制上传样稿学习 | 每次或首次必须提供文章范例 | 门槛高，新账号无内容时无法使用；不采用。 |
| C. 账号声音档案 + 可选样稿校准 + 显式反馈 | 一次创建声音，项目继承，样稿仅作可选校准 | 兼顾零门槛、可控性和长期个性；采用。 |

## 4. 用户体验与信息架构

### 4.1 设置页：账号声音

在“设置”下新增独立入口“账号声音”，不和模型、提示词、检索 API 混在一起。页面默认是声音档案列表：名称、绑定账号数、启用状态、最近使用时间和一个简短的表达摘要。每个账号声音可复制、停用、编辑或删除；删除前必须解除绑定。

首次没有档案时，页面只展示“创建账号声音”主操作，不显示冗长空表单。

### 4.2 创建向导

创建过程保持三步，所有字段均可稍后编辑：

1. **选择表达原型**：选择一个作为起点，而不是给模型下最终命令。
2. **三句设定**：我是谁/以什么视角写；写给谁；希望读者读完留下什么。可从账号定位、题材和平台资料自动预填。
3. **确认声音草案**：系统生成结构化声音档案，用户保留、删改或重生成局部规则。

完成后可选“用代表作校准”。用户粘贴自己的链接、文本或上传文件，并明确标记为“表达参考”。该步骤可跳过，且只在建立或更新声音时发生。

### 4.3 首批表达原型

原型不使用“清新”“高级感”等空泛形容词。每张原型卡同时展示写法和禁区：

| 原型 | 写法 | 明确避免 |
| --- | --- | --- |
| 把话说透 | 先给判断，再拆理由和边界 | 假设读者提问、绕圈铺垫 |
| 一线手记 | 从亲历场景、细节或观察进入 | 为煽情而虚构经历 |
| 冷静评论 | 分开写事实、判断和推理 | 口号、替读者下结论 |
| 讲给熟人听 | 自然口语，直接解释复杂问题 | 卖萌、emoji 标题、强制互动 |
| 慢叙述 | 人物、细节、时间线推动内容 | 先下百科定义后堆资料 |
| 硬核拆解 | 先说结论与适用边界，再讲机制 | 把常识包装为新发现 |

这些原型只能作为创建起点。用户保存的账号声音才是运行时的真实约束。

### 4.4 创作页

创作页不再显示“语言风格”下拉框。写作策略区域改为一个紧凑的“账号声音”状态：当前声音名称、简短摘要和“编辑”入口。题材、内容类型、渠道规则和目标篇幅仍保留在各自应有的位置。

用户只可为本篇选择一个偏移：`默认`、`更克制`、`更锋利`、`更个人化`、`更叙述`。偏移是临时的，不能覆盖账号档案；没有选择即为默认。页面不显示提示词正文。

在正式稿编辑区，用户修改过的文本旁或版本差异中提供“保存为我的偏好”。点击后才把这项改法提炼为候选偏好，用户确认后写回声音档案；系统不得静默学习用户的任意编辑。

### 4.5 账号绑定与继承

一个账号声音可绑定一个或多个已管理的发布账号；同一账号在同一时间只允许一个默认声音。尚未授权发布账号的工作空间，可设置一个工作空间默认声音，之后绑定账号时可直接复用或复制为独立声音。

创建项目后按优先级读取：`项目显式选择` → `发布账号默认声音` → `工作空间默认声音`。无可用声音时，引导创建，不回退到“清新科普”等通用风格。

## 5. 声音档案与数据边界

一个声音档案包含：

- 基本信息：名称、原型、所有者、启用状态、适用账号；
- 身份与读者关系：作者视角、目标读者、写作意图；
- 判断方式：对事实、推断、个人观点的表达边界；
- 表达规律：开篇倾向、段落节奏、句长、称谓、可用第一人称程度；
- 正负词表：常用表达、禁止表达、禁止结构、禁用 CTA；
- 固定栏目习惯：可选的收束方式或标题习惯；
- 校准材料摘要：只保留经用户确认的风格规律，不把原文当作生成上下文；
- 用户确认的编辑偏好及版本历史。

数据层新增 `account_voice_profiles`、`account_voice_bindings`、`voice_calibration_sources` 和 `voice_preferences`。项目写作策略新增 `accountVoiceProfileId` 与 `voiceOffset`。现有 `VOICE` Skill 保留读取兼容，但停止作为用户在创作页选择的“语言风格”；迁移时将已有选择提示为创建声音档案的起点，不能默认为用户真实人设。

## 6. Agent、提示词与质量门

写作上下文按以下优先级拼装：

1. 安全、版权、事实核验和来源边界；
2. 当前平台渠道规则与内容类型要求；
3. 已确认的账号声音档案；
4. 本篇偏移；
5. 当前项目资料、已采用大纲和用户本轮指令。

Agent 使用账号声音时必须：

- 把作者的判断与已核验事实分开；没有个人素材时，不伪造亲历、职业背景或观点；
- 不复用校准原文的句子、段落结构或特有表述；
- 不使用声音档案禁止的套话和结构；
- 先输出候选稿，永不直接覆盖正式稿。

初稿质量审稿在现有事实审稿之外增加“声音一致性”检查：作者视角是否可见、是否出现禁用套话、结构是否落入模板化科普、是否有无依据的亲历/态度、是否符合账号节奏。首次不通过可生成一次候选修订；再次不通过时说明具体风险并阻断采用，不以“更自然一点”这种模糊理由拦截。

## 7. 异常、权限和可解释性

- 样稿链接读取失败时，仍可完成基础声音创建；显示失败原因和重新校准入口。
- 没有模型或模型调用失败时，保留用户已填写的三句设定和草案编辑，不丢失数据。
- 删除或停用声音前提示受影响的账号、项目和默认设置；历史文稿继续保留运行时的声音版本快照。
- 每次生成候选稿保存声音版本、偏移、规则快照和审稿结果，方便用户查看“本稿按哪个声音生成”。

## 8. 验收标准

1. 新用户不提供样稿，也能在一次创建流程中获得并保存账号声音。
2. 用户提供表达参考后，系统只提炼可编辑声音规则，不把参考正文注入事实资料或照抄到候选稿。
3. 已绑定账号的新项目自动继承正确声音；用户无需重复填写风格。
4. 创作页只显示当前声音与本篇偏移，不再显示泛化“语言风格”下拉项和提示词正文。
5. 默认模板与质量审稿均拦截列出的 AI 套话、emoji 小标题、强制互动和百科式模板结构；拦截结果必须给出具体命中项。
6. 用户手动修改不会静默改变声音；只有确认“保存为我的偏好”后才建立新版本。
7. 候选和正式稿隔离、事实质量门、平台隔离和自动保存的现有行为不回退。

## 9. 范围拆分

本设计的第一实施包仅包含：声音档案数据域、六个原型、创建/编辑/绑定、创作页继承和本篇偏移、写作上下文及声音审稿。代表作自动分析、从编辑差异提炼偏好、更多栏目模板作为第二包，必须在第一包验收真实文案质量后再开启。
