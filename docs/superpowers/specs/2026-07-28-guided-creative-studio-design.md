# 固定步骤创作工作台与通用项目 Agent 设计

**日期：** 2026-07-28
**状态：** 已确认，待实施计划
**替代规格：** `2026-07-28-conversational-research-onboarding-design.md`

## 1. 产品目标

创作模块负责把已经立项的选题转化为可审核、可排版、可发布的内容包。它不是一组相互独立的 AI 表单，也不是只有聊天框的纯对话产品，而是由固定步骤引导、正式成果驱动、通用 Agent 协作的项目工作台。

产品同时服务两类用户：

- 新用户需要明确知道当前应该做什么、完成什么才能进入下一步。
- 熟练用户可能已有草稿、研究资料或品牌素材，需要跳过不必要的生成并直接进入修改。

最终结构采用：

```text
固定步骤向导
+ 中央成果工作区
+ 可折叠通用项目 Agent
+ 项目资料抽屉
+ 候选与正式版本机制
```

## 2. 核心产品原则

- 规划阶段决定选题，创作模块继承项目标题，不重复创建或要求填写选题标题。
- 一个阶段只负责一个核心正式成果，不在同一页面堆叠多个无关模块。
- 顶部只保留一条步骤导航，不重复显示第二套项目进度。
- 对话、执行任务、候选成果和正式成果必须分离。
- Agent 每次读取明确上下文，知道项目、阶段、平台、当前成果版本和选区。
- 普通聊天直接回复；只有工具执行、高成本任务和正式资产变更才进入受控动作。
- Agent 结果先成为候选，用户应用后才更新当前工作稿；完成本阶段后才推进流程。
- 所有应用过的修改形成不可变版本，允许比较、恢复和追溯。
- 配图、排版和审核读取已确认的上游成果，不使用未保存候选。
- 视频不是图文创作必经步骤，从正式正文额外派生到独立视频工坊。
- 页面不增加大段教程、示例墙、多个快捷问题或冗余功能说明。

## 3. 创作主链路

固定步骤为：

```text
策划 → 研究 → 正文 → 平台版本 → 配图 → 排版 → 审核
```

| 阶段 | 核心正式成果 | 完成条件 |
| --- | --- | --- |
| 策划 | 项目 Brief | 目标、受众、核心表达和目标平台已确认 |
| 研究 | 研究成果 | 研究结论、来源、证据和待核验项已保存 |
| 正文 | 内容母版 | 当前工作稿被标记为正式正文 |
| 平台版本 | 各平台文案 | 至少一个目标平台版本完成 |
| 配图 | 视觉方案与已选素材 | 封面和正文视觉位已确认，或明确使用已有素材 |
| 排版 | 平台发布预览 | 当前平台的文本、图片和版式已保存 |
| 审核 | 最终内容包 | 必要审核通过，待核验和版权阻断已处理 |

已完成步骤允许返回修改。未完成步骤按顺序解锁；平台版本完成后，可以从正文额外创建视频项目，但视频流程不阻塞图文发布。

## 4. 页面框架

### 4.1 项目头部

项目头部只显示：

- 从规划阶段继承的项目标题。
- 当前项目状态。
- 项目资料入口。
- 版本历史入口。
- 返回规划页入口。

项目标题不是平台文案标题。公众号、小红书、知乎和微博可以拥有不同标题，但不能反向覆盖项目选题标题。

### 4.2 固定步骤向导

顶部步骤向导是唯一进度导航。每一步显示：

- 未开始。
- 进行中。
- 已完成。
- 上游已更新。
- 存在阻断。

删除当前资料页内部的四项进度带，避免用户同时面对两套完成标准。

### 4.3 中央成果工作区

中央区域始终展示当前阶段的核心对象：

- 策划阶段显示 Brief。
- 研究阶段显示研究成果。
- 正文阶段显示内容母版编辑器。
- 平台版本显示当前平台文案。
- 配图阶段显示视觉方案和素材位。
- 排版阶段显示发布预览。
- 审核阶段显示审核报告和阻断项。

没有正式成果时显示一个主操作；已有成果时优先显示当前工作稿，而不是空状态说明。

### 4.4 可折叠 Agent

桌面宽屏下 Agent 位于右侧，宽度约 400px，可折叠为固定的“修改与讨论”入口。中等宽度使用覆盖式侧边抽屉，移动端使用底部面板，不永久压缩正文编辑区。

系统按项目保存 Agent 的展开状态，但不把该 UI 状态写入正式内容版本。

Agent 面板头部始终显示当前作用对象：

```text
当前对象
公众号正文 · V2
全文
```

存在正文选区时变为：

```text
公众号正文 · V2
已选择第 3 段 · 186 字
```

## 5. 项目资料

资料是项目级输入，不是研究阶段的完成成果。资料管理从研究页面主区域移入项目资料抽屉，所有阶段都可以调用。

资料类型包括：

- 用户想法。
- 自有草稿。
- 笔记。
- 音视频转写。
- 公开参考链接。
- 图片、音频、视频、PDF 和文本文件。

资料字段调整：

- “新增内容”改为“添加草稿或想法”。
- 输入资料的“标题”改为“资料名称”。
- 新建资料名称非必填，优先取正文第一行，其次使用内容类型和创建时间自动生成。
- 参考链接优先使用读取到的网页标题，读取前使用域名生成临时名称。
- 上传文件默认使用原始文件名。

没有附加资料时 Agent 仍可以使用项目标题、立项角度、Brief 和已有正式成果工作。界面显示“使用项目上下文”；存在附加选择时显示“附加 N 条资料”。

## 6. 通用项目 Agent

### 6.1 定位

一个项目只有一个 Agent 和一条持久化时间线。策划、研究、正文、平台版本、配图、排版和审核共用该 Agent；页面只切换当前阶段、平台和作用对象。

Agent 具备五项职责：

- 自由对话与解释。
- 澄清用户意图。
- 读取项目上下文。
- 提议并执行受控动作。
- 生成可审阅的候选成果。

### 6.2 意图路由

每条用户消息先进入 Agent Core，返回以下决策之一：

- `RESPOND`：普通讨论，直接回复，不创建任务或成果。
- `CLARIFY`：需求不明确，继续提问，不执行动作。
- `PROPOSE_ACTION`：需要搜索、读取、生成、修改、配图、排版或审核，创建受控动作。
- `PROJECT_COMMAND`：应用候选、恢复版本、完成阶段或进入下一步，要求明确确认。

示例：

| 用户输入 | 系统行为 |
| --- | --- |
| 你好 | 正常回复 |
| 这篇文章最大的问题是什么 | 基于当前稿件分析并回复，不修改 |
| 把开头压缩一半 | 生成修订候选 |
| 这里不好 | 询问希望修改结构、语气还是信息 |
| 搜索几个国内案例 | 提议联网搜索动作 |
| 就用这一版 | 提示应用当前候选 |

标准文本对话和明确的文本修订不重复弹“确认调用”。用户发送具体修改要求已经授权生成候选，但候选仍不会自动覆盖工作稿。联网检索、读取外部来源、生图、生视频、批量处理和正式资产写入继续显示确认范围。

### 6.3 上下文读取

Agent 每次运行冻结以下上下文：

- 项目标题、立项角度、核心观点、目标受众和目标平台。
- 当前阶段和平台。
- 当前正式成果版本。
- 当前正在讨论的候选及其父版本。
- 当前全文、标题、章节或正文选区。
- 已保存研究成果、来源、证据和待核验项。
- 用户本次附加的资料 ID。
- 最近若干轮对话和前序阶段摘要。
- 当前 Skill、提示词版本、模型路由和工具权限。

每次运行记录 `baseArtifactId`、`baseVersionId`、`stage`、`platform`、`selection`、`materialIds`、上游正式成果版本、动作版本、提示词版本和模型路由，以便准确重放和审计。

完整对话历史不在每次调用时全部发送。上下文由固定项目信息、当前成果、最近对话、阶段摘要和按需检索的历史组成，防止项目增长后成本失控和语义混乱。

## 7. 连续修改与版本机制

每个阶段统一使用三层状态：

- 当前工作稿：用户正在编辑的版本。
- 修订候选：Agent 根据当前版本和用户意见生成、尚未应用的版本。
- 正式阶段成果：用户完成本阶段后冻结、供下游读取的版本。

标准修改流程：

```text
当前工作稿 V1
→ 用户提出修改意见
→ Agent 冻结 V1 和选区
→ 生成候选 V2
→ 用户继续围绕 V2 修改
→ 生成候选 V3
→ 应用 V3 到工作稿
→ 完成本阶段
→ 冻结正式版本
```

用户可以在候选未应用时继续提出修改，后续请求默认基于最新候选，而不是重新从正式版本生成。Agent 输入区明确显示“正在讨论：对象 · 版本”。

候选卡只显示变更摘要和主要操作：

```text
正文修订 V3
压缩开头，保留两个风险案例
[查看差异] [应用修改]
```

操作语义：

- “查看差异”：比较父版本和当前候选。
- “应用修改”：把候选更新为当前工作稿，并创建不可变版本记录。
- “放弃候选”：恢复到当前工作稿，不删除历史事件。
- “完成并进入下一步”：把当前工作稿冻结为正式阶段成果。

Agent 候选永远不静默覆盖当前工作稿。人工直接编辑工作稿时自动保存内容，但只有“完成本阶段”才推进流程。

## 8. 各阶段详细设计

### 8.1 策划

策划阶段读取规划立项数据并自动生成 Brief 初始值。用户只核对和补充：

- 创作目标。
- 目标受众。
- 核心表达。
- 目标平台。
- 来源与核验要求。
- 禁止表达和必须保留内容。

不显示选题标题输入，不显示 Skill 配置。主操作为“确认策划并继续”。

### 8.2 研究

空状态只显示一个“开始研究”。Agent 可以在零附加资料时基于项目上下文启动。

研究过程内部可以生成计划、执行公开搜索、读取链接、整理证据和请求人工输入，但用户进度只认正式研究成果。研究成果包含：

- 核心结论。
- 可采用事实和案例。
- 来源快照。
- 证据主张及支持、反驳关系。
- 信息冲突。
- 待核验项。
- 对正文结构的建议。

研究计划只是运行中间产物，不推进项目。用户通过对话补充来源、调整角度或重新核验，并最终“保存研究成果”。

### 8.3 正文

正文阶段管理内容母版，而不是直接同时生成四个平台版本。

用户可以：

- 从空白开始生成。
- 把自己的草稿设为正文起点。
- 根据正式研究成果生成初稿。
- 直接人工编辑。
- 选中局部交给 Agent 修改。

内容母版保存核心论点、结构、完整正文、保留表达、引用和待核验项。主操作为“完成正文”。

### 8.4 平台版本

平台版本从正式内容母版派生。公众号、小红书、知乎和微博独立保存标题、正文、平台策略和版本历史，不互相覆盖。

用户可切换平台、生成首版、对话修改、查看差异和完成平台版本。母版更新后，已完成平台版本标记“上游已更新”，由用户决定是否同步，不自动覆盖人工内容。

### 8.5 配图

配图阶段读取正式正文和平台版本，生成视觉方案：

- 封面目标。
- 正文配图位置。
- 每个图片位的内容目的。
- 风格、比例、文字限制和参考图。
- 使用用户素材、生成图片或无需新增图片的决定。

图片生成是候选资产，用户确认后才绑定到视觉方案。已有图片可以直接使用，不强制调用生成 API。

### 8.6 排版

排版阶段组合正式平台文案和已确认图片，输出平台发布预览。排版规则与写作规则分离，排版修改不反向修改正文事实，除非用户明确回到正文或平台版本阶段。

### 8.7 审核

审核阶段生成版本化报告，至少覆盖：

- 事实与来源。
- 版权与素材授权。
- 平台规则。
- 内容完整性。
- 标题、封面与正文一致性。

阻断项未处理时不能生成最终内容包或进入发布中心。普通优化建议不阻断，由用户决定是否返回前序阶段修改。

## 9. 上游更新与阶段回流

任何已完成阶段被修改后，下游正式成果不自动重写，而是标记“上游已更新”。用户可以：

- 保持现有下游成果。
- 查看上游差异。
- 让 Agent 基于差异生成同步候选。

例如研究成果 V2 被采用后，已有正文 V3 仍保持不变，但显示“研究已更新”。用户选择同步时，Agent 冻结正文 V3 和研究 V1→V2 差异，生成正文 V4 候选。

## 10. 数据与接口边界

正式领域对象包括：

- `project_brief_versions`。
- `project_inputs` 与 `project_references`。
- `source_snapshots` 与 `evidence_claims`。
- `research_report_versions`。
- `content_master_versions`。
- `platform_content_versions`。
- `visual_plan_versions` 与 `media_assets`。
- `layout_package_versions`。
- `review_report_versions`。
- `project_agent_messages`、`project_stage_summaries`、`generation_runs` 和 `project_artifacts`。

通用产物至少扩展为：

- `RESEARCH_PLAN`。
- `RESEARCH_REPORT`。
- `CONTENT_MASTER`。
- `PLATFORM_COPY`。
- `VISUAL_PLAN`。
- `MEDIA_ASSET`。
- `LAYOUT_PACKAGE`。
- `REVIEW_REPORT`。

所有项目对象继续按 `workspace_id + project_id` 隔离。模型和工具只能读取服务端为本次运行冻结的上下文，不直接访问整库或其它项目。

## 11. 错误与人工边界

- 普通聊天模型缺失时显示真实配置入口，不伪造回复。
- 文本修订失败时保留当前工作稿和原候选，不产生空版本。
- 外部搜索 Key 缺失时允许讨论和规划，但在联网前阻断。
- 登录、验证码、付费墙、平台风控和权限不明来源创建 `HUMAN_INPUT_REQUIRED`，不绕过限制。
- 版本基线已经变化时拒绝静默应用，要求刷新并重新比较。
- 上游正式成果更新后，不自动覆盖下游人工版本。
- 未核验事实可以进入正文候选，但必须贯穿到审核并阻断最终发布。

## 12. 响应式与视觉约束

- 前端实现继续使用 `design-taste-frontend`。
- 视觉参数保持 `DESIGN_VARIANCE 4 / MOTION_INTENSITY 2 / VISUAL_DENSITY 6`。
- 延续波普怀旧清新方向，但成果编辑区优先保证长内容阅读。
- 桌面 Agent 折叠后不留大块空白；中屏抽屉不压缩正文；移动端底部面板可全屏查看历史。
- 动画只用于加载、抽屉开合和候选出现，不增加展示性动效。
- 页面不显示未实现按钮、假结果、示例调用量或静态任务。

## 13. 验收标准

- 从规划立项进入创作，项目标题完整继承且不存在重复选题标题输入。
- 页面只有一条七步导航，没有第二套项目进度。
- 每个阶段中央只展示一个核心成果工作区。
- Agent 可折叠、可恢复展开状态，并始终显示当前作用对象和版本。
- 输入“你好”得到普通回复，不生成研究计划或修改候选。
- 输入分析问题只回复建议；输入明确修改要求生成基于当前版本的候选。
- 连续两次修改分别基于上一候选，版本父子关系正确。
- 候选应用前不覆盖工作稿，完成阶段前不推进下一步。
- 零附加资料可以开始研究，资料名称可自动生成。
- 保存研究成果后正文可以读取其结论、来源和待核验项。
- 内容母版与四个平台版本隔离，平台切换和刷新不会串稿。
- 上游正式成果变更只标记下游待同步，不自动覆盖。
- 1024px 和 390px 无横向溢出，Agent 抽屉、差异视图和长内容编辑可用。
- 自动化不调用真实付费模型、检索、生图或视频 API；真实调用单独人工验收并进入调用日志。

## 14. 实施顺序

实施必须纵向推进，不并行堆叠未完成页面：

1. 创作工作台外壳：单一步骤导航、中央成果区、资料抽屉和可折叠 Agent。
2. Agent Core：普通对话、澄清、动作提议、上下文构建和运行快照。
3. 通用连续修订：工作稿、候选链、差异、应用、完成阶段和上游更新标记。
4. 研究成果闭环：公开来源、证据、研究报告、对话修订和保存。
5. 内容母版闭环。
6. 四平台版本闭环。
7. 配图计划与图片资产。
8. 排版与审核。

每个切片完成后更新 PRD、PLAN、IMPLEMENT 和验收日志，并提供明确的用户验收入口。

## 15. 不在当前总规格中扩张的范围
