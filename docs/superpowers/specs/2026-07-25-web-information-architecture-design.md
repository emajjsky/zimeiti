# 内容引擎 Web 信息架构与前端重构设计

日期：2026-07-25

## 1. 设计结论

本轮不是增加新功能，而是重构现有 Web 产品的信息架构和页面归属，让用户沿着自媒体工作流程完成采集、规划、创作、发布和复盘。

最终一级导航固定为：

```text
今天
发现
规划
创作
发布
复盘
素材库

设置
```

以下入口不再出现在一级侧栏：

```text
情报源
剪藏链接
网页搜索
模型与 API
```

其中：

- “情报源”改为“资讯来源”，归入设置。
- “网页搜索”归入发现。
- “剪藏链接”改名为“导入链接”，归入发现。
- “模型与 API”归入设置。
- 微博、今日头条、央视网、X、公众号、财经媒体、官方公告不再单独形成辅助渠道页面，只作为网络搜索的来源范围预设。
- 用户可见界面中删除桌面客户端、Desktop、GPU、本地运行等已经不符合当前产品方向的概念。

## 2. 设计判断

### 2.1 产品类型

这是面向自媒体运营者的高密度 Web 工作台，不是营销落地页。用户需要频繁切换数据、配置和任务，因此界面首先服务于清晰、效率和可预测性。

### 2.2 视觉语言

保留现有“波普怀旧清新”识别度，但降低粗重描边、大面积高饱和蓝色、硬阴影和装饰线条的使用频率。

设计参数：

```text
DESIGN_VARIANCE: 4
MOTION_INTENSITY: 2
VISUAL_DENSITY: 6
```

- 变化度 4：布局允许适度非对称，但不牺牲后台产品的稳定性。
- 动效 2：只使用悬停、按压、切换、加载和结果反馈，不使用滚动叙事或装饰动画。
- 密度 6：信息较紧凑，但通过分组、留白和局部导航避免拥挤。

### 2.3 设计系统策略

本轮不引入 Fluent、Carbon、Material 或新的组件库，避免在现有 React 和原生 CSS 项目中混入第二套设计语言。

继续使用当前技术栈，并建立项目自己的轻量语义化样式规则：

- React + TypeScript + Vite
- 原生 CSS 变量和组件类
- 保留现有 Lucide 图标依赖，本轮不混用第二套图标库
- Anime.js 不用于本轮信息架构重构，因为本轮没有需要时间编排的视觉场景

## 3. 用户主流程

产品主流程固定为：

```text
设置资讯来源和检索 API
        ↓
发现热点、主动搜索或导入链接
        ↓
加入热点池并创建选题
        ↓
确认立项并进入创作
        ↓
生成平台内容并安排发布
        ↓
回填数据并复盘
```

导航只表达工作阶段。配置能力全部进入设置，避免用户在主流程中遇到与当前任务无关的系统入口。

## 4. 全局应用壳

### 4.1 顶部栏

顶部栏保留：

- 产品标识
- 全局搜索
- 新建选题
- 通知
- 刷新
- 用户菜单

调整规则：

- 顶部栏高度保持 58 至 64 像素。
- 产品标识只出现一次，不在侧栏再次展示完整品牌区块。
- 全局搜索用于搜索热点、选题、内容和素材，不承担页面内筛选。
- “新建选题”是唯一常驻主操作。
- 不显示版本号、Desktop、CLI 状态或装饰性元信息。

### 4.2 侧栏

侧栏分为三个区域：

```text
工作
  今天
  发现
  规划
  创作
  发布
  复盘

资源
  素材库

系统
  设置
```

视觉规则：

- 侧栏宽度 208 至 224 像素。
- 当前项使用浅色填充、左侧强调线和加粗文字，不使用整块高饱和蓝底。
- 导航图标统一 18 至 20 像素。
- 分组标题只承担导航分区，不加入说明句。
- 小于 960 像素时侧栏折叠为图标栏。
- 小于 720 像素时使用抽屉导航。

### 4.3 页面标题区

每个页面只保留：

- 页面标题
- 必要的主操作
- 必要时出现的局部页签

删除：

- `DISCOVER / 网页搜索` 一类装饰性面包屑
- 横贯全页的装饰线和中心方块
- 重复解释页面用途的副标题
- 与任务无关的统计或状态条

## 5. “发现”工作区

### 5.1 局部导航

“发现”使用页面内部页签：

```text
热点情报
网络搜索
导入链接
```

三个页签共享同一个一级导航高亮和同一页面壳。切换页签时不改变侧栏，不让用户误以为进入另一个产品模块。

### 5.2 热点情报

职责：查看已经进入系统的情报记录，筛选、阅读、加入热点池和创建选题。

页面结构：

```text
标题区：热点情报                         刷新热点
局部页签：热点情报 | 网络搜索 | 导入链接
筛选区：时间 | 来源 | 题材 | 关键词搜索 | 已立项状态
结果区：三列卡片网格
详情：右侧抽屉或弹层
```

筛选规则：

- “来源”筛选对应真实来源名称或来源类型。
- “题材”筛选对应 AI、科技、财经、体育、娱乐、社会、国际、时政、文化、教育、健康、汽车、其它。
- 不再同时展示“题材”和另一组语义重复的关键词分类按钮。
- 关键词使用搜索输入，不使用一整排固定关键词按钮。
- 时间默认“近 7 天”，可切换“今天、近 3 天、近 7 天、近 30 天”。
- 数据层继续只保留近 30 天记录。

卡片规则：

- 桌面宽屏固定三列，中屏两列，窄屏一列。
- 卡片高度在同一行内统一，标题最多两行，摘要最多四行。
- 顶部来源条使用马卡龙色填充，但颜色由来源类型稳定映射，不随机变化。
- 题材标签和关键词标签使用低饱和马卡龙色，标签颜色由标签值稳定映射。
- 不显示“可信、待验证”等没有实际操作价值的标签。
- 发布时间使用本地时区，格式为“今天 14:32”“昨天 09:18”或“07-21 16:40”。
- 已确认立项时，卡片右上角显示“已立项”。删除对应选题后标签同步消失。
- 卡片主体点击打开详情，主操作为“创建选题”或“查看选题”。

状态反馈：

- 刷新中：刷新按钮进入加载状态，结果区保持原内容，不闪白。
- 刷新成功：页头显示短暂结果反馈，例如“新增 8 条，更新 3 条”。
- 无新增：显示“已是最新”，不是无反馈。
- 刷新失败：显示可操作错误，并保留上一次数据。
- 空状态：根据原因分别引导“配置资讯来源”“进行网络搜索”或“导入链接”。

### 5.3 网络搜索

职责：用户主动通过 Tavily 等检索 API 查找公开网页，并将有价值的结果加入热点池。

页面结构：

```text
标题区：网络搜索
局部页签：热点情报 | 网络搜索 | 导入链接
检索条：检索词 | 题材 | 来源范围 | 开始搜索
当前检索条件摘要
候选结果列表
```

布局规则：

- 检索条件位于页面顶部同一横向区域，不再使用左侧大色块表单加右侧结果的割裂布局。
- 检索词占主要宽度。
- 题材和来源范围使用下拉选择。
- 来源范围预设包括：全网、微博、今日头条、央视网、X、公众号、财经媒体、官方公告。
- 来源预设只负责向检索服务传递域名范围，不展示成独立渠道卡片。
- 搜索结果使用紧凑列表，不复制热点情报的三列卡片。
- 每条结果显示标题、摘要、域名、发布时间、题材和“加入热点池”。

配置缺失处理：

- 未配置 Tavily 时，页面显示就地错误状态和“前往设置”按钮。
- 按钮跳转到“设置 > 模型与 API > 检索 API”。
- 页面中不出现 API Key 输入框。

### 5.4 导入链接

职责：用户粘贴一条公开文章或网页链接，系统预读后加入热点池。

页面结构：

```text
标题区：导入链接
局部页签：热点情报 | 网络搜索 | 导入链接
链接输入框 + 读取链接
预读结果
加入热点池
```

文案和交互规则：

- 全部用户可见文案使用“导入链接”，不再使用“剪藏链接”。
- 输入前有明确空输入状态，按钮禁用。
- 读取中显示内容骨架，不使用只有转圈图标的等待状态。
- 成功后展示标题、摘要、来源、发布时间和题材。
- 验证码、登录、付费墙或不可访问页面显示具体原因，不尝试绕过。
- 加入热点池成功后提供“查看热点情报”和“继续导入”两个后续动作。

## 6. “设置”工作区

### 6.1 局部导航

“设置”使用页面内部页签：

```text
工作空间
资讯来源
模型与 API
飞书 Base
账号授权
```

设置页签在桌面端使用左侧二级导航，在窄屏使用顶部横向滚动页签。设置页面不与主工作流程共用卡片或标题结构。

### 6.2 工作空间

负责：

- 工作空间名称
- 默认题材
- 时区
- 数据保留期展示
- 成员和权限的后续入口

本轮不扩展成员系统，只保留已有可用配置。

### 6.3 资讯来源

职责：管理自动采集来源，不负责主动搜索或手工导入。

页面结构：

```text
标题区：资讯来源                         添加自定义 RSS
来源目录：按题材或来源类型分组
已接入来源：状态、刷新频率、最近同步、操作
题材与关键词：来源级默认配置
```

功能范围：

- 浏览默认 RSS 来源目录。
- 批量接入默认来源。
- 添加自定义 RSS。
- 启用、停用、编辑、删除来源。
- 设置刷新频率。
- 设置来源默认题材和关键词。
- 查看最近同步时间和错误。

不包含：

- 微博、头条、X 等辅助渠道卡片。
- 网络搜索入口。
- 导入链接入口。
- Tavily Key 配置。
- 核心 Agent 配置。

来源列表优先使用分组列表和表格式行，不再使用大量彩色卡片。颜色只用于状态和题材，不用于区分每一个来源容器。

### 6.4 模型与 API

保留现有内部页签：

```text
百炼
核心 Agent
检索 API
外部 API
任务策略
调用记录
```

规则：

- 百炼 Key 只配置一次。
- 核心 Agent 复用百炼凭据，只配置规划模型和运行策略。
- Tavily 等检索凭据统一在“检索 API”。
- 已保存连接可查看状态、编辑、重新验证和删除。
- 任务策略从已验证连接的模型目录中选择模型。
- 调用次数、Token、费用和错误只出现在“调用记录”，不重复散落到其他页。

### 6.5 飞书 Base

负责：

- 飞书授权状态
- 内容项目模板编辑
- 模板字段预览
- 根据确认后的模板创建 Base
- 已绑定 Base 管理
- 同步状态和错误

飞书配置不与工作空间基础信息混在同一个长页面。

### 6.6 账号授权

负责公众号、视频号、小红书等平台账号的授权或手工绑定状态。本轮只建立页面归属和空状态，不扩展实际发布 API。

## 7. 组件边界

### 7.1 路由状态

一级视图建议收敛为：

```ts
type View =
  | 'today'
  | 'discover'
  | 'plan'
  | 'topicEditor'
  | 'create'
  | 'publish'
  | 'review'
  | 'assets'
  | 'settings';
```

局部视图独立定义：

```ts
type DiscoverSection = 'inbox' | 'search' | 'import';

type SettingsSection =
  | 'workspace'
  | 'sources'
  | 'models'
  | 'feishu'
  | 'accounts';
```

### 7.2 页面壳组件

新增：

- `DiscoverWorkspace`：管理发现页标题、局部页签和三个子页面。
- `SettingsWorkspace`：管理设置二级导航和五个配置子页面。
- `SectionTabs`：统一局部页签交互和无障碍属性。
- `PageHeader`：统一标题、主操作和反馈区。

调整：

- `SettingsHub` 重命名并收敛为 `SourceSettings`。
- `LinkClipEditor` 重命名为 `LinkImportPanel`。
- `WebSearchPanel` 只保留检索表单和结果。
- `ModelSettingsScreen` 作为设置子页面继续使用。
- `WorkspaceSettings` 拆成工作空间和飞书 Base 两个明确区块。

删除：

- `sources`、`clip`、`automation`、`models` 作为一级 `View`。
- 辅助渠道独立页面模式。
- 从资讯来源跳转到搜索或导入的渠道卡片操作。

## 8. 状态和导航规则

### 8.1 深层跳转

页面可通过统一导航意图跳转到设置的具体位置，例如：

```ts
openSettings('models', 'search-api');
openSettings('sources');
openDiscover('search', preset);
openDiscover('import');
```

不再通过修改一级 `View` 来模拟二级页面。

### 8.2 返回规则

- 网络搜索结果加入热点池后，用户留在当前结果页。
- 导入链接成功后，用户可主动进入热点情报。
- 设置保存后留在当前页签，并显示就地成功反馈。
- 从错误提示进入设置后，保存成功可返回原任务，但本轮允许先通过浏览器历史返回。

### 8.3 URL 规则

当前原型如仍使用单页状态，可先保持现有运行方式，但组件状态必须按一级和二级视图分离。后续接入正式路由时，目标路径为：

```text
/discover/inbox
/discover/search
/discover/import
/settings/workspace
/settings/sources
/settings/models
/settings/feishu
/settings/accounts
```

本轮不要求引入路由库，但禁止继续增加新的平级布尔状态和一级 View。

## 9. 视觉规范

### 9.1 色彩

保留暖白底和深蓝黑文字，主强调色使用克制的钴蓝。红色只用于错误和关键警示，不再作为按钮硬阴影装饰。

建议语义色：

```text
页面背景：暖白
一级表面：纯白
二级表面：淡蓝灰
主文字：深蓝黑
次文字：灰蓝
主操作：钴蓝
成功：薄荷绿
警告：柔黄
错误：珊瑚红
```

来源和标签允许使用多种马卡龙色，但必须由数据值稳定映射，并保持低饱和、深色文字和足够对比度。

### 9.2 圆角和阴影

- 页面面板和卡片统一 8 像素圆角。
- 输入框和按钮统一 6 像素圆角。
- 标签使用小圆角，不使用全胶囊造型。
- 阴影只用于抽屉、弹层和悬浮层。
- 普通内容容器使用边框或背景层级，不使用厚重偏移阴影。

### 9.3 字体和层级

- 继续使用适合中文后台的无衬线字体。
- 页面标题 28 至 32 像素。
- 区块标题 18 至 20 像素。
- 正文 14 像素。
- 辅助信息 12 像素。
- 数字和技术标识可使用等宽字体，但不把普通中文导航变成等宽字。

### 9.4 动效

只允许：

- 页签切换的 120 至 180 毫秒淡入。
- 按钮悬停和按压反馈。
- 列表加载骨架。
- 保存、刷新和加入热点池的结果反馈。
- 抽屉进入和退出。

不使用：

- 页面进入大范围错位动画。
- 自动循环动画。
- 滚动劫持。
- 卡片漂浮、磁吸和视差。
- 为展示 Anime.js 而添加的无业务意义动画。

## 10. 响应式

### 10.1 宽屏，1280 像素及以上

- 展开侧栏。
- 热点三列卡片。
- 设置使用左侧二级导航。
- 网络搜索条件横向排列。

### 10.2 中屏，960 至 1279 像素

- 侧栏可折叠为图标栏。
- 热点两列卡片。
- 设置仍可使用窄二级导航。
- 网络搜索条件分为两行。

### 10.3 窄屏，720 至 959 像素

- 侧栏折叠。
- 热点单列。
- 设置二级导航变为横向滚动页签。
- 详情使用全宽抽屉。

### 10.4 手机，小于 720 像素

- 使用顶部栏和抽屉导航。
- 主操作按钮固定在标题区，不做底部悬浮按钮。
- 所有表单单列。
- 结果操作可换行，但按钮文字不能折为两行。

同时删除当前 `body { min-width: 1180px; }` 的硬限制，避免 Web 产品在普通笔记本和窄屏浏览器中横向溢出。

## 11. 数据和服务边界

本次重构以改变前端信息架构为主，继续复用以下服务契约：

- RSS 来源目录和刷新 API。
- Tavily 搜索 API。
- 公开链接读取 API。
- 情报分类、关键词、去重和 30 天保留策略。
- 百炼 Key、模型目录、任务策略和调用日志 API。
- 飞书模板和 Base 同步数据结构。

组件移动后仍使用原有 API，不复制数据，不创建第二套状态。

唯一新增的服务能力是资讯来源更新接口，用于持久化来源名称、地址、题材、关键词、语言、启用状态和刷新频率。当前服务端只有来源新增与删除，如果只在前端提供编辑会在刷新后丢失，因此必须增加 `PUT /api/v1/intelligence/sources/:id`，并保持现有来源数据结构不变。

## 12. 错误处理

所有错误必须出现在用户正在操作的位置：

- 来源同步错误显示在对应来源行。
- 搜索凭据缺失显示在网络搜索页。
- 链接不可读显示在导入链接预读区。
- 模型验证失败显示在对应连接配置中。
- 保存成功和失败均保留当前表单内容。
- 全局 Toast 只用于短暂确认，不承载需要用户处理的详细错误。

错误信息必须同时说明：发生了什么、数据是否保留、用户下一步能做什么。

## 13. 测试和验收

### 13.1 导航验收

- 侧栏只出现 8 个一级入口。
- 界面不再出现 Desktop、桌面客户端或 V0.1 版本装饰。
- 发现内三个页签切换时侧栏始终高亮“发现”。
- 设置内五个页签切换时侧栏始终高亮“设置”。
- 资讯来源、模型与 API 不再是一级入口。

### 13.2 发现验收

- 热点筛选中的来源、题材和关键词语义对应正确。
- 网络搜索可选择微博、今日头条、央视网、X、公众号、财经媒体和官方公告来源范围。
- 未配置 Tavily 时能准确跳到检索 API 设置。
- 导入链接输入为空时按钮禁用。
- 网络搜索和导入链接成功后均可加入同一热点池。
- 已立项标签随选题创建和删除同步变化。

### 13.3 设置验收

- 资讯来源只管理自动来源，不出现辅助渠道卡片。
- 来源支持添加、编辑、启停、删除和查看同步状态。
- 模型与 API 保留连接验证、已保存连接管理、任务策略和调用记录。
- 飞书 Base 独立于工作空间基础配置。

### 13.4 视觉验收

- 1280、1024、768 和 390 像素宽度无横向溢出。
- 热点卡片在同一行高度一致。
- 普通页面不出现大面积硬阴影和装饰性中心方块横线。
- 当前导航高亮清晰但不刺眼。
- 标签颜色稳定，不能在每次渲染时随机变化。
- Loading、Empty、Error、Success 四类状态均可见且可理解。

### 13.5 自动化测试调整

- 更新现有 UI contract 测试中的一级 View 和侧栏文案断言。
- 增加发现局部页签和设置局部页签断言。
- 增加“辅助渠道不在资讯来源页”的断言。
- 增加“搜索预设仍包含国内外渠道”的断言。
- 保留现有来源筛选、分类、30 天保留和 API 契约测试。
- 使用 Playwright 验证主要导航、响应式、搜索缺少凭据和导入空状态。

## 14. 实施顺序

批准本设计后，实施计划按以下顺序拆解：

1. 重构一级 View、侧栏和页面壳。
2. 建立 DiscoverWorkspace，并迁移热点、搜索、导入。
3. 建立 SettingsWorkspace，并迁移来源、模型、飞书和账号页。
4. 删除辅助渠道页面和可见桌面端文案。
5. 重构基础视觉、响应式和状态反馈。
6. 更新 PRD、PLAN、IMPLEMENT 和验收记录。
7. 更新测试并执行构建、单元测试和 Playwright 验收。

## 15. 本轮不做

- 不接入新的资讯平台抓取能力。
- 不新增浏览器自动化抓取。
- 不扩展 AI 热点分析。
- 不实现新的发布 API。
- 不实现账号 OAuth。

- 不引入新的设计系统、动画库或路由库。
