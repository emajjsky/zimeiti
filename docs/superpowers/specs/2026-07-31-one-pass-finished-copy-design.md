# 一次 Agent 任务交付最终成稿设计

> 日期：2026-07-31
> 状态：设计已口头确认，待用户复核本文档
> 适用范围：纯 Web 内容项目；公众号、小红书、知乎、微博正文生成
> 替代范围：首次正文生成不再遵循“生成候选 -> AI 审稿 -> AI 重写 -> 用户采用”的旧链路

## 1. 产品目标

用户点击“生成正文”后，系统应结合已确认规划、研究资料、平台规则、账号声音和本篇要求，通过一次 Agent 任务交付可直接进入配图与排版的完整成稿。用户看到的结果只有标题和正文，不承担清理审稿意见、内部状态或核验清单的工作。

本设计中的“一次 Agent 任务”具有明确边界：一次用户操作、一次正文模型调用、一次事务落库。模型可以在同一次推理中静默完成构思、组织、写作和自检，但系统不得在正文返回后自动调用审稿模型、自动重写或循环复审。

“成稿”表示系统按照当前输入尽最大能力产出符合平台、篇幅、事实和账号表达要求的完整文章。用户仍可主动编辑或提出新修改，但不应因为系统交付的是半成品而被迫返工。

## 2. 非目标

- 不承诺每篇内容必然成为爆款；系统负责优化传播结构、标题承接、读者价值和平台适配。
- 不在首次正文生成后展示 AI 审稿意见、质量分数、待核验列表或内部 Prompt。
- 不通过后台多轮模型调用弥补输入质量问题。
- 不把发布审核、配图规划或排版任务混入正文生成。
- 不自动覆盖用户已经编辑过的正文。

## 3. 用户链路

```text
确认规划
-> 按需完成研究或准备用户原始材料
-> 系统在调用前检查写作输入是否就绪
-> 用户点击“生成正文”
-> Agent 一次生成最终成稿
-> 标题与正文直接进入编辑器并自动保存
-> 用户确认正文后进入配图和排版
```

首次生成不再打开“审核文案”候选弹窗。页面执行中显示“正在生成正文”；执行成功后正文直接出现在当前平台编辑器，右侧切换为已有正文的主动修改动作。

## 4. 调用前输入检查

系统必须先判断项目是否具备可靠写作基础，再决定是否调用模型。

### 4.1 必需输入

- 已确认的项目规划：选题标题、题材、内容类型、目标平台和核心表达。
- 当前平台写作规则：目标篇幅、平台结构、渠道禁区和输出格式。
- 已保存的账号声音；用户未选择账号声音时使用明确的通用写作规则，不臆造个人 IP。
- 至少一种内容依据：已采用研究事实、用户原创草稿/经历/观点，或用户明确授权使用的参考资料。

### 4.2 外部事实型内容的门槛

财经、科技新闻、政策、健康、人物、公司和事件解读等依赖外部事实的内容，必须至少具有与选题直接相关的已核验事实。只有媒体标题、搜索摘要、未确认主张或无关来源时，系统在模型调用前提示“写作资料不足，请先补充研究”，不得付费生成一篇靠模型记忆补全的文章。

个人观点、经验复盘、用户原稿改写和虚构创作可使用用户材料作为主要依据，不强迫进入研究流程。系统必须把用户观点标为作者表达，不把它伪装成外部事实。

## 5. 写作资料包

服务端在每次生成前构建只读 `WritingPacket`。它是本次 Agent 唯一可见的业务上下文，不直接把完整项目快照、历史候选或审稿记录发送给模型。

```ts
type WritingPacket = {
  projectId: string;
  platform: 'WECHAT' | 'XIAOHONGSHU' | 'ZHIHU' | 'WEIBO';
  lockedTitle: string;
  subject: string;
  contentType: string;
  audience: string;
  objective: string;
  targetLength: string;
  platformRules: string[];
  accountVoice: string[];
  articleTone: string;
  authorMaterials: Array<{ id: string; kind: 'DRAFT' | 'OPINION' | 'EXPERIENCE'; content: string }>;
  verifiedClaims: Array<{ id: string; claim: string; sourceIds: string[] }>;
  creativeReferences: Array<{ id: string; purpose: 'ANGLE' | 'STRUCTURE' | 'STYLE'; summary: string }>;
  forbiddenClaims: string[];
};
```

### 5.1 可以进入模型的内容

- 研究结果中顶层状态为 `VERIFIED` 的明确主张。
- 已核验主张对应的来源 ID，用于运行追溯，但不要求模型在正文中输出引用编号。
- 用户原创草稿、经历和观点，并明确标注其用途。
- 用户授权的创作参考，只提供已提炼的角度、结构或表达规则。
- 当前平台规则、账号声音、本篇语气和目标篇幅。

### 5.2 禁止进入模型的内容

- 旧候选正文、旧失败运行和旧审稿意见。
- `SINGLE_SOURCE`、`CONFLICTING`、`NEEDS_REVIEW` 等未确认外部主张。
- 证据摘要中没有被提升为顶层已核验事实的旁支日期、数字、因果解释和推断。
- 其他平台正文和无关项目历史核验池。
- 参考文章原文中未授权复用的句子。

当前宇树科技案例暴露出的核心输入错误必须由此解决：模型曾从证据 quote 中抽取“3 月 20 日”“6 月 1 日”“7 月 6 日”等旁支事实，而审稿只认可顶层 `verifiedFacts`，导致生成和审稿互相否定。新资料包只传顶层已核验主张，不传可被误当成写作事实的完整证据对象。

## 6. 单次 Agent 执行

`GENERATE_DRAFT` 使用正文生成任务 Scope 选定的文本模型，并只调用一次 `textRunner.runText()`。系统提示词要求模型在同一次推理中静默完成以下工作：

1. 理解选题、受众和读者价值。
2. 设计符合平台的开篇钩子、论证顺序、段落节奏和结尾收束。
3. 只把 `verifiedClaims` 作为确定的外部事实；作者观点必须以分析或判断的语气表达。
4. 使用账号声音和本篇语气，避免模板化 AI 套话、虚假权威、夸张承诺和生硬 CTA。
5. 在输出前自行检查标题承接、篇幅、事实边界、结构完整性和平台适配。
6. 只输出最终正文，不输出构思过程、检查清单、JSON、Markdown 代码围栏、核验项或解释。

系统不得在本次模型返回后继续调用：

- 账号声音修正模型；
- 质量审稿模型；
- 自动重写模型；
- 二次复审模型。

## 7. 输出契约

### 7.1 模型输出

首次正文模型只返回完整正文纯文本。项目规划中确认的标题继续作为正式标题，不要求模型再次生成标题或改变选题。

```ts
type FinishedCopyOutput = {
  title: string; // 来自 lockedTitle，不由模型改写
  body: string;  // 模型唯一业务输出
};
```

平台规则决定正文形态：

- 公众号：移动端可读的完整长文，段落清晰，不输出 Markdown 标记。
- 知乎：结论与论证链完整，保留问题语境，不照搬公众号口吻。
- 小红书：短段落、强信息密度和可配图结构，不自动添加虚假体验或强制互动。
- 微博：单条、长微博或串文按已选渠道规则输出，不复制小红书分页话术。

### 7.2 程序校验

模型返回后只允许执行不调用 AI 的确定性技术校验：

- 正文非空；
- 正文不是 JSON、错误信息或代码围栏；
- 字数处于平台目标篇幅的合理容差内；
- 不包含系统提示词、内部字段名或运行信息；
- 当前项目、平台和运行状态仍允许写入。

校验失败时任务返回明确错误并保持原正文不变，不自动发起修复或重试调用。用户可检查输入后主动重试。

## 8. 落库与版本

首次生成成功后在一个事务中完成：

1. 保存 `generation_runs` 的成功状态、模型、Token、资料包摘要和正文输出。
2. 创建 `PLATFORM_COPY` 产物索引，状态直接为 `ACCEPTED`，用于版本追溯。
3. 创建新的 `platform_content_versions` 版本并写入标题、正文和父版本关系。
4. 更新项目快照中当前平台的正式正文、版本号、`DRAFT` 状态和更新时间。
5. 更新项目/渠道制作状态，使用户可以继续确认正文并进入配图。

首次生成没有“尚未采用的候选”。刷新页面后必须恢复刚生成的完整正文。

现有历史候选继续保留审计状态，不自动采用或删除。用户当前宇树科技候选应在新链路上线后废弃并重新生成，避免把旧流程生成的低质量内容写入正式正文。

## 9. 已有正文的主动修改

润色、重构、扩写、压缩、局部修改和平台适配属于用户主动发起的新任务，与首次生成不同：

- 输入必须包含当前正式正文、用户明确要求、当前选区、写作资料包和父版本 ID。
- 每次用户操作只调用一次模型，不自动审稿或重写。
- 输出为修改后的完整正文和程序生成的版本差异。
- 结果先保存为候选，用户查看“修改后正文/段落差异”并选择“采用修改”或“放弃修改”。
- 候选弹窗不得显示 AI 自审问题，也不得以 `NEEDS_REVIEW` 禁用采用按钮。
- 采用后创建新正式版本；放弃后保持原正文不变。

## 10. 审核、配图与发布边界

正文生成成功不自动进入 AI 审核。用户确认正文后按渠道进入配图和排版。

当前“审核”阶段只汇总可确定的发布准备状态：正文是否存在、封面和正文图片是否齐备、排版稿是否生成、链接是否有效、用户是否已处理研究阶段留下的风险。它不自动重写正文，也不让另一个模型在用户不可见的循环中反复否定写作模型。

未来若增加内容审核模型，必须是用户主动触发、单独计费、只给建议且不改正文的可选能力，不属于首次生成链路。

## 11. 页面行为

### 11.1 空正文

- 主按钮：“生成正文”。
- 点击后显示单一运行状态，不弹确认卡或候选审核。
- 成功后正文直接填入编辑器并显示“已自动保存”。
- 失败时正文保持原状，并显示可行动的中文错误。

### 11.2 已有正文

- 编辑器始终展示当前正式版本。
- 右侧提供润色、重构、扩写、压缩和修改选区等主动动作。
- 修改任务完成后才打开差异候选，底部操作为“放弃修改”和“采用修改”。

### 11.3 删除旧界面语义

首次生成路径不再出现：

- “审核文案”；
- “正文需重写”；
- “发布前核验”；
- “需先重写”；
- “正式文稿尚未改变”；
- “查看并采用”。

这些文字不能以隐藏状态继续控制首次生成流程。

## 12. 错误边界与用量

- 输入不足在调用前阻止，不产生 Token 消耗。
- 模型或网络失败只记录一次失败调用，不自动重试。
- 技术校验失败记录模型原始响应的受限诊断，不把原始内容直接显示在页面。
- 首次生成一次成功运行只能对应一次正文模型用量；调用日志不得出现同一正文任务的声音修正、质量审稿或自动重写子调用。
- 用户主动修改属于新的明确任务和新的单次用量，不能由后台自动触发。

## 13. 数据兼容

- 保留现有 `qualityReview` 字段以读取历史产物，但新生成和新修改不再写入该字段。
- 服务端采用接口不再读取 `qualityReview.status` 作为候选采用门禁。
- 历史 `NEEDS_REVIEW` 候选仍按原状态展示为历史记录，不自动迁移为正式正文。
- 当前正式正文、版本历史、项目资料和已采用研究结果不做破坏性迁移。

## 14. 验收标准

1. 空正文点击一次“生成正文”只产生一次正文模型调用。
2. 成功后完整正文直接出现在编辑器，刷新后仍存在，不出现候选审核弹窗。
3. 首次生成的 Worker 路径不调用质量审稿、声音修正、自动重写或复审。
4. 公众号正文只使用写作资料包中的顶层已核验事实，不读取证据 quote 中的旁支事实。
5. 外部事实型项目没有足够已核验事实时在调用前阻止，调用日志不增加模型用量。
6. 用户观点型内容可以使用用户原创材料直接生成，不被强制要求外部研究。
7. 新生成正文的用户可见结果只有标题和正文，不展示内部核验、审稿或质量问题。
8. 用户主动修改已有正文时保留候选差异和采用控制，但一次操作仍只调用一次模型。
9. `NEEDS_REVIEW` 不再阻止新修改候选被用户采用；发布准备检查与正文生成完全分离。
10. 四个平台分别满足目标篇幅、内容结构和渠道表达规则。
11. 调用日志能够证明每次首次生成只有一个 `PROJECT_COPY` 模型调用。
12. 全量自动测试、类型检查、生产构建和创作工作台端到端回归通过。

## 15. 实施范围

本次只重构正文生成与主动修改链路：写作资料包、单次 Agent 调用、直接版本落库、候选差异和页面状态。不会顺带重做研究界面、配图生成、排版模板、账号授权或发布中心。
