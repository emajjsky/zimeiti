# AI 热点分析设计

> 状态：设计已确认，待实施
> 日期：2026-07-26
> 范围：阶段 1 的“单条情报 → AI 分析 → 创建选题”闭环

## 1. 目标

第一版只解决一个决策：一条已进入热点池的资讯，是否值得当前账号继续做成内容。

分析必须结合工作空间的题材定位、目标受众和用户勾选的平台。结果用于辅助判断和预填选题，不自动立项，不自动创建内容项目。

## 2. 第一版范围

### 包含

- 单条资讯分析。
- 用户勾选公众号、小红书、视频号，可单选或多选。
- 五维结构化评分、综合分和建议状态。
- 最多三个选题角度。
- 各勾选平台的独立适配建议。
- 待核验事实和风险提示。
- 执行前确认卡、模型 Scope、提示词版本和调用记录。
- 用户可见、可编辑、可恢复默认的任务提示词。

### 不包含

- 多条资讯聚类和事件时间线。
- 多 Agent 交叉评审。
- AI 自动创建选题或项目。
- 自动搜索补充来源和自动事实核验。
- 批量分析整个热点池。
- 为尚未接入执行器的任务展示可保存的假提示词功能。

## 3. 产品决策

采用“结构化评分卡 + 简短自然语言结论”。一次模型调用返回固定结构，服务端校验后持久化。自由分析报告不作为正式数据，多 Agent 评审留到后续阶段。

### 3.1 五个评分维度

| 维度 | 权重 | 定义 |
| --- | ---: | --- |
| 时效性 | 20 | 是否正在发生、是否已过时、可跟进窗口有多长 |
| 账号匹配度 | 25 | 与工作空间题材、定位、目标受众的相关程度 |
| 内容价值 | 25 | 信息增量、解释空间、实用价值和观点形成空间 |
| 传播潜力 | 15 | 讨论度、情绪点、冲突点、利益相关性和收藏价值 |
| 可执行与风险控制 | 15 | 来源完整度、素材可得性、制作难度、争议与合规风险；分数越高越容易安全执行 |

每个维度由模型返回 `0-100` 分和一句理由。综合分由服务端按固定权重计算，模型不得直接决定综合分。

建议状态由服务端确定：

- `FOLLOW`：综合分大于等于 75，建议跟进。
- `WATCH`：综合分 55-74，继续观察或补充来源。
- `SKIP`：综合分低于 55，暂不建议。

平台适配分独立展示，不计入综合分。

## 4. 输入与输出

### 4.1 输入快照

- 资讯 ID、标题、摘要、原文 URL、来源、发布时间、题材和关键词。
- 工作空间主要题材、账号定位说明和目标受众。
- 用户本次勾选的平台。
- 当前 `INTELLIGENCE_ANALYSIS` 模型策略。
- 当前热点分析提示词版本。

第一版在“设置 → 工作空间”补充两个简短字段：`账号定位` 和 `目标受众`。已有主要题材继续复用。栏目体系尚未正式实现时不新增假栏目对象；后续可把已选择栏目作为额外上下文。

主要题材至少需要一项。账号定位或目标受众为空时仍可执行，但确认卡必须提示“将按通用受众分析”，不得假装已经完成个性化匹配。

### 4.2 结构化结果

```json
{
  "decisionReason": "一句话判断",
  "timingWindow": "TODAY | THREE_DAYS | ONE_WEEK | EVERGREEN",
  "dimensions": {
    "timeliness": { "score": 0, "reason": "" },
    "accountFit": { "score": 0, "reason": "" },
    "contentValue": { "score": 0, "reason": "" },
    "spreadPotential": { "score": 0, "reason": "" },
    "feasibilityAndSafety": { "score": 0, "reason": "" }
  },
  "angles": [
    { "title": "", "coreViewpoint": "", "targetAudience": "" }
  ],
  "platforms": [
    { "platform": "WECHAT", "fitScore": 0, "recommendedFormat": "", "reason": "" }
  ],
  "factsToVerify": [],
  "risks": []
}
```

服务端约束：角度最多 3 个，待核验事实和风险各最多 5 个；平台结果必须与用户勾选的平台完全一致；所有分数限制为 `0-100`。

服务端补充 `overallScore`、`decision`、模型、提示词版本和分析时间后保存正式结果。

## 5. 提示词模板

入口：`设置 → 模型与 API → 提示词模板`。

提示词分三层：

1. 固定系统约束：来源边界、安全合规、禁止编造、JSON Schema 和字段上限，不允许用户编辑。
2. 工作空间任务模板：用户可见、可编辑，可调整分析重点、评分偏好和补充规则。
3. 运行上下文：服务端注入本次资讯、账号定位、目标受众和平台，不作为模板内容持久化。

热点分析模板支持查看默认值、编辑保存、恢复默认、版本号、修改时间和可用变量说明。第一版变量白名单：

- `{{title}}`
- `{{summary}}`
- `{{source}}`
- `{{publishedAt}}`
- `{{category}}`
- `{{keywords}}`
- `{{primaryTopics}}`
- `{{accountPositioning}}`
- `{{targetAudience}}`
- `{{platforms}}`

未知变量拒绝保存，模板正文最大 12,000 字符。每次保存或恢复默认都创建新版本；历史运行继续引用原版本，不被覆盖。

第一轮只开放已接入执行器的“热点分析”模板。其它 Scope 在执行器接入时再启用，不显示可操作的空壳编辑器。

## 6. 用户流程与页面

```text
打开热点详情
→ 点击“AI 分析”
→ 勾选目标平台
→ 查看确认卡
→ 确认执行
→ 查看运行状态
→ 展示结构化结果
→ 选择角度并创建选题，或关闭详情
```

确认卡显示：任务目的、来源数、勾选平台、执行模型、提示词版本、预估用量/费用和将写入的资产。供应商没有公开价格时显示“费用暂不可估”，不得显示虚假的 0 元。取消确认不得调用模型。

结果继续放在现有热点详情抽屉，不新增一级页面：

- 顶部：综合分、建议状态、时效窗口和一句话判断。
- 评分依据：五条紧凑评分条和一句理由。
- 选题建议：最多三个角度，用户选择一个。
- 平台建议：仅显示勾选平台的适配分、推荐形式和理由。
- 风险提示：有内容时才显示待核验事实和风险，不渲染空模块。

“创建选题”预填原始资讯、来源、选中角度、推荐受众、主平台/联动平台和待核验清单。AI 分析不会自动改变热点的立项状态。

## 7. 数据边界

新增领域数据：

- `prompt_template_versions`：工作空间、Scope、版本、模板正文、来源（默认/自定义）、创建时间。
- `intelligence_analyses`：工作空间、资讯、运行记录、选择平台、结构化结果、综合分、建议状态和创建时间。

复用：

- `agent_model_policies` / 当前任务策略：确定 `INTELLIGENCE_ANALYSIS` 的真实模型。
- `generation_runs`：保存不可变输入快照、输出、模型、提示词版本、用量、状态和错误。
- 当前调用记录：展示模型、Token、耗时和结果，并补充提示词版本。

热点详情默认读取最新一条成功分析。失败和取消记录保留在运行记录中，不覆盖上次成功结果。

## 8. API 与执行

建议接口：

- `GET /api/v1/settings/prompt-templates/INTELLIGENCE_ANALYSIS`
- `PUT /api/v1/settings/prompt-templates/INTELLIGENCE_ANALYSIS`
- `POST /api/v1/settings/prompt-templates/INTELLIGENCE_ANALYSIS/reset`
- `POST /api/v1/intelligence/items/:id/analyses/prepare`
- `POST /api/v1/generation-runs/:id/confirm`
- `POST /api/v1/generation-runs/:id/cancel`
- `GET /api/v1/intelligence/items/:id/analyses/latest`

`prepare` 校验资讯、平台、模型策略、凭据和模板，创建 `DRAFT` 运行并返回确认卡。`confirm` 才进入队列并返回任务 ID，前端复用现有任务状态查询。Worker 通过任务策略调用真实文本模型；不得硬编码模型名。

模型输出先做 JSON 提取和 Schema 校验。首次结构错误时允许同一模型进行一次结构修复；仍失败则标记运行失败，不保存正式分析。

## 9. 失败与安全

- 未配置热点分析模型：阻止准备任务，并提供“前往任务策略”。
- 百炼或外部连接不可用：显示服务端真实错误，浏览器不接触 Key。
- 资讯缺少标题、摘要或来源 URL：阻止执行并说明缺失项。
- 网络超时或模型失败：保留失败运行，允许重新分析。
- 输出结构错误：只重试一次结构修复，不以空字段伪造成功。
- 工作空间隔离：模板、策略、运行和分析查询都必须带 `workspace_id`。
- 固定系统约束和 Schema 不向用户开放编辑，避免破坏审计与解析协议。

## 10. 测试与验收

### 自动化

- 提示词查看、保存、恢复默认、版本递增、未知变量和长度校验。
- 两个工作空间之间模板、模型策略、运行和分析不可交叉访问。
- 没有模型策略、无效凭据、缺少资讯字段时不进入模型调用。
- 五维分数边界、服务端权重计算和三档建议状态。
- 用户勾选平台与模型返回平台严格一致。
- 结构错误触发一次修复；二次失败不保存正式结果。
- 成功、失败、取消均创建正确运行记录；失败不覆盖上次成功结果。
- 创建选题预填角度、平台和待核验清单。

### 真实验收

1. 用户在任务策略为热点分析选择一个真实可用文本模型。
2. 用户查看并修改热点分析提示词，确认版本递增。
3. 选择一条真实 RSS 或公众号资讯，勾选至少两个平台。
4. 确认卡中的模型、模板版本、平台和来源正确。
5. 确认执行后得到五维评分、综合结论、角度、平台建议和待核验项。
6. 调用记录显示真实模型、Token、耗时、状态和模板版本。
7. 选择一个角度创建选题，预填内容正确，热点出现“已立项”。

## 11. 实施顺序

1. 数据迁移、领域类型和结构校验。
2. 提示词模板服务与设置页。
3. 分析准备、确认、取消和 Worker 执行链路。
4. 热点详情结果展示和创建选题预填。
5. 自动化测试、真实模型验收和四份主文档更新。
