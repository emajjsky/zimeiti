# 创作项目中心列表布局设计

> 日期：2026-07-28  
> 状态：待用户书面确认  
> 范围：只调整“创作”项目中心的项目浏览布局，不改变统一项目领域、七步流程或 API

## 1. 目标

将旧规划页中更适合快速扫读的“左侧列表 + 右侧详情”布局搬到当前“创作”项目中心。规划仍然是创作第一步，正式业务对象仍然是 `ContentProject`；不得恢复独立规划导航、旧 `TopicCandidate` 状态机或“确认立项后再创建项目”的旧链路。

## 2. 页面结构

### 2.1 顶部区域

- 保留页面标题“创作”、真实项目数量和“新建创作”。
- 保留阶段筛选：全部、待规划、研究中、正文中、制作中、待审核、已完成。
- 新建表单继续支持手工想法、已有草稿、导入内容及目标平台，不改变现有创建行为。

### 2.2 桌面项目区

项目区使用两栏：

- 左侧为可选择的紧凑项目列表，占主要宽度。
- 右侧为当前选中项目详情，使用稳定宽度并在页面滚动时保持可见。

列表列固定为：

1. 项目：标题，必要时在第二行显示核心表达摘要。
2. 题材：读取 `project.planning.category`，为空显示“未分类”。
3. 目标平台：读取 `project.planning.targetPlatforms`，显示平台短标签。
4. 来源：读取 `project.originType`，显示热点、手工想法、已有草稿、导入内容或历史项目。
5. 阶段：读取 `project.stage`，显示待规划、研究中、正文中、平台制作中、配图中、排版中、待审核或已完成。
6. 更新时间：格式化 `project.updatedAt`。

整行可点击。键盘焦点、悬停和选中状态必须清晰；列表不再使用大面积卡片、顶部彩条或大段留白。

### 2.3 右侧项目详情

右侧只显示真实项目数据：

- 项目标题、题材、来源和当前阶段。
- 创作角度。
- 创作目标。
- 目标受众。
- 核心表达。
- 来源与核验要求。
- 目标平台。
- 计划发布时间；未填写时显示“未安排”。

底部只保留一个主动作，根据阶段显示：完成规划、继续研究、继续正文、制作平台版本、处理配图、继续排版、完成审核或查看项目。点击后进入当前项目对应阶段。

项目中心不提供删除按钮。本轮不新增项目删除 API，避免用旧规划页的删除行为误删统一项目及其素材、消息和版本。

## 3. 状态行为

- 默认选中当前筛选结果的第一项。
- 切换筛选后，若当前选中项目仍在结果中则保持；否则选择新结果第一项。
- 项目数据刷新、创建项目或热点加入后，选择状态必须指向仍存在的真实项目。
- 空工作空间继续显示“还没有内容项目”和“新建第一篇内容”。
- 某个筛选没有项目时显示“这个阶段还没有项目”，不保留右侧旧项目详情。
- 新建创作成功后直接进入该项目规划工作台，行为不变。

## 4. 响应式设计

- 大于 1100px：左侧列表 + 右侧详情。
- 790px 至 1100px：列表占满宽度；点击项目后在列表下方显示详情，不挤压表格。
- 小于 790px：不渲染横向表格，改为紧凑项目行；每行显示标题、阶段、来源、平台和下一步。点击后使用底部详情抽屉。
- 390px 下不得出现横向滚动；按钮、筛选和平台标签允许自身横向滚动，但不能扩大文档宽度。

## 5. 视觉规则

- 延续当前波普怀旧清新风格和现有字体、按钮、马卡龙状态色。
- `DESIGN_VARIANCE 4 / MOTION_INTENSITY 2 / VISUAL_DENSITY 7`。
- 项目区以分隔线和行选中状态建立层级，不使用悬浮大卡片阴影。
- 马卡龙色只用于来源、阶段和平台标签；正文背景保持白色或现有纸张底色。
- 行切换只使用 CSS 颜色和 1-2px 位移动效，不增加 Anime.js 时间线。

## 6. 数据与组件边界

- 继续使用 `CreativeProjectCenter` 的现有输入：`projects`、`onOpenProject`、`onCreateProject`。
- 将项目筛选、默认选择和下一步文案提取为可测试的纯函数；不为 UI 新增服务端接口。
- `onOpenProject(project)` 仍由 `main.tsx` 根据 `project.stage` 打开正确阶段。
- 不修改 `ContentProject`、规划 API、热点加入、今天、复盘或七步工作台。

## 7. 验收条件

自动化必须覆盖：

1. 阶段筛选返回正确项目。
2. 默认选择第一项，筛选后不会保留不可见项目。
3. 列表和详情都读取真实 `ContentProject` 字段。
4. 下一步动作与项目阶段一一对应。
5. 新建创作、规划保存/确认、热点加入和刷新恢复原 E2E 不回归。
6. 浏览器验证桌面左右布局、1024px 上下布局和 390px 紧凑行/详情抽屉，无横向溢出。
7. 页面不出现旧“选题池、确认立项、已立项、Topic”业务文案。

## 8. 非目标

- 不恢复独立规划页面或一级导航。
- 不恢复旧选题详情与删除动作。
- 不修改规划表单字段和七步创作工作台。
- 不新增项目排序、批量操作、拖拽、搜索、分页或虚拟列表。
- 不调用模型、检索或其它付费接口。
