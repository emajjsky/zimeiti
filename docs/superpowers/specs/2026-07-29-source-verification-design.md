# 来源筛选与事实核验设计

## 目标

把已经保存的研究来源变成可审阅、可追溯的研究结论。来源未经用户选择和模型核验前，不得进入正文事实上下文。

## 产品链路

1. 来源结果展示标题、摘要、来源类型、语言、发布时间、相关度和原链接。
2. 系统依据相关度、官方或一手来源属性生成默认推荐选择，用户可以逐条勾选、全选或清空。
3. 用户点击“准备事实核验”时，前端提交明确的来源 ID 集合。
4. prepare 只冻结研究计划、待核验主张和已选来源，并展示模型、来源数量和写入范围，不消耗模型额度。
5. 用户点击“确认调用”后，Worker 才调用 `SOURCE_VERIFICATION` Scope 指定的文本模型。
6. 模型输出逐条主张的支持、冲突和引用关系。引用必须来自已选来源摘要，来源 ID 必须属于本次快照。
7. 结果状态仅允许 `VERIFIED`、`SINGLE_SOURCE`、`CONFLICTING`、`NEEDS_REVIEW`。
8. 核验产物保持候选状态。用户点击“确认研究结论”后才成为正式研究上下文；未确认或待复核结论不能进入正文。

## 数据边界

- `project_research_sources` 保存来源质量元数据与用户选择状态。
- `generation_runs` 继续承载 prepare、confirm、queue、running、success 和 failed 状态。
- 新增 `project_source_verifications` 保存核验运行和结构化输出。
- `project_artifacts` 新增 `RESEARCH_VERIFICATION` 类型，预览结构化核验结果。
- 模型只接收所选来源的标题、摘要、URL、来源类型和检索时间，不接收未选来源。

## 模型契约

- 新增文本任务 Scope `SOURCE_VERIFICATION`，在“模型与 API > 任务策略”中配置。
- 输出必须是严格 JSON，每条证据包含 `sourceId`、关系、原文引用和说明。
- 服务端校验来源 ID、主张、状态和引用。引用无法在来源摘要中定位时，输出无效并触发一次修复请求。
- 模型不能把单一来源包装成多源核验，也不能把没有证据的判断标记为 `VERIFIED`。

## 界面

- 延续现有高密度工作台，不新增一级页面。
- 来源预览使用紧凑列表，不再增加说明卡片。
- 来源行左侧为复选框，中间为标题与摘要，右侧为来源质量元数据和原链接。
- 底部只保留“关闭”和“准备事实核验”两个主操作，批量选择放在列表工具条。
- 事实核验结果按主张分组，状态、解释和证据链接同屏可见。

## 错误与质量门

- 没有可用来源、没有勾选来源、没有配置 `SOURCE_VERIFICATION` 模型时，prepare 返回明确错误。
- 来源任务仍在执行时不能开始核验。
- 模型失败或结构校验失败时保留来源选择，不生成伪造结论。
- `CONFLICTING` 和 `NEEDS_REVIEW` 不能在确认后变成已核验事实，只能作为待核验项传给后续正文阶段。

## 验收

- 刷新后来源质量字段和选择状态仍存在。
- prepare 前无模型调用日志；confirm 后出现一条 `SOURCE_VERIFICATION` 日志。
- 未选来源不出现在冻结快照和核验结果中。
- 证据链接可打开，引用能在对应来源摘要中定位。
- 用户确认研究结论后，研究产物显示“已确认”；取消确认前正文阶段不能消费该结果。
