# 研究阶段单入口与对话成果设计

**日期：** 2026-07-28
**状态：** 已确认，待实施计划
**范围：** 规划立项到资料研究，再到文案阶段的衔接

## 1. 目标

新用户从规划阶段确认立项后，进入创作项目不再重复填写选题标题，也不需要先理解资料类型、勾选资料或学习研究指令。研究阶段只提供一个快捷入口“开始研究”，后续通过项目 Agent 对话持续修订；每次执行生成候选成果，只有用户明确保存后才成为正式研究成果并推进到文案阶段。

## 2. 产品原则

- 选题标题只在规划阶段确定。创作页继承项目标题，不在资料弹窗和研究动作中要求用户再次确定。
- 页面只暴露一个研究快捷入口，不堆叠“制定计划、事实核验、内容缺口”等并列选项。
- 项目上下文是研究的最低输入。草稿、想法、链接和文件是可选增强，不是启动门槛。
- 对话用于修改研究方向和成果，不替代正式资产。每次执行先产生候选版本，保存后才更新正式研究成果。
- 研究计划是内部执行过程，不代表研究完成。项目进度使用“研究成果”，不能仅因生成计划而完成。
- 未核验事实可以保留在研究成果中，但必须保持待核验状态，后续审核与发布继续阻断。
- 页面不增加教程段落、功能说明、示例墙或多个快捷问题。

## 3. 新用户主路径

1. 用户在规划页确认选题并立项，系统创建内容项目，冻结选题标题、选中角度、核心观点、关联资讯和初始待核验项。
2. 用户进入“项目概览”，补充创作目标、目标受众、核心表达和目标平台。
3. 用户进入“资料与研究”。左侧可选地添加自己的想法、草稿、参考链接或素材文件；右侧 Agent 即使没有附加资料也可以启动。
4. Agent 空状态只显示当前项目已就绪状态和一个主按钮“开始研究”。
5. 用户点击“开始研究”，系统用固定意图创建受控研究请求：基于当前项目上下文，确定研究问题、来源范围和证据缺口。prepare 阶段不调用模型，仍显示调用确认卡。
6. 用户确认后，Agent 执行研究计划及允许的来源动作，形成研究成果候选。遇到登录、验证码、付费墙、权限不明或需要用户账号的来源时停止，并请求人工处理。
7. 用户继续通过对话提出修改，例如调整研究重点、补充国内案例、删除无关视角或重新核验某项数据。每次确认执行后创建新的研究成果候选，不覆盖正式成果。
8. 用户查看候选，只保留“继续修改”和“保存研究成果”两个主要去向。
9. 用户保存后，候选成为正式研究成果，项目进度更新并开放文案阶段。文案 Agent 默认继承该正式成果及其来源、证据和待核验项。

## 4. 页面设计

### 4.1 项目标题

- 创作页顶部继续显示规划阶段冻结的项目标题。
- 项目概览允许编辑创作目标和核心表达，但不提供第二个选题标题字段。
- 平台文案标题属于文案版本，可以由 Agent 生成或人工修改，不反向覆盖项目选题标题。

### 4.2 左侧资料区

- “新增内容”改为“添加草稿或想法”。
- “新增项目内容”弹窗改为“添加草稿或想法”。
- 输入内容的“标题”改为“资料名称”。新建时资料名称非必填，保存时按以下顺序自动生成：正文第一行、内容类型加创建时间。
- 参考链接的名称优先使用读取到的网页标题；读取前允许按域名或链接生成临时名称。
- 上传文件的名称默认使用原始文件名。
- “已选 0 条给 Agent”改为“使用项目上下文”；存在选择时显示“附加 N 条资料”。
- 清空附加资料只清除本次 Agent 输入，不删除资料资产。

### 4.3 右侧 Agent 空状态

空状态不显示“还没有对话”，不显示多个快捷任务，只渲染：

```text
当前选题已就绪
[ 开始研究 ]
```

按钮使用现有主操作样式。点击后直接准备固定研究请求，不要求用户先在输入框中组织第一句话。输入框继续保留，用于用户从一开始就有明确要求时直接发送。

### 4.4 对话与成果

- 对话时间线继续显示用户请求、调用确认、运行状态、候选产物和系统事件。
- 候选卡只显示成果摘要、来源数量、已核验主张数、待核验项数和更新时间，不在消息卡中塞入完整长文。
- “查看成果”打开研究成果审阅层，显示研究结论、证据主张、来源快照和待核验项。
- 对话修订默认基于最新研究成果候选；如果已有正式成果，则同时冻结正式版本 ID，避免并发覆盖。
- 用户保存候选后写入正式研究成果，并记录采用事件。未保存候选不推进项目进度。

## 5. 受控动作与资产

界面只显示一个“开始研究”，后台使用以下受控动作完成真实工作：

- `START_RESEARCH`：根据项目上下文建立研究目标和问题。
- `SEARCH_WEB`：按明确查询和允许域名搜索公开来源。
- `READ_LINK`：读取公开链接并保存来源快照；遇到受限页面转人工处理。
- `REVISE_RESEARCH`：根据用户对话修订研究方向或研究成果。
- `FINALIZE_RESEARCH`：汇总证据、结论、冲突和待核验项，生成研究成果候选。

正式领域资产至少包含：

- `research_runs`：每次受控执行及其冻结上下文。
- `source_snapshots`：URL、来源名称、标题、抓取时间、正文摘要、内容哈希和读取状态。
- `evidence_claims`：主张、证据引用、支持/反驳关系、核验状态和置信说明。
- `research_report_versions`：研究成果候选与正式版本、父版本、摘要、结论、待核验项和来源引用。
- `project_artifacts`：为研究计划和研究成果提供通用候选、采用和废弃状态。

研究计划可以作为运行中间产物保存，但不计入用户进度。只有已保存的 `RESEARCH_REPORT` 推进“研究成果”。

## 6. 上下文与数据流

研究请求冻结以下内容：

- 项目标题、选中角度、核心观点、目标受众和待核验项。
- 关联热点及其分析快照。
- Writing Brief 中与研究有关的目标、受众、核心表达和来源要求。
- 用户本次附加的输入、参考链接和文件 ID。
- 当前正式研究成果版本、最近候选版本和必要的阶段摘要。
- 动作版本、提示词版本、模型路由和执行范围。

数据流固定为：

```text
规划立项
  -> 项目上下文
  -> 开始研究 / 自由对话
  -> prepare 确认卡
  -> 用户确认
  -> 受控来源与研究动作
  -> 研究成果候选
  -> 对话修订或保存
  -> 正式研究成果
  -> 文案阶段继承
```

## 7. 保存与进入下一步

- “保存研究成果”是显式采用操作，不是普通表单自动保存。
- 保存事务同时完成：采用候选、废弃同项目旧候选、更新研究阶段摘要、记录系统事件、更新项目进度。
- 文案阶段只读取最新正式研究成果，不读取未保存候选。
- 保存时存在待核验项不阻止进入文案，但这些项目必须随正文版本继续传递，并在最终审核和发布前阻断。
- 正式研究成果保存后再次研究会创建新候选。新候选采用前，文案继续绑定原正式版本；采用后，已有文案标记为“研究已更新”，由用户决定是否让 Agent 同步修订。

## 8. 错误与人工边界

- 未配置研究模型：点击开始后返回可操作错误，并跳转任务策略设置，不创建假结果。
- 未配置检索 API：允许先形成研究问题，但执行网络搜索前明确提示配置检索 API。
- 没有附加资料：正常启动，不显示错误。
- 链接无法读取：保存失败原因和读取状态，不把链接元数据当作正文证据。
- 登录、验证码、付费墙、平台风控或权限不明：停止自动动作，创建 `HUMAN_INPUT_REQUIRED`，不尝试绕过。
- 结构化输出失败：仅允许一次结构修复；仍失败则保留真实错误并允许用户重试。
- 候选保存冲突：检测正式版本 ID；若已被其它操作更新，要求刷新后重新比较，禁止静默覆盖。

## 9. 验收标准

- 从规划立项进入创作，项目标题完整继承，资料弹窗不再出现容易误解为选题标题的必填项。
- 零附加资料时“开始研究”和自由输入均可用。
- Agent 空状态只有一个快捷主按钮，没有并列任务选项和冗余说明。
- 点击“开始研究”只创建确认卡，确认前不调用模型或检索 API。
- 每次对话修订产生新候选；刷新后消息、运行、候选和正式成果均可恢复。
- 未保存候选不完成研究进度，也不改变文案阶段读取的研究版本。
- 保存研究成果后进度更新并开放文案；文案上下文包含正式研究结论、来源引用和待核验项。
- 无资料、模型缺失、检索 Key 缺失、来源受限、执行失败和版本冲突都有真实可恢复状态。
- 桌面 1024px 和移动 390px 无横向溢出，固定按钮、确认卡和成果审阅层不遮挡内容。
- 自动化测试不调用真实付费模型或检索 API；真实调用仅通过单独人工验收。

## 10. 不在本切片实现

- 配图生成、排版、审核、内容包导出和平台发布。
- 需要登录态的公众号批量读取、社交平台自动化采集或绕过访问限制。
- 团队协作、评论、审批流和多人并发编辑界面。
- 自动替用户保存研究成果或自动覆盖已经进入文案阶段的正式资产。
