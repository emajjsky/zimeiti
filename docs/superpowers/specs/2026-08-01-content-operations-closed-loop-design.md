# 自媒体内容运营闭环设计规格

> 日期：2026-08-01  
> 状态：待用户书面审阅  
> 目标版本：真实可用 MVP  
> 适用范围：Web 内容引擎；公众号、小红书、知乎、微博

## 1. 背景与目标

当前系统已经具备邮箱注册登录、内容项目、研究、四平台正文、配图、排版稿和审核等基础能力，但工作空间仍被服务端隐式选取，素材停留在项目级，发布账号、发布记录、数据和复盘尚未形成真实业务对象。发布中心、账号授权和全局素材库中的占位内容不能继续作为产品能力存在。

本次目标是把产品收敛为一个自媒体人可以真实使用的最小闭环：

```text
注册登录
  → 选择工作空间
  → 管理素材与发布账号
  → 创建内容项目
  → 按平台完成内容包
  → 排期并发布
  → 回填或同步数据
  → 形成复盘结论和下一步行动
```

本设计必须同时解决此前数据消失事故暴露出的根因：任何业务请求都不能再默认选择“第一个工作空间”，任何页面也不能再通过整份状态覆盖写入其它领域数据。

## 2. 产品原则

1. **真实能力优先。** 未完成真实 OAuth、官方 API 校验和发布回执前，不显示“已授权”“已发布”或“同步成功”。
2. **空间显式隔离。** 当前工作空间必须由客户端显式携带，服务端逐次校验成员关系，不允许隐式回退到首个空间。
3. **领域数据独立。** 项目、素材、账号、发布记录、指标和复盘分别使用正式领域表与专用接口，不再写入整份工作空间快照。
4. **素材只存一份。** 空间素材是文件的唯一业务所有者，项目只建立引用；解除项目引用不得删除文件。
5. **渠道规则真实。** 四个平台使用独立交付状态机，不把公众号流程复制到小红书或微博。
6. **操作可见可追溯。** 模型任务策略、发布方式、同步来源、失败原因和人工确认均可见，不设置隐藏任务策略或静默兜底。
7. **先闭环再扩展。** MVP 先完成单用户多空间、四平台人工发布闭环；团队邀请、复杂审批和不确定的第三方自动化不进入本期。

## 3. 范围与非目标

### 3.1 本期范围

- 保留并完善现有邮箱注册、登录和会话。
- 一个用户可创建、切换、重命名和删除多个工作空间。
- 建立空间级素材库，支持上传、预存、预览、删除和跨项目复用。
- 修正公众号、小红书、知乎、微博的交付步骤和图片数量上限。
- 建立发布账号管理，明确账号的真实连接方式与能力。
- 建立排期、发布记录、发布回执、指标快照和复盘记录。
- 用人工发布和人工数据回填跑通所有平台；仅在平台官方能力真实可用时接入 OAuth/API。
- 删除发布中心、账号授权和素材库中的硬编码演示数据与虚假状态。

### 3.2 本期非目标

- 不做团队邀请、成员管理 UI、评论和多人审批；数据库既有角色继续用于授权边界。
- 不通过上传 Cookie、模拟登录、绕过验证码或控制用户浏览器后台来冒充官方发布能力。
- 不承诺四个平台均可自动发布或自动同步数据。
- 不做视频号、抖音、B 站等新平台。
- 不做跨空间共享素材；跨空间复用必须显式复制成目标空间的新素材。
- 不做复杂 BI、竞品监控、粉丝画像或收益结算。
- 不重建研究、正文生成和图片生成管线；本期只修正渠道流程、配图约束、关键词质量和预览交互。

## 4. 分阶段交付

### 4.1 阶段 A：空间与素材底座

完成多空间请求上下文、空间创建/切换/删除、空间级素材库和现有项目文件迁移。阶段 A 通过前，不进入发布闭环开发。

### 4.2 阶段 B：四平台正确交付链路

统一渠道能力配置和状态机，修正小红书、微博的错误排版步骤，落实图片上限、预览和审核规则。阶段 B 通过前，不把内容标记为可发布。

### 4.3 阶段 C：账号、发布、数据与复盘

完成发布账号、排期、人工或官方发布、发布记录、指标快照和复盘。MVP 的最终验收是至少一条真实内容完成“内容包 → 发布回执 → 数据 → 复盘”。

三个阶段依次实施，每个阶段独立迁移、测试和验收，不并行修改同一领域，不保留双写分支。

## 5. 用户、会话与工作空间

### 5.1 用户与注册登录

现有邮箱注册和密码登录继续作为 MVP 唯一身份入口。邮箱在写入和登录时统一去除首尾空白并转为小写，保持唯一约束；密码只保存安全哈希。注册成功时可以同时创建首个工作空间，也允许账号处于“暂无工作空间”状态后进入创建页。

本期不要求邮箱验证码、找回密码和第三方登录，但接口与页面不得把这些能力显示为已支持。

### 5.2 工作空间定义

工作空间是用户内容运营数据的一级隔离单元。以下对象全部归属于且只能归属于一个工作空间：

- 内容项目及项目资料；
- 空间素材与项目素材引用；
- 资讯来源、情报、模型凭据和任务策略；
- 账号声音和发布账号；
- 排期、发布记录、指标快照和复盘。

一个用户可以拥有多个工作空间。例如“个人账号”“公司品牌”和“客户 A”应分别建空间；不同空间的数据不会自动合并或互相可见。

### 5.3 显式请求上下文

除身份接口和工作空间管理接口外，所有空间内业务请求必须携带 `X-Workspace-Id`。前端 API 客户端从当前选择中统一注入该请求头；服务端的工作空间上下文中间件完成以下校验：

1. 请求头存在且为合法 UUID；
2. 工作空间存在且未处于删除中；
3. 当前用户是该空间成员；
4. 当前接口允许该成员角色执行请求动作。

校验成功后，中间件只向后续服务暴露 `request.workspace.id`、`request.workspace.role` 和 `request.user.id`。领域服务不得再次查询或猜测“当前空间”，并彻底删除 `currentWorkspace()` 按排序取第一条记录的逻辑。

客户端把最后使用空间写入服务端用户偏好。登录后优先恢复仍有权限的最后使用空间；若不存在，则显示空间选择页；若用户没有空间，则显示创建空间页。客户端缓存只能用于加快显示，不能作为授权依据。

### 5.4 角色边界

沿用现有 `OWNER`、`EDITOR`、`VIEWER`：

| 动作 | OWNER | EDITOR | VIEWER |
| --- | --- | --- | --- |
| 查看空间数据 | 是 | 是 | 是 |
| 编辑项目、素材引用、发布数据 | 是 | 是 | 否 |
| 管理凭据和发布账号 | 是 | 否 | 否 |
| 重命名或删除空间 | 是 | 否 | 否 |

MVP 不提供邀请成员入口，但服务端权限必须按该表实现，避免以后开放协作时重写授权模型。

### 5.5 空间删除

只有 OWNER 可以删除空间。删除流程必须先调用影响预览接口，返回项目、素材、发布账号、发布记录、指标和复盘的数量，再要求用户输入完整空间名称确认。

删除请求在一个数据库事务中把空间标记为 `DELETING` 并写入存储删除任务；从该时刻起空间不可再读写。Worker 删除该空间独占的文件后，执行数据库级级联删除。任务失败时空间保持 `DELETING` 并向 OWNER 显示明确失败原因和重试入口，不恢复成可编辑状态，也不静默忽略文件删除失败。

允许删除最后一个空间。完成后用户仍保持登录，进入创建空间页。生产环境只有在备份策略健康且最近一次备份可验证时才开放永久删除；每次删除仍必须通过影响预览和名称确认。产品不提供“误删后自动找回”的虚假承诺。

## 6. 空间级素材库

### 6.1 领域边界

`workspace_assets` 是素材元数据与文件生命周期的唯一所有者；`project_asset_links` 只表达项目如何使用素材。项目、配图方案和发布快照都只能引用素材 ID，不能复制 `storage_key`、哈希或外链地址作为另一份事实来源。

被用户选中的网图必须先下载到私有存储、校验 MIME/大小/哈希并创建空间素材，之后才能绑定项目。AI 生图成功后同样先创建空间素材，再建立项目引用。未被选中的搜索结果只作为临时搜索结果，不写入素材库。

### 6.2 素材类型与来源

MVP 支持：

- 类型：图片、文档、音频、视频、其它文件；
- 来源：用户上传、AI 生成、网络导入；
- 状态：`ACTIVE`、`ARCHIVED`、`DELETING`；
- 版权状态：待确认、用户自有、已获授权、开放许可、禁止使用。

素材保留原始文件名、MIME、大小、SHA-256、存储键、创建人、来源 URL、来源说明、版权状态和创建时间。服务端以实际文件内容检测类型，不能只相信扩展名或浏览器提交的 MIME。

### 6.3 去重与复用

同一工作空间内以 `workspace_id + sha256` 去重。重复上传返回已有素材，并允许建立新的项目引用；不同工作空间即使哈希相同也各自拥有独立素材记录和权限边界。

项目引用包含用途、作用阶段、平台范围和排序。解除引用只删除 `project_asset_links`。删除空间素材时若仍有项目、配图或发布快照引用，接口返回 `409 ASSET_IN_USE` 及引用项目列表，用户必须先处理引用，系统不得连带破坏项目。

发布记录创建后使用不可变的发布内容快照。已发布快照引用的素材不能从存储删除；只能从素材库默认列表归档隐藏，确保历史发布记录可审计和复盘。

### 6.4 预览与文件访问

素材列表必须显示真实缩略图或类型占位，点击后打开大图/文件预览。私有文件通过短时鉴权响应或流式下载接口读取，不暴露物理路径和永久公开 URL。搜索结果、AI 生成结果和项目素材使用同一个预览组件，选中前后均可预览。

上传、网络导入和 AI 生成失败时保留明确错误，不创建空素材记录，不显示损坏缩略图为“已完成”。

## 7. 四平台交付状态机

### 7.1 渠道能力表

| 平台 | 正文 | 独立配图步骤 | 独立排版步骤 | 审核 | 图片上限 |
| --- | --- | --- | --- | --- | --- |
| 公众号 | 是 | 是 | 是 | 是 | 12 张 |
| 知乎 | 是 | 是 | 是 | 是 | 12 张 |
| 小红书 | 是 | 图文卡片 | 否 | 是 | 9 张 |
| 微博 | 是 | 否；正文/审核中可选附件 | 否 | 是 | 9 张 |

图片上限按最终交付包中的去重素材数计算，包括封面或首图。超过上限时前端禁止继续添加，服务端保存接口再次校验，不能只依赖界面控制。

### 7.2 正确流程

```text
公众号：正文 → 配图 → 排版 → 审核
知乎：正文 → 配图 → 排版 → 审核
小红书：正文 → 图文卡片 → 审核
微博：正文 → 审核
```

小红书图文卡片属于图片交付物制作，不生成公众号式 HTML/富文本排版对象。微博没有独立配图工作台；可在正文或审核中选择最多 9 张附件，发布快照保留附件顺序。

### 7.3 状态模型

渠道状态不再使用一套固定 `COPY/VISUAL/LAYOUT/REVIEW` 顺序硬套所有平台。领域层使用渠道能力表计算允许状态和下一步：

- 公众号、知乎：`COPY → VISUAL → LAYOUT → REVIEW → READY`；
- 小红书：`COPY → CARDS → REVIEW → READY`；
- 微博：`COPY → REVIEW → READY`。

不存在的步骤不能出现在导航、URL、待办和完成条件中。历史项目若保存了小红书或微博排版状态，迁移时保留已有正文和图片，不再把该排版对象作为前置条件，也不生成新的无效排版数据。

### 7.4 配图策略透明度

配图策划页必须显示本次使用的任务 Scope、模型提供方和模型名称；用户可跳转到任务策略设置。策划结果应以图片内容和构图为主、文字元素为辅，默认禁止大段 PPT 式文案堆叠。

每个配图项的搜索关键词必须来自当前正文对应段落的主体、场景、动作和视觉对象，不得只复用文章标题或抽象主题。封面词与正文词、不同正文图之间必须去重。搜索词允许用户编辑后主动搜索，不自动消耗检索额度。

网图、AI 生图和已有素材都必须在采用前提供大图预览；采用后仍可从当前配图项打开同一预览。任何生成、导入或绑定错误必须展示服务端返回的可行动原因。

## 8. 发布账号与平台能力

### 8.1 发布账号

发布账号是工作空间内的真实发布目标，包含平台、显示名称、平台账号标识、连接方式、连接状态和已验证能力。账号声音与发布账号是两个领域：前者服务写作风格，后者服务发布和数据，不得混用。

连接方式分为：

- `MANUAL`：用户在平台后台人工发布，系统保存目标账号、导出包、回执和指标；四个平台均支持。
- `OFFICIAL_API`：仅当对应平台官方接口、应用资质、用户授权和真实调用全部通过时启用。

连接状态分为 `MANUAL_READY`、`CONNECTING`、`CONNECTED`、`EXPIRED`、`ERROR`。手工账号不能显示成 OAuth 已连接；缺少官方权限时，连接按钮显示真实限制说明。

### 8.2 能力分级

每个官方连接器以运行时能力声明返回 `canPublish`、`canSchedule`、`canReadMetrics`。页面和服务端都按能力声明开放动作：

- 没有 `canPublish`：只允许导出和人工发布确认；
- 没有 `canSchedule`：排期只作为内容日历和提醒，不声称平台已定时；
- 没有 `canReadMetrics`：只允许人工数据回填；
- 连接过期：停止自动动作，保留历史记录并要求重新授权。

凭据只进入服务端加密凭据库，接口不得回传密钥、刷新令牌或 Cookie。

## 9. 发布记录、数据与复盘

### 9.1 发布记录

发布记录独立于内容项目状态。一个项目可以按不同平台、账号和时间创建多条发布记录。记录包含：

- 工作空间、项目、平台版本和目标账号；
- 不可变内容快照与素材顺序；
- 发布方式：人工或官方 API；
- 计划发布时间、实际发布时间；
- 状态：`DRAFT`、`SCHEDULED`、`PUBLISHING`、`PUBLISHED`、`FAILED`、`CANCELLED`；
- 平台内容 ID、公开 URL、失败代码和失败说明。

人工发布流程为“生成发布包 → 用户在平台发布 → 回到系统填写链接或平台内容 ID并确认”。只有完成确认后才能进入 `PUBLISHED`。官方发布只有收到平台成功响应并保存平台内容 ID 后才能进入 `PUBLISHED`。

每次状态变化写入不可变发布事件，记录操作者、时间、前后状态、方式和失败原因。项目是否完成由其目标渠道是否存在有效发布记录派生，不通过修改项目 JSON 冒充发布结果。

### 9.2 指标快照

指标按发布记录保存时间快照，不直接覆盖“当前数据”。统一字段包括曝光、阅读/播放、点赞、评论、分享、收藏、涨粉；平台没有的字段为 `null`，不能填 `0` 冒充真实值。平台特有指标放入受校验的扩展字段。

快照来源为 `MANUAL` 或 `OFFICIAL_API`。人工回填和自动同步使用同一数据结构，每次新增快照并保留历史。页面显示数据来源、采集时间和相对上一快照的变化。

### 9.3 复盘记录

复盘以发布记录为主对象，读取内容快照、发布时间和指标快照，形成：

- 目标与实际结果；
- 表现较好的内容元素；
- 未达到预期的原因假设；
- 下一次可执行动作；
- 复盘状态：草稿或已确认。

系统可以根据确定性指标计算变化和达成率，但不得把相关性自动写成因果结论。若后续增加 AI 复盘，AI 只能生成可编辑草稿，用户确认后才成为正式复盘。

复盘确认后，行动项可回到“今天”形成待办，但不能静默修改账号规则、写作策略或历史正文。

## 10. 数据模型

### 10.1 新增或调整的表

| 表 | 作用 | 关键约束 |
| --- | --- | --- |
| `user_workspace_preferences` | 保存用户最后使用空间 | 每用户一条；目标空间删除时置空 |
| `workspaces` | 空间主体与删除状态 | 增加 `status`、`updated_at` |
| `workspace_assets` | 空间素材唯一元数据 | `workspace_id + sha256` 唯一 |
| `project_asset_links` | 项目与素材引用 | 空间、项目、素材必须一致 |
| `storage_deletion_jobs` | 可靠删除私有文件 | 幂等状态机，不吞失败 |
| `channel_accounts` | 发布账号与能力状态 | 平台账号在空间内唯一 |
| `publication_records` | 排期和发布事实 | 引用不可变内容快照 |
| `publication_events` | 发布状态审计 | 只追加，不更新历史 |
| `publication_metric_snapshots` | 已发布数据时间快照 | 保留来源与采集时间 |
| `publication_retrospectives` | 复盘结论与行动 | 每条发布记录最多一个正式复盘 |

所有业务表必须带 `workspace_id`，所有跨表外键或服务校验必须证明对象属于同一空间。禁止仅凭全局 ID 查询后再相信客户端提交的 `workspace_id`。

### 10.2 现有数据归位

- `content_projects` 继续作为项目正式存储，不回迁到 `workspace_snapshots`。
- `workspace_snapshots` 只允许保留低频界面偏好；不得重新写入项目、素材、发布记录、情报或来源集合。
- `project_references` 中的文件元数据迁入 `workspace_assets`，原项目关系迁入 `project_asset_links`。相同空间内相同 SHA-256 只生成一份素材。
- 网络图片和 AI 图片全部验证实际文件、大小和哈希后迁入；无法验证的记录阻止迁移完成并输出清单，不静默丢弃。
- 旧的小红书/微博排版对象不再参与状态推进；有价值的正文和图片关系保留，确认没有独立业务用途后移除旧字段，不长期双写。

## 12. 前端信息架构

### 12.1 全局空间选择

顶部栏显示当前工作空间名称和切换入口。切换前等待当前页面显式保存请求完成；切换后清空项目选择、查询缓存和临时预览 URL，再按新空间重新加载。空间不存在或权限失效时回到空间选择页，不自动进入另一个空间。

“设置 → 工作空间”改为真实管理页，展示空间列表、创建、重命名、删除影响预览和确认流程。

### 12.2 素材库

一级导航“素材库”改为真实页面，包含类型、来源、版权状态、所属项目和时间筛选；支持上传、预览、编辑元数据、查看引用项目和删除。项目内素材选择器直接复用该数据源和预览组件。

### 12.3 创作

创作工作台根据平台能力生成步骤，不渲染不存在的页面：

- 公众号/知乎显示正文、配图、排版、审核；
- 小红书显示正文、图文卡片、审核；
- 微博显示正文、审核。

配图页显示可见的任务策略信息和统一大图预览。所有平台保存时执行图片数量上限校验。

### 12.4 发布

“发布”包含三个页签：

- **内容日历**：真实排期记录，不使用固定日期和示例卡片；
- **待发布**：按账号和平台完成预检、导出、人工确认或官方发布；
- **已发布**：查看平台链接、发布方式、状态和最新指标。

“设置 → 发布账号”管理账号。现有“账号授权”占位页替换为真实账号列表；手工账号使用“已配置人工发布”，不能标记“已授权”。

### 12.5 复盘

“复盘”只展示已经存在 `PUBLISHED` 发布记录的内容。列表按发布记录而不是项目完成状态生成，显示目标账号、发布时间、最新指标、数据来源和复盘状态。无指标时提供回填入口，无发布记录时显示真实空状态。

## 13. 错误处理与安全

### 13.1 稳定错误码

至少定义以下业务错误：

- `WORKSPACE_REQUIRED`
- `WORKSPACE_FORBIDDEN`
- `WORKSPACE_DELETING`
- `ASSET_IN_USE`
- `ASSET_FILE_INVALID`
- `CHANNEL_CAPABILITY_UNAVAILABLE`
- `ACCOUNT_CONNECTION_EXPIRED`
- `INVALID_STATE_TRANSITION`
- `PUBLICATION_RECEIPT_REQUIRED`
- `METRIC_VALUE_INVALID`

页面展示面向用户的可行动说明；服务端日志保存内部错误和关联 ID，不把堆栈、数据库错误、密钥或第三方原始敏感响应直接返回浏览器。

### 13.2 安全要求

- 每个业务请求均校验 JWT、工作空间成员关系和角色权限。
- 上传限制文件大小、允许类型和实际内容；文件名不参与物理路径拼接。
- 私有文件下载使用授权校验，禁止目录穿越和永久公开地址。
- 官方平台令牌使用现有凭据库加密，日志自动脱敏。
- 删除空间、删除账号、确认发布和手工指标回填写入审计记录。
- 所有写接口使用结构化校验；指标拒绝负数、非有限数和非法时间。
- 自动发布使用幂等键，网络超时后先查询平台结果，不能盲目重复发布。

## 14. 迁移方案

1. 迁移前生成 PostgreSQL 备份并记录 SHA-256；统计空间、项目、项目文件、图片绑定和现有发布相关数据。
2. 增加新表、索引、约束和工作空间状态字段，不改变现有读取。
3. 按空间和 SHA-256 回填 `workspace_assets` 与 `project_asset_links`，验证记录数、文件大小、哈希和引用关系。
4. 为每个现有用户写入合法的最后使用空间；只有一个空间的用户保持原空间，多空间用户不擅自切换，首次进入显示选择页。
5. 前端 API 客户端统一发送 `X-Workspace-Id`，服务端所有业务路由切换到工作空间上下文中间件；删除隐式首空间查询。
6. 切换项目素材、配图和发布包读取到空间素材与项目引用，不建立双写。
7. 迁移渠道状态：公众号、知乎保持完整流程；小红书移除排版前置；微博移除配图和排版前置并保留已有附件。
8. 验证新旧数据数量和关键哈希一致后，删除已替代的旧文件所有权字段、旧写入口、硬编码演示数据和无效状态分支。
9. 运行完整自动化和真实浏览器验收；失败时使用迁移前备份整体回滚，不做单条数据猜测性修复。

迁移脚本必须幂等或明确拒绝重复执行。任何校验不一致都应中止发布，不允许带着部分迁移数据继续运行。

## 15. 测试与验收标准

### 15.1 自动化

- 单元测试覆盖工作空间上下文、角色权限、渠道状态机、图片上限、素材引用和发布状态机。
- API 契约覆盖跨空间 ID 访问、缺少请求头、删除影响预览、引用中素材删除、人工发布回执和指标校验。
- 迁移测试覆盖现有 8 个项目、33 份素材和 29 个配图绑定的数量与哈希不变。
- E2E 覆盖注册登录、创建第二空间、切换后数据隔离、刷新恢复、删除空间、素材上传/复用/预览、四平台步骤、发布和复盘。
- 桌面与 390px 视口无横向溢出；浏览器控制台无未处理异常，网络面板无静默失败请求。

### 15.2 阶段 A 验收

1. 同一用户创建两个空间，在 A 创建项目和素材后切到 B，B 看不到 A 的任何业务数据。
2. 刷新和重新登录后恢复最后使用空间；权限失效时不回退到另一个空间。
3. 一份素材可被两个项目引用；解除一个引用不影响另一个项目和文件预览。
4. 被项目或发布快照使用的素材不能被直接删除。
5. 删除空间前准确显示影响数量，确认后文件与数据库记录完成一致删除。

### 15.3 阶段 B 验收

1. 公众号、知乎只走“正文 → 配图 → 排版 → 审核”，最多 12 张图片。
2. 小红书只走“正文 → 图文卡片 → 审核”，最多 9 张卡片，不出现排版入口。
3. 微博只走“正文 → 审核”，可选最多 9 张附件，不出现配图和排版入口。
4. 搜图词与正文段落语义贴切且不同配图项不重复；用户主动触发搜索。
5. 网图、AI 生图和素材库图片在采用前后均能打开大图预览。
6. 配图页显示真实任务 Scope、提供方和模型；失败时显示真实错误。

### 15.4 阶段 C 验收

1. 创建一个人工发布账号，完成内容排期、发布包导出、平台实际发布和链接回填。
2. 未填写链接或平台内容 ID 时不能确认人工发布成功。
3. 已发布列表展示真实账号、平台、时间、链接和发布方式，不显示演示数据。
4. 为同一发布记录回填至少两次指标，页面保留历史并计算变化。
5. 基于该发布记录填写并确认一条复盘，包含结果、原因假设和下一步行动。
6. 若测试官方连接器，必须使用真实授权账号和真实平台回执；否则该能力保持不可用并明确说明。

## 16. 完成定义

以下条件全部满足后，才能宣称本次产品闭环完成：

- 三个阶段的自动化和真实验收均通过；
- 工作空间不再由服务端隐式选择；
- 素材文件只有一个业务所有者且不存在断链；
- 四平台流程、图片上限和预览符合本规格；
- 发布账号、发布记录、指标和复盘均来自真实数据库；
- 未开放平台没有伪 OAuth、伪自动发布或伪数据同步；
- 发布中心、素材库和账号页不存在硬编码演示业务数据；
- 文档明确区分已实现、已自动化验证、已真实验收和未开放能力；
- 代码中不存在旧整份状态覆盖写入口、隐式空间回退、双写逻辑和临时迁移垃圾。
