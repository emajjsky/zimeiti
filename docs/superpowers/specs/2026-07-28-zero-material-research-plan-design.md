# 零资料研究计划设计

## 目标

让已确认规划的内容项目在没有上传任何资料时，也能通过项目 Agent 生成一份可确认、可追溯的研究计划；同时消除当前对话区与确认卡重复显示“已准备”的状态。

本切片只完成研究计划，不执行网络搜索、链接读取、Playwright 浏览或证据判定。

## 用户路径

1. 用户确认项目规划，进入“资料与研究”。
2. 用户可以添加并勾选自己的内容、参考链接和文件，也可以保持 0 条资料。
3. 新用户可点击唯一快捷动作“制定研究计划”；熟悉产品的用户可直接输入具体研究要求。
4. 系统只创建待确认运行，展示模型、提示词、资料数量和写入范围，不调用模型。
5. 用户点击“确认调用”后才进入队列并调用规划模型。
6. 完成后研究计划作为 `RESEARCH_PLAN` 产物展示待回答问题、建议来源、待核验主张和下一步动作。
7. 计划中的 `SEARCH_WEB`、`READ_LINK` 和 `ASK_USER` 仍是后续动作建议，不在本切片自动执行。

## 状态与数据

- 0 条资料是合法输入，不是错误状态。服务端仍调用 `researchSnapshot()`，得到空数组并冻结到运行快照。
- 快捷动作使用固定请求：“根据已确认的规划，制定本项目的研究计划。”，与手工输入走同一个 prepare 接口。
- prepare 前继续要求核心 Agent 凭据和 `AGENT_PLANNER` 模型策略；缺失配置时展示现有设置入口。
- prepare 必须继续取消同项目旧的 DRAFT 运行，确保当前阶段只有一个可确认任务。
- `CONFIRMATION` 类型消息保留在数据库用于审计，但不在普通对话线程重复渲染；当前待确认状态以唯一确认卡为准。
- 用户消息、运行、确认卡和最终研究计划均按工作空间与项目持久化。

## 界面

- 保留现有资料区与项目 Agent 双栏，不调整信息架构。
- 研究输入区在 0 条资料时显示“未选资料”，不显示红色阻断说明。
- 输入区只增加一个紧凑快捷按钮“制定研究计划”；不增加说明卡、功能列表或多个模板入口。
- 仍保留自由文本输入、发送按钮和 `Ctrl/Cmd + Enter`。
- 快捷动作和发送都只生成确认卡；确认卡继续是唯一计费入口。
- 使用现有按钮、边框、圆角和色彩系统，不引入新依赖或装饰动画。

## 错误处理

- 未配置核心 Agent 或规划模型时保持原错误和“去配置”入口。
- prepare、确认、取消、轮询失败时保持当前上下文和输入，不伪造成功状态。
- 空规划或找不到项目继续由现有服务端校验拒绝。
- 模型结构错误继续由现有严格 Schema 和一次修复机制处理。

## 验收

- 空资料项目可点击“制定研究计划”并看到资料数为 0 的确认卡。
- prepare 请求携带空 `inputIds` 和 `referenceIds`，不会因“至少选择一条资料”失败。
- 点击快捷动作后不出现与确认卡重复的“研究计划已准备”消息。
- 未点击“确认调用”时不创建 Worker Job，不调用百炼。
- 有资料项目和文案阶段 Agent 行为不回归。
- 1024px 与 390px 不横向溢出。
